## 1. Unix/Linux 계정 관리

### 문제 1. root 계정 원격 접속 제한 (U-01) (15점) ★★★

**문제:**
Linux 시스템에서 SSH를 통한 root 계정의 원격 로그인을 차단하려고 한다.
(1) 설정 파일의 절대 경로를 쓰시오. (5점)
(2) 설정해야 할 항목과 값을 쓰시오. (5점)
(3) 설정 적용을 위한 명령어를 쓰시오. (5점)

---

**✅ 모범 답안:**

```
(1) 설정 파일 경로:
/etc/ssh/sshd_config

(2) 설정 항목:
PermitRootLogin no

(3) 설정 적용 명령어:
systemctl restart sshd
또는
service sshd restart
```

---

**📊 채점 기준:**
- (1) 파일 경로 정확히 작성 (5점)
  - /etc/ssh/sshd_config 정확히 작성: 5점
  - 경로가 부정확하거나 상대 경로: 0점
- (2) 설정 항목 정확히 작성 (5점)
  - PermitRootLogin no 정확히 작성: 5점
  - 항목명만 작성하고 값 누락: 3점
- (3) 적용 명령어 작성 (5점)
  - systemctl restart sshd 또는 service sshd restart: 5점
  - 재시작 명령어 누락: 0점

---

**🔑 핵심 요약:**
- **U-01 root 원격 접속 제한**: SSH 통한 직접 root 로그인 차단
- **파일**: `/etc/ssh/sshd_config`
- **설정**: `PermitRootLogin no`
- **적용**: `systemctl restart sshd`
- **이유**: root 계정은 UID 0으로 모든 권한을 가지므로 직접 원격 접속을 허용하면 Brute Force 공격 위험

---

**💡 암기 팁:**
"SSH 설정은 /etc/ssh/sshd_config에서 PermitRootLogin no로 root 차단!"

## 2. Unix/Linux 파일 및 권한 관리

### 문제 2. 패스워드 파일 보호 (U-04, U-08) (20점) ★★★

**문제:**
Linux 시스템에서 패스워드 관련 파일의 보안 설정을 점검하려고 한다.

(1) /etc/shadow 파일의 적절한 권한(8진수)과 소유자를 쓰시오. (5점)
(2) /etc/shadow 파일의 권한을 (1)과 같이 설정하는 명령어를 쓰시오. (5점)
(3) /etc/passwd 파일의 적절한 권한(8진수)을 쓰시오. (5점)
(4) /etc/shadow 파일의 권한이 644인 경우 발생할 수 있는 보안 위협을 설명하시오. (5점)

---

**✅ 모범 답안:**

```
(1) /etc/shadow 파일 권한 및 소유자:
권한: 400 (r--------)
소유자: root

(2) 권한 설정 명령어:
chmod 400 /etc/shadow
chown root /etc/shadow

(3) /etc/passwd 파일 권한:
644 (rw-r--r--)

(4) 보안 위협:
/etc/shadow 파일에는 암호화된 패스워드 해시값이 저장되어 있음.
권한이 644인 경우 일반 사용자가 읽을 수 있어,
공격자가 해시값을 획득하여 Rainbow Table 공격이나
사전 공격(Dictionary Attack)을 통해 패스워드를 크래킹할 수 있음.
```

---

**📊 채점 기준:**
- (1) 권한 및 소유자 (5점)
  - 권한 400과 소유자 root 모두 정확: 5점
  - 권한만 정확: 3점
- (2) 명령어 (5점)
  - chmod와 chown 모두 작성: 5점
  - chmod만 작성: 3점
- (3) /etc/passwd 권한 (5점)
  - 644 정확히 작성: 5점
- (4) 보안 위협 설명 (5점)
  - Rainbow Table/사전 공격 언급: 5점
  - 패스워드 노출 위험만 언급: 3점

---

**🔑 핵심 요약:**
- **U-04/U-08 패스워드 파일 보호**
- **/etc/shadow**: 400 (root만 읽기), 암호화된 패스워드 저장
- **/etc/passwd**: 644 (모두 읽기 가능), 계정 정보만 저장
- **/etc/group**: 644
- **/etc/gshadow**: 400
- **위협**: 644 권한 시 Rainbow Table 공격으로 패스워드 크래킹 가능

---

**💡 암기 팁:**
"shadow는 400(사방 차단), passwd는 644(읽기는 OK)"

### 문제 3. 소유자 없는 파일 점검 (U-06) (12점) ★★

**문제:**
Linux 시스템에서 소유자가 존재하지 않는 파일을 점검하려고 한다.

(1) 시스템 전체에서 소유자가 없는 파일을 찾는 명령어를 쓰시오. (6점)
(2) 소유자 없는 파일이 발생하는 원인과 보안 위협을 설명하시오. (6점)

---

**✅ 모범 답안:**

```
(1) 명령어:
find / -nouser -print

또는

find / -nouser -o -nogroup -print

(2) 발생 원인 및 보안 위협:

발생 원인:
- 계정이 삭제된 후에도 해당 계정이 소유했던 파일이 남아있는 경우

보안 위협:
- 공격자가 동일한 UID로 새 계정을 생성하면
  해당 파일들의 소유권을 자동으로 획득하게 됨
- 중요 파일에 대한 무단 접근 및 수정 가능
```

---

**📊 채점 기준:**
- (1) 명령어 (6점)
  - find / -nouser 포함하여 정확히 작성: 6점
  - 경로나 옵션 일부 누락: 3점
- (2) 원인 및 위협 (6점)
  - 계정 삭제 원인과 UID 재사용 위협 모두 설명: 6점
  - 원인만 설명: 3점
  - 위협만 설명: 3점

---

**🔑 핵심 요약:**
- **U-06 소유자 없는 파일**
- **명령어**: `find / -nouser -print`
- **원인**: 계정 삭제 후 파일 잔존 (UID만 표시)
- **위협**: 공격자가 동일 UID로 계정 생성 시 파일 접근 가능
- **대책**: 정기 점검(월 1회), 발견 시 삭제 또는 소유자 재지정

## 3. Unix/Linux 시스템 보안 설정

### 문제 4. 패스워드 정책 설정 (U-02) (18점) ★★★

**문제:**
Linux 시스템에서 다음 조건에 맞게 패스워드 정책을 설정하려고 한다.

**조건:**
- 최대 사용기간: 90일
- 최소 사용기간: 1일
- 최소 길이: 8자
- 경고 일수: 7일

(1) 설정 파일의 절대 경로를 쓰시오. (4점)
(2) 각 조건에 해당하는 설정 항목과 값을 쓰시오. (8점)
(3) 패스워드 복잡성(영문, 숫자, 특수문자 포함)을 강제하는 PAM 설정 파일과 설정 라인을 쓰시오. (6점)

---

**✅ 모범 답안:**

```
(1) 설정 파일:
/etc/login.defs

(2) 설정 항목:
PASS_MAX_DAYS 90
PASS_MIN_DAYS 1
PASS_MIN_LEN 8
PASS_WARN_AGE 7

(3) PAM 복잡성 설정:
파일: /etc/pam.d/system-auth 또는 /etc/pam.d/common-password

설정:
password requisite pam_pwquality.so retry=3 minlen=8 dcredit=-1 ucredit=-1 lcredit=-1 ocredit=-1

설명:
- dcredit=-1: 숫자 최소 1개
- ucredit=-1: 대문자 최소 1개
- lcredit=-1: 소문자 최소 1개
- ocredit=-1: 특수문자 최소 1개
```

---

**📊 채점 기준:**
- (1) 파일 경로 (4점)
  - /etc/login.defs 정확히 작성: 4점
- (2) 설정 항목 (8점)
  - 4개 항목 모두 정확: 8점
  - 3개 정확: 6점
  - 2개 정확: 4점
- (3) PAM 설정 (6점)
  - 파일 경로와 설정 라인 모두 정확: 6점
  - 파일 경로만 정확: 2점
  - 설정 라인만 정확: 4점

---

**🔑 핵심 요약:**
- **U-02 패스워드 복잡성 설정**
- **파일**: `/etc/login.defs` (유효기간, 길이)
- **PAM**: `/etc/pam.d/system-auth` (복잡성)
- **필수 설정**: PASS_MAX_DAYS 90, PASS_MIN_LEN 8
- **복잡성**: dcredit(숫자), ucredit(대문자), lcredit(소문자), ocredit(특수문자)

---

**💡 암기 팁:**
"MAX 90일, MIN 1일, LEN 8자, WARN 7일! PAM으로 복잡성 강제!"

### 문제 5. 계정 잠금 임계값 설정 (U-03) (15점) ★★

**문제:**
Linux 시스템에서 로그인 5회 실패 시 계정을 잠그고, 10분(600초) 후 자동 해제되도록 설정하려고 한다.

(1) 설정 파일의 경로를 쓰시오. (5점)
(2) PAM 설정 라인을 쓰시오. (7점)
(3) 특정 사용자(user01)의 잠금을 수동으로 해제하는 명령어를 쓰시오. (3점)

---

**✅ 모범 답안:**

```
(1) 설정 파일:
/etc/pam.d/system-auth
또는
/etc/pam.d/common-auth

(2) PAM 설정:
auth required pam_tally2.so deny=5 unlock_time=600

(3) 수동 해제 명령어:
pam_tally2 --user=user01 --reset
```

---

**📊 채점 기준:**
- (1) 파일 경로 (5점)
  - /etc/pam.d/system-auth 또는 common-auth: 5점
- (2) PAM 설정 (7점)
  - deny와 unlock_time 모두 정확: 7점
  - deny만 정확: 4점
- (3) 수동 해제 명령어 (3점)
  - pam_tally2 --reset 포함: 3점

---

**🔑 핵심 요약:**
- **U-03 계정 잠금 임계값**
- **파일**: `/etc/pam.d/system-auth`
- **설정**: `auth required pam_tally2.so deny=5 unlock_time=600`
- **deny=5**: 5회 실패 시 잠금
- **unlock_time=600**: 600초(10분) 후 자동 해제
- **수동 해제**: `pam_tally2 --user=사용자명 --reset`
- **목적**: Brute Force 공격 방어

---

**💡 암기 팁:**
"pam_tally2로 deny 5회, unlock 600초!"

### 문제 7. PATH 환경변수 보안 설정 (U-43) (12점) ★★

**문제:**
다음은 root 계정의 PATH 환경변수이다.

```bash
$ echo $PATH
.:/usr/local/bin:/usr/bin:/bin
```

(1) 위 설정에서 보안상 위험한 부분을 지적하시오. (4점)
(2) 해당 설정이 위험한 이유를 설명하시오. (5점)
(3) 안전한 PATH 설정 예시를 쓰시오. (3점)

---

**✅ 모범 답안:**

```
(1) 위험한 부분:
PATH 맨 앞에 "." (현재 디렉토리) 포함

(2) 위험한 이유:
"."은 현재 디렉토리를 의미하며, PATH 맨 앞에 위치할 경우
공격자가 악의적인 명령어를 현재 디렉토리에 생성하면
정상 명령어보다 먼저 실행됨 (트로이목마 공격).

예시:
- 공격자가 /tmp/ls 악성 스크립트 생성
- root가 /tmp에서 ls 명령어 실행
- /bin/ls 대신 /tmp/ls가 먼저 실행되어 시스템 침해

(3) 안전한 PATH 설정:
export PATH=/usr/local/bin:/usr/bin:/bin:/usr/sbin:/sbin

("." 제거 및 절대 경로만 포함)
```

---

**📊 채점 기준:**
- (1) 위험 부분 지적 (4점)
  - "." 포함을 명확히 지적: 4점
- (2) 위험 이유 (5점)
  - 트로이목마 공격 가능성 설명: 5점
  - 예시 포함: 추가 1점(bonus)
- (3) 안전한 설정 (3점)
  - "." 제거된 PATH: 3점

---

**🔑 핵심 요약:**
- **U-43 PATH 보안 설정**
- **위험**: PATH에 "." (현재 디렉토리) 포함
- **공격**: 트로이목마 - 악성 명령어가 정상 명령어보다 먼저 실행
- **대책**: "." 제거, 절대 경로만 포함
- **설정**: `export PATH=/usr/local/bin:/usr/bin:/bin:/usr/sbin:/sbin`

---

**💡 암기 팁:**
"PATH에 점(.) 찍으면 트로이목마! 절대 경로만!"

## 4. Windows 계정 및 정책 관리

### 문제 8. Guest 계정 비활성화 (W-06) (10점) ★★★

**문제:**
Windows 시스템에서 Guest 계정을 비활성화하려고 한다.

(1) Guest 계정 상태를 확인하는 명령어를 쓰시오. (3점)
(2) Guest 계정을 비활성화하는 명령어를 쓰시오. (4점)
(3) Guest 계정을 비활성화해야 하는 이유를 설명하시오. (3점)

---

**✅ 모범 답안:**

```
(1) 상태 확인 명령어:
net user Guest

(2) 비활성화 명령어:
net user Guest /active:no

(3) 비활성화 이유:
Guest 계정은 패스워드 없이 로그인 가능한 익명 계정으로,
활성화되어 있으면 인증 없이 시스템에 접근할 수 있어
무단 접근 및 정보 유출의 위험이 있음.
```

---

**📊 채점 기준:**
- (1) 확인 명령어 (3점)
  - net user Guest: 3점
- (2) 비활성화 명령어 (4점)
  - net user Guest /active:no: 4점
- (3) 이유 설명 (3점)

### 문제 14. Linux 시스템 종합 보안 점검 (20점) ★★★

**문제:**
다음은 Linux 시스템 점검 결과이다. 각 항목의 취약점과 조치 방법을 쓰시오.

```bash
[점검 1]
$ ls -l /etc/shadow
-rw-r--r-- 1 root root 1234 Nov 5 14:30 /etc/shadow

[점검 2]
$ echo $PATH
.:/usr/local/bin:/usr/bin:/bin

[점검 3]
$ grep PASS_MAX_DAYS /etc/login.defs
PASS_MAX_DAYS 99999

[점검 4]
$ grep PermitRootLogin /etc/ssh/sshd_config
PermitRootLogin yes
```

---

**✅ 모범 답안:**

```
[점검 1] /etc/shadow 권한 취약점 (U-08)

현재 상태: 644 (rw-r--r--)
문제점: 일반 사용자가 읽기 가능, 암호화된 패스워드 해시 노출
위협: Rainbow Table 공격으로 패스워드 크래킹 가능

조치 방법:
chmod 400 /etc/shadow
(root만 읽기 가능하도록 설정)

[점검 2] PATH 설정 취약점 (U-43)

현재 상태: PATH 맨 앞에 "." (현재 디렉토리) 포함
문제점: 트로이목마 공격 위험
위협: 악성 명령어가 정상 명령어보다 먼저 실행될 수 있음

조치 방법:
~/.bash_profile 또는 /etc/profile 수정
export PATH=/usr/local/bin:/usr/bin:/bin:/usr/sbin:/sbin
(맨 앞의 "." 제거, 절대 경로만 포함)

[점검 3] 패스워드 유효기간 취약점 (U-02)

현재 상태: PASS_MAX_DAYS 99999 (약 273년)
문제점: 패스워드 변경 주기가 없음
위협: 패스워드 유출 시 장기간 사용되어 위험 증가

조치 방법:
/etc/login.defs 수정
PASS_MAX_DAYS 90
(최대 사용기간을 90일로 제한)

[점검 4] root 원격 접속 허용 취약점 (U-01)

현재 상태: PermitRootLogin yes
문제점: SSH를 통한 root 직접 로그인 허용
위협: Brute Force 공격으로 root 계정 탈취 가능

조치 방법:
/etc/ssh/sshd_config 수정
PermitRootLogin no
systemctl restart sshd
(일반 계정으로 로그인 후 su 또는 sudo 사용)
```

---

**📊 채점 기준:**
- 점검 1 (5점): 권한 문제와 chmod 400 조치
- 점검 2 (5점): PATH "." 문제와 제거 조치
- 점검 3 (5점): 유효기간 문제와 90일 설정
- 점검 4 (5점): root 접속 문제와 no 설정

---

**🔑 핵심 요약:**
- **종합 점검**: 권한, PATH, 패스워드 정책, SSH 설정
- **U-08**: shadow 400
- **U-43**: PATH에서 "." 제거
- **U-02**: PASS_MAX_DAYS 90
- **U-01**: PermitRootLogin no
