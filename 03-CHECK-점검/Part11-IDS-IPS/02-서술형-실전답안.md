## 1. IDS vs IPS

### 문제 1-1: IDS와 IPS의 차이점을 설명하고, 각각의 장단점을 비교하시오 (15점) ★★★

#### ✅ 모범 답안:

**[IDS vs IPS 기본 정의]**

**IDS (Intrusion Detection System) - 침입 탐지 시스템 ★★★**
```
역할: 탐지 + 알림 (Detection + Alert)
동작: 패시브(Passive) 모드
배치: 네트워크 미러링 포트 (SPAN, TAP)

     Internet
        |
    [방화벽]
        |
     [스위치]----[미러링]----[IDS] (모니터링만)
        |
    [서버들]
```

**IPS (Intrusion Prevention System) - 침입 방지 시스템 ★★★**
```
역할: 탐지 + 차단 (Detection + Prevention)
동작: 인라인(Inline) 모드
배치: 트래픽 경로 중간

     Internet
        |
    [방화벽]
        |
      [IPS]----← 모든 트래픽 통과 (차단 가능)
        |
     [스위치]
        |
    [서버들]
```

**[상세 비교표]**

| 구분 | IDS | IPS |
|------|-----|-----|
| **역할** | 탐지 + 경보 | 탐지 + 차단 |
| **동작 모드** | Passive (수동) | Inline (능동) |
| **트래픽 경로** | 미러링 포트 | 실제 경로 중간 |
| **공격 대응** | 알림만 (사후 대응) | 실시간 차단 (사전 차단) |
| **네트워크 영향** | 없음 (장애 시 트래픽 영향 無) | 있음 (장애 시 네트워크 단절) |
| **지연(Latency)** | 없음 | 있음 (검사 시간) |
| **오탐 영향** | 경보만 | 정상 트래픽 차단 (심각) |
| **보안성** | 낮음 (탐지만) | 높음 (차단) |
| **가용성** | 높음 | 낮음 (Single Point of Failure) |

**[IDS 특징]**

**장점:**
1. **네트워크 영향 없음**
   - 미러링 포트 사용
   - IDS 장애 시에도 네트워크 정상
   - 트래픽 지연 없음

2. **유연한 분석**
   - 이미 지나간 트래픽 분석 가능
   - 복잡한 패턴 매칭 가능
   - 시간 여유로 정밀 분석

3. **오탐 영향 적음**
   - False Positive 발생해도 경보만
   - 정상 트래픽 차단 위험 없음

4. **사후 분석 용이**
   - 로그 보관
   - 포렌식 자료 수집

**단점:**
1. **공격 차단 불가 ★★★**
   - 탐지 후 관리자 수동 대응 필요
   - 실시간 방어 불가
   - 공격이 이미 시스템에 도달

2. **대응 시간 지연**
   - 알림 → 확인 → 조치 → 차단
   - 분/시간 단위 지연

3. **미러링 트래픽 손실 가능**
   - 대용량 트래픽 시 패킷 드롭
   - 일부 공격 미탐지 가능

**[IPS 특징]**

**장점:**
1. **실시간 차단 ★★★**
   - 공격 즉시 차단
   - 자동 대응 (관리자 개입 불필요)
   - Zero-Day 공격 방어 가능

2. **시스템 보호**
   - 악성 트래픽이 시스템 도달 전 차단
   - 네트워크 계층 방어

3. **방화벽 보완**
   - 방화벽 우회 공격 탐지
   - 애플리케이션 계층 공격 차단

**단점:**
1. **네트워크 단일 장애점 (SPOF) ★★★**
   - IPS 장애 시 전체 네트워크 단절
   - 이중화(HA) 필수
   - 비용 증가

2. **트래픽 지연**
   - 모든 패킷 검사
   - Latency 발생 (수 ms ~ 수십 ms)
   - 실시간 서비스 영향

3. **오탐 시 심각한 영향 ★★★**
   - False Positive → 정상 트래픽 차단
   - 서비스 장애 발생
   - 신중한 정책 설정 필요

4. **복잡한 패턴 검사 제한**
   - 빠른 처리 필요
   - 간단한 패턴만 검사
   - 정교한 분석 어려움

**[실무 사용 시나리오]**

**IDS를 사용하는 경우:**
```
1. 네트워크 모니터링이 주 목적
2. 가용성이 최우선 (다운타임 불가)
3. 오탐률이 높아 수동 확인 필요
4. 사후 분석 및 포렌식 중심
5. 예산 제약

예시:
- 대학교 네트워크 (교육 목적)
- 연구 네트워크 (분석 목적)
- 백업 모니터링
```

**IPS를 사용하는 경우:**
```
1. 실시간 차단이 필수
2. 중요 자산 보호
3. 규정 준수 (컴플라이언스)
4. 오탐률이 낮아 자동 차단 가능
5. 충분한 예산과 인력

예시:
- 금융권 (실시간 거래 보호)
- 의료 기관 (개인정보 보호)
- 정부 기관 (국가 중요 정보)
- 대기업 DMZ
```

**[하이브리드 구성] ★★**
```
     Internet
        |
    [방화벽]
        |
      [IPS]----← 알려진 공격 실시간 차단
        |
     [스위치]----[IDS]----← 정밀 분석, 새로운 패턴 탐지
        |
    [서버들]

- IPS: 확실한 공격 즉시 차단
- IDS: 의심스러운 패턴 정밀 분석
- 최적의 보안과 가용성
```

**[최신 트렌드]**

**NGIPS (Next-Generation IPS) ★★**
```
기능:
- 전통적 IPS 기능
+ Deep Packet Inspection (DPI)
+ 애플리케이션 인식
+ SSL/TLS 복호화
+ 사용자 식별
+ Advanced Malware Protection
+ Threat Intelligence 연동

제품: Palo Alto, Cisco Firepower, Fortinet
```

**[채점 기준]**
- IDS vs IPS 차이 (5점)
- 각각의 장단점 (8점, 각 4점)
- 배치 위치 설명 (2점)

## 2. 탐지 기법

### 문제 2-1: IDS/IPS의 3가지 탐지 기법(Signature, Anomaly, Behavior)을 설명하고, 각각의 장단점을 비교하시오 (15점) ★★★

#### ✅ 모범 답안:

**[3가지 탐지 기법]**

**1. Signature-based Detection (시그니처 기반) ★★★**

**원리:**
```
알려진 공격 패턴을 DB에 저장
→ 네트워크 트래픽과 비교
→ 매칭되면 탐지/차단

백신 프로그램과 동일한 방식
```

**시그니처 예시:**
```
alert tcp any any -> any 80 (
    content: "GET /../../etc/passwd";
    msg: "Directory Traversal Attempt";
    sid: 1000001;
)

- GET 요청에 /../etc/passwd 포함 시 탐지
```

**장점:**
1. **높은 정확도 (Low False Positive) ★★★**
   - 알려진 공격 확실히 탐지
   - 오탐률 낮음

2. **빠른 탐지 속도**
   - 단순 패턴 매칭
   - 실시간 처리 가능

3. **명확한 경보**
   - 구체적인 공격 유형 식별
   - 공격명, CVE 번호 제공

4. **쉬운 이해**
   - 관리자가 이해하기 쉬움
   - 규칙 작성 용이

**단점:**
1. **Zero-Day 공격 탐지 불가 ★★★**
   - 새로운 공격은 시그니처 없음
   - 업데이트 전까지 무방비

2. **우회 가능 ★★**
   - 패턴 조금 변경하면 우회
   - 예: `GET /etc/passwd` → `GET /etc//passwd`
   - 예: SQL Injection → 다양한 인코딩

3. **시그니처 관리 부담**
   - 지속적인 업데이트 필요
   - 수만 개 규칙 관리
   - 업데이트 지연 시 취약

4. **변종 공격 탐지 어려움**
   - 조금만 달라도 미탐지
   - Polymorphic 악성코드 탐지 불가

**사용 사례:**
```
- Snort (오픈소스 IDS)
- Suricata
- 대부분의 상용 IPS
```

---

**2. Anomaly-based Detection (이상 탐지) ★★★**

**원리:**
```
1. 정상 트래픽 패턴 학습 (Baseline 수립)
2. 현재 트래픽과 비교
3. 임계값 초과 시 이상 탐지

통계적 기법 사용
```

**Baseline 예시:**
```
정상 패턴:
- 평균 HTTP 요청: 100 req/sec
- 평균 트래픽: 10 Mbps
- 접속 국가: 한국 90%, 미국 5%, 일본 5%

이상 탐지:
- 갑자기 1000 req/sec → DDoS 의심
- 갑자기 100 Mbps → 트래픽 폭증
- 중국에서 접속 → 비정상 접근
```

**장점:**
1. **Zero-Day 공격 탐지 가능 ★★★**
   - 알려지지 않은 공격도 탐지
   - 새로운 공격 패턴 발견
   - 시그니처 업데이트 불필요

2. **변종 공격 탐지**
   - 공격 방식이 달라도 이상 행동은 동일
   - 내부자 위협 탐지

3. **포괄적 보안**
   - 전체 네트워크 행동 모니터링
   - 복합 공격 탐지

**단점:**
1. **높은 오탐률 (High False Positive) ★★★**
   - 정상 행동도 이상으로 오인
   - 예: 마케팅 이벤트로 트래픽 급증 → DDoS로 오인
   - 예: 야간 배치 작업 → 이상 행동으로 탐지

2. **Baseline 수립 기간 필요**
   - 수일~수주 학습 기간
   - 학습 기간 동안 공격 탐지 불가
   - 네트워크 변화 시 재학습 필요

3. **임계값 설정 어려움**
   - 너무 낮으면: 오탐 증가
   - 너무 높으면: 미탐 증가
   - 튜닝에 많은 시간 소요

4. **복잡한 분석**
   - 높은 연산 비용
   - 실시간 처리 어려움

**사용 기법:**
```
- Statistical Analysis (통계 분석)
- Machine Learning (머신러닝)
  - SVM, Neural Network, Random Forest
- Protocol Analysis
```

---

**3. Behavior-based Detection (행위 기반) ★★**

**원리:**
```
정상 행동 패턴 정의
→ 행동 모니터링
→ 비정상 행동 탐지

프로세스, 시스템 호출, 파일 접근 등 분석
```

**행동 패턴 예시:**
```
정상 웹 서버 행동:
- 80, 443 포트 LISTEN
- 정적 파일 읽기 (/var/www/)
- 로그 파일 쓰기 (/var/log/)

비정상 행동 탐지:
- 25번 포트 OPEN (SMTP, 스팸 발송 시도)
- /etc/passwd 읽기 시도 (권한 상승)
- 아웃바운드 연결 다수 생성 (C&C 통신)
- 암호화 라이브러리 로드 (랜섬웨어)
```

**장점:**
1. **정교한 공격 탐지**
   - APT 공격 탐지
   - 다단계 공격 추적
   - Lateral Movement 탐지

2. **컨텍스트 기반 탐지**
   - 단순 패킷이 아닌 행동 분석
   - 공격 의도 파악

3. **낮은 우회 가능성**
   - 공격자가 행동을 숨기기 어려움
   - 최종 목적은 동일 (권한 상승, 데이터 탈취)

**단점:**
1. **정상 행동 정의 어려움**
   - 모든 정상 행동 나열 불가
   - 애플리케이션마다 다름

2. **오탐 가능**
   - 관리자의 정상적인 특수 작업도 탐지
   - 예: 수동 설정 변경, 긴급 패치

3. **리소스 집약적**
   - 모든 행동 추적
   - 많은 CPU, 메모리 필요

**사용 사례:**
```
- HIDS (Host-based IDS)
- EDR (Endpoint Detection and Response)
- UEBA (User and Entity Behavior Analytics)
```

---

**[탐지 기법 비교표]**

| 구분 | Signature | Anomaly | Behavior |
|------|-----------|---------|----------|
| **탐지 대상** | 알려진 공격 | 통계적 이상 | 비정상 행동 |
| **Zero-Day** | ✗ 불가 | ✓ 가능 | ✓ 가능 |
| **오탐률** | 낮음 | 높음 | 중간 |
| **미탐률** | 높음 | 낮음 | 낮음 |
| **처리 속도** | 빠름 | 느림 | 느림 |
| **학습 기간** | 불필요 | 필요 | 필요 |
| **우회 난이도** | 쉬움 | 어려움 | 어려움 |
| **관리 복잡도** | 낮음 | 높음 | 높음 |

**[하이브리드 접근] ★★★**

```
최신 IPS는 3가지 기법 모두 사용:

1. Signature: 알려진 공격 빠르게 차단
2. Anomaly: Zero-Day 공격 탐지
3. Behavior: APT, 내부자 위협 탐지

예: Palo Alto Networks, Cisco Firepower
```

**[실무 적용]**

```
시그니처 기반 (1차 방어):
- 빠른 탐지/차단
- 알려진 공격 대부분 차단
- 오탐 최소화

이상 탐지 (2차 방어):
- 새로운 공격 패턴 발견
- 관리자에게 알림
- 수동 확인 후 시그니처 생성

행위 기반 (3차 방어):
- 호스트 레벨 모니터링
- 침해 후 행동 탐지
- 포렌식 증거 수집
```

**[채점 기준]**
- 3가지 탐지 기법 설명 (9점, 각 3점)
- 장단점 비교 (4점)
- 비교표 또는 사용 사례 (2점)

## 3. Snort 룰 작성

### 문제 3-1: Snort 룰의 구조를 설명하고, 주어진 공격을 탐지하는 룰을 작성하시오 (15점) ★★★

**공격 시나리오:**
1. 외부에서 내부 웹 서버(192.168.1.100)로 SQL Injection 시도 (URL에 `' OR 1=1--` 포함)
2. 내부 서버에서 외부 IRC 서버(6667 포트)로 접속 시도 (봇넷 C&C 통신 의심)

#### ✅ 모범 답안:

**[Snort 룰 기본 구조]**

```
[Rule Header]  |  [Rule Options]
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
action proto src_ip src_port direction dst_ip dst_port (options)
```

**[Rule Header 구성요소]**

**1. Action (동작) ★★★**
```
alert   - 경보 생성 및 패킷 로깅
log     - 패킷 로깅만
pass    - 패킷 무시 (화이트리스트)
drop    - 패킷 차단 (IPS 모드)
reject  - 패킷 차단 + RST 전송
```

**2. Protocol (프로토콜)**
```
tcp
udp
icmp
```

**[Snort 룰 작성 Best Practices] ★★**

1. **구체적인 msg 작성**
   - 공격 유형 명확히 기재
   - 예: "SQL Injection - Union Select"

2. **flow 옵션 사용**
   - 연결 상태 확인으로 오탐 감소
   - `flow:to_server,established`

3. **content 순서 최적화**
   - 빈번한 패턴을 앞에 배치
   - 빠른 미스매치로 성능 향상

4. **threshold 활용**
   - DDoS, 스캔 등 대량 공격 탐지
   - 단일 패킷이 아닌 패턴 탐지

5. **sid 규칙 준수**
   - 1-999999: Snort 예약
   - 1000000-: 사용자 정의

6. **정기적인 룰 업데이트**
   - 새로운 취약점 반영
   - 오탐 발생 시 튜닝

7. **테스트**
   - 프로덕션 적용 전 테스트
   - 정상 트래픽 차단 여부 확인

## 4. HIDS vs NIDS

### 문제 4-1: HIDS와 NIDS의 차이점을 설명하고, 각각의 장단점을 비교하시오 (12점) ★★★

#### ✅ 모범 답안:

**[HIDS vs NIDS 정의]**

**NIDS (Network-based IDS) - 네트워크 기반 IDS ★★★**
```
배치: 네트워크 구간 (스위치 미러링 포트)
감시: 네트워크 트래픽 (패킷)
범위: 전체 네트워크 세그먼트

     [인터넷]
        |
    [방화벽]
        |
     [스위치]----[미러링]----[NIDS]
     /  |  \
  [서버][서버][서버]

- 모든 서버의 네트워크 트래픽 감시
```

**HIDS (Host-based IDS) - 호스트 기반 IDS ★★★**
```
배치: 개별 호스트 (서버, PC)
감시: 시스템 내부 활동
범위: 해당 호스트만

  [웹서버]               [DB서버]
     |                      |
  [HIDS Agent]          [HIDS Agent]

- 각 서버마다 에이전트 설치
- 시스템 로그, 파일, 프로세스 감시
```

**[상세 비교]**

| 구분 | NIDS | HIDS |
|------|------|------|
| **배치 위치** | 네트워크 구간 | 각 호스트 |
| **감시 대상** | 네트워크 패킷 | 시스템 이벤트 |
| **탐지 범위** | 네트워크 전체 | 단일 호스트 |
| **암호화 트래픽** | 탐지 불가 | 탐지 가능 |
| **내부 활동** | 불가 | 가능 (파일, 프로세스) |
| **자원 사용** | 네트워크 대역폭 | 호스트 CPU/메모리 |
| **관리 복잡도** | 낮음 (중앙 집중) | 높음 (각 호스트) |
| **비용** | 낮음 | 높음 (호스트 수만큼) |

**[NIDS 상세 설명]**

**장점:**
1. **중앙 집중식 관리 ★★★**
   - 한 곳에서 전체 네트워크 감시
   - 관리 편의성
   - 적은 인력으로 운영 가능

2. **호스트 영향 없음**
   - 호스트에 에이전트 불필요
   - CPU/메모리 사용 없음
   - 시스템 성능 저하 없음

3. **저렴한 비용**
   - 소수의 NIDS로 다수 호스트 감시
   - 라이선스 비용 절감

4. **네트워크 공격 탐지**
   - 포트 스캔, DDoS
   - 네트워크 레벨 공격

5. **OS 독립적**
   - Windows, Linux 상관없이 감시
   - 네트워크 패킷만 분석

**단점:**
1. **암호화 트래픽 탐지 불가 ★★★**
   - HTTPS, SSH, VPN 내용 분석 불가
   - SSL/TLS 복호화 필요 (성능 저하)

2. **스위치 환경에서 제약**
   - 미러링 포트 필요
   - 모든 트래픽 복사 → 네트워크 부하

3. **대용량 트래픽 환경**
   - 10Gbps 이상 트래픽 처리 어려움
   - 패킷 드롭 발생 가능

4. **호스트 내부 활동 미탐지 ★★★**
   - 파일 변조, 로컬 권한 상승
   - 직접 콘솔 접근 공격
   - 내부자 위협

5. **패킷 조각화 공격**
   - IP Fragmentation 공격 탐지 어려움
   - 재조립 필요

**[HIDS 상세 설명]**

**장점:**
1. **호스트 내부 활동 감시 ★★★**
   ```
   감시 항목:
   - 파일 무결성 (Tripwire)
   - 로그 분석 (/var/log/)
   - 프로세스 모니터링
   - 레지스트리 변경 (Windows)
   - 시스템 콜
   - 사용자 활동
   ```

2. **암호화 트래픽 탐지 가능 ★★★**
   - 애플리케이션 레벨에서 복호화 후 분석
   - HTTPS 내용도 확인 가능

3. **정밀한 탐지**
   - 실제 피해 여부 확인
   - 공격 성공 vs 실패 구분
   - False Positive 감소

4. **공격 후 활동 탐지**
   - Backdoor 설치
   - Rootkit
   - 권한 상승
   - 데이터 유출

5. **네트워크 독립적**
   - 네트워크 위치 무관
   - VPN, 원격 사용자도 감시

**단점:**
1. **각 호스트마다 에이전트 설치 ★★★**
   - 관리 부담 증가
   - 수백~수천 대 관리 어려움
   - 에이전트 업데이트 필요

2. **호스트 자원 사용 ★★**
   - CPU: 5~10%
   - 메모리: 100~500MB
   - 디스크 I/O
   - 성능 저하 가능

3. **높은 비용**
   - 호스트 수만큼 라이선스
   - 대규모 환경에서 고비용

4. **단일 호스트만 감시**
   - 네트워크 전체 관점 부족
   - 분산 공격 탐지 어려움

5. **무력화 가능성 ★★**
   - 공격자가 호스트 장악 시 HIDS 중지
   - 로그 삭제 가능

**[감시 범위 비교]**

**NIDS 탐지 가능:**
```
네트워크 공격:
- 포트 스캔
- SYN Flooding
- DDoS
- ARP Spoofing
- Man-in-the-Middle
- DNS Spoofing
- SQL Injection (평문 HTTP)
- 웜 전파
```

**HIDS 탐지 가능:**
```
호스트 공격:
- 파일 변조 (/etc/passwd)
- Rootkit 설치
- 권한 상승 (setuid 파일 생성)
- 로컬 Buffer Overflow
- 악성 프로세스 실행
- 레지스트리 변경
- 계정 추가/삭제
- 로그 삭제
- 내부자 파일 접근
```

**[실무 권장 구성] ★★★**

**통합 운영 (Best Practice):**
```
     [인터넷]
        |
    [방화벽]
        |
      [IPS]--------← 1차 방어: 알려진 공격 차단
        |
     [스위치]----[NIDS]----← 2차 방어: 네트워크 이상 탐지
     /  |  \
  [웹서버][앱서버][DB서버]
    HIDS   HIDS    HIDS  ← 3차 방어: 호스트 내부 감시

계층별 방어:
- 네트워크: NIDS (폭넓은 감시)
- 호스트: HIDS (정밀 감시)
- 상호 보완: NIDS 우회 공격 → HIDS 탐지
```

**역할 분담:**
```
NIDS:
- 네트워크 공격 1차 탐지
- 전체 트래픽 패턴 분석
- 분산 공격 상관 분석

HIDS:
- 중요 서버 정밀 감시
- 공격 성공 여부 확인
- 사후 포렌식 증거 수집
```

**[최신 솔루션] ★★**

**SIEM (Security Information and Event Management)**
```
NIDS + HIDS 통합:
- 네트워크 이벤트 수집
- 호스트 로그 수집
- 상관 분석 (Correlation)
- 통합 대시보드

제품: Splunk, QRadar, ArcSight
```

**EDR (Endpoint Detection and Response)**
```
차세대 HIDS:
- 행위 기반 탐지
- 실시간 대응
- Threat Intelligence 연동
- 자동 격리

제품: CrowdStrike, Carbon Black, SentinelOne
```

**[채점 기준]**
- NIDS vs HIDS 차이 (4점)
- 각각의 장단점 (6점)
- 감시 범위 또는 통합 운영 (2점)

## 5. False Positive/Negative

### 문제 5-1: False Positive와 False Negative의 개념을 설명하고, 각각이 미치는 영향과 해결 방법을 제시하시오 (12점) ★★★

#### ✅ 모범 답안:

**[오탐/미탐 정의]**

```
실제 상황
         |  정상   |  공격
━━━━━━━━━━━━━━━━━━━━━━━━━
IDS/IPS  |         |
판단     |         |
━━━━━━━━━━━━━━━━━━━━━━━━━
정상     |   TN    |   FN
         |(정탐)   |(미탐) ★★
━━━━━━━━━━━━━━━━━━━━━━━━━
공격     |   FP    |   TP
         |(오탐)★★ |(정탐)
```

**TN (True Negative) - 올바른 정상 판단**
- 정상 트래픽을 정상으로 판단 ✓

**TP (True Positive) - 올바른 공격 판단**
- 공격을 공격으로 판단 ✓

**FP (False Positive) - 오탐 ★★★**
- 정상 트래픽을 공격으로 잘못 판단 ✗

**FN (False Negative) - 미탐 ★★★**
- 실제 공격을 정상으로 잘못 판단 ✗

---

**[False Positive (오탐) 상세]**

**정의:**
```
정상적인 활동을 공격으로 잘못 탐지
"늑대가 나타났다!" (실제로는 늑대 없음)
```

**발생 원인:**

1. **너무 엄격한 탐지 규칙 ★★★**
   ```
   예시:
   - 모든 SQL 키워드 차단
   - 정상 쿼리도 차단: "SELECT username FROM users"
   ```

2. **정상 행동 변화**
   ```
   - 마케팅 이벤트로 트래픽 급증
   - 새로운 서비스 출시
   - 정기 배치 작업
   ```

3. **불완전한 Baseline**
   ```
   - 학습 기간 부족
   - 정상 행동 패턴 미포함
   ```

4. **애플리케이션 특성 미고려**
   ```
   - 정상적으로 많은 요청 발생하는 API
   - 대용량 파일 전송
   ```

**영향:**

1. **경보 피로(Alert Fatigue) ★★★**
   ```
   하루 수천 건의 오탐 경보
   → 관리자 무시
   → 실제 공격도 놓침

   "양치기 소년 효과"
   ```

2. **업무 과부하**
   ```
   - 오탐 확인에 시간 낭비
   - 실제 공격 분석 시간 부족
   - 인력 자원 고갈
   ```

3. **IPS 모드 시 서비스 장애 ★★★**
   ```
   정상 트래픽 차단
   → 서비스 중단
   → 고객 불만
   → 매출 손실
   ```

4. **IDS/IPS 신뢰도 저하**
   ```
   - 관리자가 규칙 비활성화
   - 탐지 시스템 무용지물
   ```

**해결 방법:**

1. **규칙 튜닝 ★★★**
   ```bash
   # 오탐 발생 규칙 식별
   snort -A console -q -c snort.conf -r pcap_file.pcap

   # 규칙 수정
   # Before: content:"select";
   # After:  content:"select"; nocase; http_uri; \
   #         content:"union"; distance:0; within:100;

   # 더 구체적인 조건 추가
   ```

2. **Whitelist 활용 ★★★**
   ```
   # Snort suppress (특정 IP 제외)
   suppress gen_id 1, sig_id 1000001, track by_src, ip 192.168.1.100

   # 신뢰할 수 있는 IP/도메인 화이트리스트
   pass tcp 192.168.1.0/24 any -> any any
   ```

3. **Threshold 조정**
   ```
   # 단일 이벤트가 아닌 반복 패턴 탐지
   threshold: type threshold, track by_src, count 10, seconds 60

   # 10분에 1회만 경보
   threshold: type limit, track by_src, count 1, seconds 600
   ```

4. **상관 분석 (Correlation) ★★**
   ```
   단일 이벤트가 아닌 복수 이벤트 조합

   예: SQL Injection 경보 + 비정상 DB 쿼리 증가
       → 실제 공격 가능성 높음
   ```

5. **정기적인 Baseline 업데이트**
   ```
   - 월별 정상 트래픽 패턴 재학습
   - 새로운 서비스 반영
   - 계절적 변화 고려
   ```

6. **Context-aware 탐지**
   ```
   시간대 고려:
   - 업무 시간: 높은 트래픽 정상
   - 심야: 낮은 트래픽도 의심
   ```

---

**[False Negative (미탐) 상세]**

**정의:**
```
실제 공격을 탐지하지 못함
"늑대가 없다" (실제로는 늑대 있음) - 더 위험!
```

**발생 원인:**

1. **Zero-Day 공격 ★★★**
   ```
   - 새로운 공격 기법
   - 시그니처 미등록
   - 업데이트 전까지 무방비
   ```

2. **우회 기법 ★★★**
   ```
   - 인코딩: URL 인코딩, Base64
   - 난독화: JavaScript 난독화
   - 조각화: IP Fragmentation
   - 암호화: SSL/TLS
   ```

3. **너무 관대한 규칙**
   ```
   - 오탐 줄이려다 임계값 너무 높게 설정
   - 조건이 너무 구체적
   ```

4. **성능 한계**
   ```
   - 대용량 트래픽에서 패킷 드롭
   - 일부 패킷 검사 누락
   ```

5. **APT (Advanced Persistent Threat)**
   ```
   - 장기간 은밀하게 진행
   - 정상 행동으로 위장
   - 여러 단계로 나누어 공격
   ```

**영향:**

1. **보안 침해 발생 ★★★**
   ```
   - 공격자가 시스템 장악
   - 데이터 유출
   - 랜섬웨어 감염
   - 서비스 중단
   ```

2. **늦은 발견**
   ```
   - 피해 확대 후 인지
   - 복구 비용 증가
   - 고객 정보 유출
   ```

3. **법적 책임**
   ```
   - 개인정보보호법 위반
   - 손해배상
   - 기업 이미지 실추
   ```

4. **False Positive보다 더 심각 ★★★**
   ```
   오탐: 불편함
   미탐: 실제 피해
   ```

**해결 방법:**

1. **시그니처 정기 업데이트 ★★★**
   ```bash
   # Snort 룰 업데이트 (일일)
   oinkmaster -o /etc/snort/rules

   # Emerging Threats 규칙셋 사용
   # 최신 공격 패턴 반영
   ```

2. **복수 탐지 기법 사용 ★★★**
   ```
   Signature + Anomaly + Behavior

   - 시그니처: 알려진 공격
   - 이상 탐지: 새로운 공격
   - 행위 기반: 공격 후 활동
   ```

3. **Defense in Depth (다층 방어) ★★★**
   ```
   1. 방화벽
   2. IPS
   3. WAF
   4. HIDS
   5. EDR
   6. SIEM

   한 계층 우회해도 다른 계층에서 탐지
   ```

4. **Threat Intelligence 연동 ★★**
   ```
   - 외부 위협 정보 수집
   - 알려진 악성 IP/도메인 차단
   - IOC (Indicators of Compromise) 활용
   ```

5. **정기 취약점 점검**
   ```
   - 모의 침투 테스트
   - 취약점 스캔
   - IDS/IPS 우회 가능성 검증
   ```

6. **로그 상관 분석**
   ```
   IDS + 방화벽 + 서버 로그 통합 분석
   단일 이벤트는 놓쳐도 전체 패턴에서 탐지
   ```

7. **Honeypot 운영**
   ```
   - 공격자 유인
   - 새로운 공격 기법 학습
   - 시그니처 생성
   ```

---

**[오탐 vs 미탐 Trade-off]**

```
        미탐 많음
           ↑
           |
      관대한 설정
           |
━━━━━━━━━━┼━━━━━━━━━━→ 임계값
           |
      엄격한 설정
           |
        오탐 많음
           ↓

균형점 찾기:
- 보안 중요도
- 서비스 특성
- 운영 인력
```

**권장 전략:**

1. **초기: 엄격하게 설정 (오탐 허용)**
   - 공격 패턴 학습
   - 정상 행동 파악

2. **중기: 점진적 완화**
   - 오탐 규칙 튜닝
   - Whitelist 추가

3. **운영: 지속적 모니터링**
   - 새로운 오탐 발생 시 조정
   - 미탐 발생 시 규칙 강화

**[측정 지표]**

```
정확도 (Accuracy) = (TP + TN) / (TP + TN + FP + FN)

정밀도 (Precision) = TP / (TP + FP)
- 경보 중 실제 공격 비율

재현율 (Recall) = TP / (TP + FN)
- 실제 공격 중 탐지 비율

F1 Score = 2 × (Precision × Recall) / (Precision + Recall)
- 종합 성능
```

**목표:**
```
- Precision (정밀도) 높이기: 오탐 감소
- Recall (재현율) 높이기: 미탐 감소
- 둘 다 높이기: 어려움 (Trade-off)
```

**[채점 기준]**
- False Positive/Negative 정의 (4점)
- 각각의 영향 (4점)
- 해결 방법 (4점)

## ✅ 핵심 요약

### 가장 자주 출제되는 Top 5 ★★★

1. **IDS vs IPS 차이**: Passive vs Inline, 탐지 vs 차단
2. **탐지 기법 3가지**: Signature, Anomaly, Behavior
3. **Snort 룰 작성**: 구조, content, flow, sid
4. **HIDS vs NIDS**: 호스트 vs 네트워크, 암호화 트래픽
5. **False Positive/Negative**: 오탐/미탐, 영향, 해결 방법

### 서술형 답안 작성 팁

1. **비교표 활용**: IDS vs IPS, HIDS vs NIDS
2. **Snort 룰 직접 작성**: 주석 포함하여 설명
3. **실무 사례**: 오탐/미탐 실제 영향
4. **다이어그램**: 배치 위치, 트래픽 흐름
5. **장단점 균형**: 양쪽 관점 모두 서술

### 실전 시험 전략

- Snort 룰 기본 구조는 **암기 필수**
- IDS/IPS 차이는 **항상 출제**
- 탐지 기법 3가지 **특징 비교**
- False Positive가 False Negative보다 **덜 심각**
- NIDS + HIDS **통합 운영**이 Best Practice
