# 보안 솔루션 - 필수 암기

## 🔴 CAPTCHA ★★★

### 문제 (2024년 기출)
```
CAPTCHA에 대한 설명으로 올바른 것은?
```

### ✅ 정답
```
CAPTCHA (Completely Automated Public Turing test to tell Computers and Humans Apart)
= 컴퓨터와 인간을 구별하기 위한 완전 자동화된 공개 튜링 테스트

정의:
사람인지 봇(자동화 프로그램)인지 구별하는 인증 기술

목적:
- 자동화된 봇 공격 방어
- 무차별 대입 공격 방지 (Brute Force)
- 스팸 등록/댓글 차단

종류:
1. 텍스트 기반
   - 왜곡된 문자/숫자 입력
   - 가장 기본적

2. 이미지 기반
   - "신호등이 있는 이미지 선택"
   - reCAPTCHA v2

3. 체크박스
   - "저는 로봇이 아닙니다" 클릭
   - reCAPTCHA v2 Invisible

4. 행동 분석 기반
   - 마우스 움직임, 클릭 패턴 분석
   - reCAPTCHA v3 (점수 기반)

단점:
- 사용자 불편
- 접근성 문제 (시각 장애인)
- AI/ML로 우회 가능성
```

## 🔴 허니팟 / 허니넷 ★★

### 문제 (2024년 기출)
```
공격자를 유인하는 보안시스템?
```

### ✅ 정답
```
허니팟 (Honeypot) ★★★
또는
허니넷 (Honeynet)

정의:
의도적으로 취약점을 가진 시스템을 구축하여
공격자를 유인하고 공격 패턴을 분석하는 미끼 시스템

목적:
1. 공격 패턴 분석
2. 공격자 추적
3. 실제 시스템 보호 (주의 분산)
4. 위협 인텔리전스 수집

종류:
1. 허니팟 (Honeypot)
   - 단일 시스템
   - 특정 서비스 에뮬레이션 (FTP, SSH, 웹 등)

2. 허니넷 (Honeynet)
   - 여러 허니팟으로 구성된 네트워크
   - 실제 네트워크처럼 구성

레벨:
- Low-interaction: 제한된 서비스만 제공 (안전)
- High-interaction: 실제 시스템 (위험하지만 정보 많음)

주의사항:
허니팟 자체가 공격 기반으로 악용될 위험
격리된 네트워크에 구축 필요
```

## 🔴 수리카타 (Suricata) ★★

### 문제 (2024년 기출)
```
수리카타의 특징은?
```

### ✅ 정답
```
Suricata

정의:
오픈소스 IDS/IPS (침입 탐지/방지 시스템)
Snort의 대안

주요 특징:

1. 멀티스레딩 ★★★
   - 다중 CPU 코어 활용
   - Snort보다 빠름 (Snort는 단일 스레드)

2. 통합 IDS/IPS/NSM
   - IDS: 침입 탐지
   - IPS: 침입 방지
   - NSM: 네트워크 보안 모니터링

3. 프로토콜 지원
   - HTTP, TLS, SMB, FTP 등 프로토콜 파싱
   - 파일 추출 및 분석

4. Snort 룰 호환
   - Snort 룰 그대로 사용 가능

5. JSON 출력
   - EVE (Extensible Event Format)
   - ELK Stack 연동 용이

Snort vs Suricata:
┌──────────┬──────────┬──────────┐
│   구분   │  Snort   │ Suricata │
├──────────┼──────────┼──────────┤
│ 스레딩   │ 단일     │ 멀티 ★  │
│ 성능     │ 보통     │ 높음     │
│ 프로토콜 │ 기본     │ 고급     │
│ 출력     │ 다양     │ JSON     │
└──────────┴──────────┴──────────┘
```

## 🔴 Wireshark (와이어샤크) ★★★

### 문제 (2024년 기출)
```
다음 설명에 해당하는 도구는?
- 네트워크 패킷을 캡처하고 분석하는 도구
- GUI 기반으로 사용이 편리
- 패킷 필터링 기능 제공
```

### ✅ 정답
```
Wireshark (와이어샤크) ★★★

정의:
오픈소스 네트워크 프로토콜 분석기 (Packet Analyzer)
네트워크 트래픽을 실시간으로 캡처하고 상세 분석하는 도구
```

### 주요 기능 ★★★

**1. 패킷 캡처 (Packet Capture)**
```
- 실시간 네트워크 트래픽 캡처
- 모든 네트워크 인터페이스 지원
- Promiscuous Mode (무차별 모드) 지원
  → 자신에게 오지 않는 패킷도 캡처 가능
```

**2. 패킷 분석 (Packet Analysis)** ★★★
```
- OSI 7계층 모든 프로토콜 분석
  - Layer 2: Ethernet, ARP
  - Layer 3: IP, ICMP
  - Layer 4: TCP, UDP
  - Layer 7: HTTP, DNS, FTP, SMTP 등

- 패킷 구조 상세 표시
  - 헤더 정보
  - 페이로드 (데이터)
  - 16진수/ASCII 뷰
```

**3. 디스플레이 필터 (Display Filter)** ★★★
```
캡처된 패킷 중 원하는 패킷만 표시

주요 필터 문법:
1. 프로토콜 필터
   - http
   - dns
   - tcp
   - udp

2. IP 주소 필터
   - ip.src == 192.168.1.100   (출발지 IP)
   - ip.dst == 8.8.8.8         (목적지 IP)
   - ip.addr == 192.168.1.1    (출발지 또는 목적지)

3. 포트 필터
   - tcp.port == 80
   - tcp.srcport == 443
   - tcp.dstport == 22

4. HTTP 필터
   - http.request.method == "GET"
   - http.request.uri contains "login"
   - http.response.code == 200

5. 논리 연산자
   - and (또는 &&)
   - or  (또는 ||)
   - not (또는 !)

   예: ip.src == 192.168.1.100 and tcp.port == 80
```

**4. 캡처 필터 (Capture Filter)** ★★
```
캡처 시작 전 필터링 (BPF 문법 사용)

예시:
- host 192.168.1.100       (특정 호스트)
- port 80                  (특정 포트)
- tcp port 443             (TCP 443 포트)
- not broadcast            (브로드캐스트 제외)
```

**5. 통계 및 분석 기능**
```
- Protocol Hierarchy (프로토콜 계층 통계)
- Conversations (통신 세션 분석)
- Endpoints (엔드포인트 통계)
- I/O Graph (트래픽 그래프)
- Expert Information (이상 패킷 탐지)
```

### 사용 시나리오 ★★★

**1. 네트워크 문제 해결 (Troubleshooting)** ★★★
```
문제: 웹 사이트 접속 안 됨

분석 방법:
1. Wireshark 실행 및 캡처 시작
2. 브라우저에서 해당 사이트 접속 시도
3. 필터 적용: http
4. TCP 3-way Handshake 확인
   - SYN → SYN-ACK → ACK
5. HTTP 요청/응답 확인
   - HTTP 200 OK? 또는 에러?
6. 응답 시간 확인 (Time 컬럼)

발견 가능한 문제:
- DNS 실패 (NXDOMAIN)
- 연결 거부 (RST 패킷)
- 타임아웃 (재전송 다수)
- 느린 응답 (지연 시간 큼)
```

**2. 보안 분석 (Security Analysis)** ★★★
```
1. ARP Spoofing 탐지
   필터: arp
   확인: 동일 IP에 대해 다른 MAC 주소

2. 포트 스캔 탐지
   필터: tcp.flags.syn == 1 and tcp.flags.ack == 0
   확인: 짧은 시간 내 다수 포트로 SYN 패킷

3. 평문 패스워드 탐지
   필터: http.request.method == "POST"
   확인: Form Data에 패스워드 평문 전송

4. DNS 터널링 탐지
   필터: dns
   확인: 비정상적으로 긴 DNS 쿼리

5. 멀웨어 C&C 통신 탐지
   확인: 의심스러운 IP로 주기적 통신
```

**3. 패킷 추출 (Follow Stream)** ★★
```
TCP 스트림 재구성:
1. 패킷 선택
2. 우클릭 → Follow → TCP Stream
3. 전체 통신 내용 확인
   - HTTP 요청/응답 전체
   - 평문 데이터 (FTP, Telnet 등)
```

### Wireshark vs tcpdump ★★

| 구분 | Wireshark | tcpdump |
|------|-----------|---------|
| **인터페이스** | GUI ★★★ | CLI (명령줄) |
| **사용 편의성** | 높음 (초보자 친화) | 낮음 (전문가용) |
| **필터링** | 강력한 디스플레이 필터 | BPF 필터 |
| **분석 기능** | 매우 풍부 (통계, 그래프 등) | 제한적 |
| **실시간 분석** | 가능 | 가능 |
| **파일 저장** | .pcap, .pcapng | .pcap |
| **성능** | GUI로 인한 부하 | 가벼움 ★★★ |
| **사용 환경** | Windows, Linux, macOS | Linux, Unix (주로) |

```
Wireshark: 상세 분석, 가시화 ★★★
tcpdump: 서버 환경, 스크립트 자동화
```

### 주요 디스플레이 필터 예시 ★★★

```
1. HTTP GET 요청만 표시
   http.request.method == "GET"

2. 특정 IP와의 통신
   ip.addr == 192.168.1.100

3. TCP 재전송 패킷 (네트워크 문제 의심)
   tcp.analysis.retransmission

4. SYN Flood 공격 탐지
   tcp.flags.syn == 1 and tcp.flags.ack == 0

5. DNS 응답 중 실패한 것만
   dns.flags.rcode != 0

6. 큰 패킷 (1000바이트 이상)
   frame.len > 1000

7. HTTPS 트래픽
   tcp.port == 443

8. 특정 도메인
   http.host contains "example.com"

9. SQL Injection 시도 의심
   http.request.uri contains "select" or http.request.uri contains "union"

10. Telnet 평문 통신
    tcp.port == 23
```

### 실전 팁 ★★

**패킷 저장 및 공유**:
```
- 파일 → Save As → .pcap 또는 .pcapng
- .pcap: 범용 형식 (tcpdump 호환)
- .pcapng: Wireshark 전용 (메타데이터 풍부)
```

**성능 최적화**:
```
- 캡처 필터로 불필요한 트래픽 제외
- 링 버퍼 사용 (순환 저장)
- 대용량 캡처 시 파일 분할
```

**주의사항** ★★★:
```
1. 법적 문제
   - 승인 없이 타인 패킷 캡처 금지
   - 회사 네트워크 분석 시 사전 승인 필요

2. 민감 정보 노출
   - 평문 패스워드
   - 개인정보
   → 저장 파일 암호화 또는 삭제

3. 네트워크 부하
   - Promiscuous Mode는 네트워크 카드 부하 증가
   - 대량 트래픽 캡처 시 CPU/메모리 소비
```

### 관련 도구

```
1. tshark ★★
   - Wireshark의 CLI 버전
   - 스크립트 자동화에 유용
   - 예: tshark -r capture.pcap -Y "http"

2. tcpdump ★★★
   - 경량 CLI 패킷 캡처
   - Linux 서버에서 기본 제공
   - 예: tcpdump -i eth0 port 80

3. Ettercap
   - MITM 공격 도구
   - ARP Spoofing 후 Wireshark로 분석

4. NetworkMiner
   - 패킷에서 파일 추출
   - 포렌식 분석
```

### 핵심 요약

```
Wireshark: ★★★

정의:
GUI 기반 네트워크 프로토콜 분석기

주요 기능:
1. 패킷 캡처 (실시간)
2. 패킷 분석 (OSI 7계층)
3. 디스플레이 필터 (강력한 필터링) ★★★
4. 통계 및 그래프

사용 시나리오:
- 네트워크 문제 해결 (Troubleshooting) ★★★
- 보안 분석 (공격 탐지)
- 프로토콜 분석
- 포렌식 조사

주요 필터:
- http
- tcp.port == 80
- ip.addr == 192.168.1.100
- http.request.method == "GET"

vs tcpdump:
- Wireshark: GUI, 상세 분석
- tcpdump: CLI, 서버 환경, 가벼움
```

**암기 팁**:
```
"와이어샤크 = 패킷 분석의 왕" ★★★
"디스플레이 필터 문법 필수 암기"
"http, tcp.port, ip.addr"
"Promiscuous Mode = 무차별 모드"
```
