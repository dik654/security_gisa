## 1. SOC (Security Operations Center)

### 문제 1-1: SOC의 정의와 역할을 설명하고, SOC의 3가지 유형을 비교하시오 (15점) ★★★

#### ✅ 모범 답안:

**[SOC 정의]**

**SOC (Security Operations Center) - 보안관제센터 ★★★**
```
정의:
조직의 보안 상태를 24/7 모니터링하고
보안 사고를 탐지, 분석, 대응하는 전담 조직

목적:
- 실시간 보안 위협 탐지
- 신속한 사고 대응
- 보안 이벤트 상관 분석
- 보안 정책 준수 확인
```

**[SOC 주요 역할]**

**1. 모니터링 (Monitoring) ★★★**
```
24/7 실시간 감시:
- 네트워크 트래픽
- 시스템 로그
- 보안 장비 이벤트
- 애플리케이션 로그

도구:
- SIEM
- IDS/IPS
- 방화벽
- 엔드포인트 보안
```

**2. 탐지 (Detection) ★★★**
```
보안 위협 식별:
- 악성코드 감염
- 비정상 접근 시도
- 내부자 위협
- DDoS 공격
- 데이터 유출

방법:
- 시그니처 기반
- 이상 탐지
- 행위 분석
- Threat Intelligence
```

**3. 분석 (Analysis) ★★★**
```
단계별 분석:

1차 분석 (Tier 1):
- 경보 분류
- 오탐 필터링
- 긴급도 판단

2차 분석 (Tier 2):
- 상세 조사
- 영향 범위 파악
- 공격 경로 추적

3차 분석 (Tier 3):
- 포렌식 분석
- 루트 원인 분석
- APT 추적
```

**4. 대응 (Response) ★★★**
```
사고 대응 조치:

즉시 조치:
- 악성 IP 차단
- 계정 정지
- 네트워크 격리
- 시스템 종료

사후 조치:
- 취약점 패치
- 정책 업데이트
- 재발 방지 대책
```

**5. 보고 (Reporting) ★★**
```
정기 보고:
- 일일 보안 현황
- 주간 위협 동향
- 월간 통계 보고
- 분기별 경영진 보고

사고 보고:
- 긴급 보고
- 상세 분석 보고
- 사후 조치 보고
```

---

**[SOC 3가지 유형]**

**1. In-House SOC (자체 구축형) ★★★**

```
구성:
[기업 본사]
    |
[자체 SOC]
- 전담 인력
- 보안 장비
- SIEM 시스템
    |
[전체 IT 인프라 모니터링]
```

**특징:**
```
구축: 기업이 직접 구축 및 운영
인력: 자체 보안 전문가 고용
위치: 기업 내부 또는 별도 시설
장비: 직접 구매 및 관리
```

**장점:**
1. **완전한 통제권 ★★★**
   - 모든 정책 자체 결정
   - 즉각적인 대응
   - 커스터마이징 자유

2. **민감 정보 보호**
   - 로그가 외부로 나가지 않음
   - 내부 정보 유출 위험 낮음

3. **조직 특화**
   - 비즈니스에 최적화
   - 내부 시스템 깊은 이해

4. **빠른 대응**
   - 내부 직원이므로 즉시 접근
   - 커뮤니케이션 원활

**단점:**
1. **높은 비용 ★★★**
   - 초기 구축: 수억~수십억
   - 인건비: 전문가 3~10명 이상
   - 장비/SW 구매 및 유지보수
   - 24/7 운영 비용

2. **인력 확보 어려움**
   - 보안 전문가 채용 경쟁
   - 교육 및 훈련 비용
   - 이직 시 공백

3. **전문성 한계**
   - 다양한 위협 경험 부족
   - 글로벌 위협 정보 접근 제한

**적합 조직:**
```
- 대기업
- 금융기관
- 정부기관
- 높은 보안 요구 조직
- 규제 준수 필요
```

---

**2. Managed SOC (아웃소싱형, MSSP) ★★★**

```
MSSP (Managed Security Service Provider)

구성:
[기업] ----로그 전송----> [외부 SOC]
                         (보안 전문 업체)
                              |
                         [모니터링]
                         [탐지/분석]
                         [대응 지원]
```

**특징:**
```
구축: 외부 보안 업체에 위탁
인력: MSSP의 보안 전문가
위치: MSSP 시설
장비: MSSP 소유
```

**장점:**
1. **낮은 비용 ★★★**
   - 초기 투자 최소화
   - 월정액 요금제
   - 인건비 절감

2. **즉시 서비스 시작**
   - 구축 기간 불필요
   - 계약 즉시 운영

3. **전문성 활용 ★★★**
   - 다양한 고객 경험
   - 최신 위협 정보 보유
   - 전문 분석가 활용

4. **24/7 운영**
   - 교대 근무 인력 확보
   - 휴가/야간 대응 가능

5. **규제 준수**
   - 컴플라이언스 지원
   - 정기 보고서 제공

**단점:**
1. **통제권 제한 ★★★**
   - 정책 변경 유연성 낮음
   - 의사결정 지연 가능

2. **정보 유출 위험**
   - 로그가 외부로 전송
   - MSSP 신뢰 필요

3. **표준화된 서비스**
   - 조직 특화 어려움
   - 커스터마이징 제한

4. **대응 지연**
   - 물리적 거리
   - 승인 절차 필요

**적합 조직:**
```
- 중소기업
- 보안 인력 부족
- 예산 제약
- 빠른 도입 필요
```

**주요 MSSP:**
```
국내:
- 안랩, NSHC, 이글루시큐리티
- 시큐아이, 지란지교시큐리티

국외:
- IBM Security, SecureWorks
- Trustwave, NTT Security
```

**3. Hybrid SOC (하이브리드형) ★★**

```
구성:
[기업]
    |
[In-House SOC]----협력----[Managed SOC]
    (1차 대응)              (2차 분석)
    |                        |
[내부 자산]              [위협 정보]
[즉시 대응]              [전문 분석]
```

**특징:**
```
기본 모니터링: 자체 SOC
고급 분석: MSSP 활용
위협 정보: MSSP 공유
긴급 대응: 자체 처리
```

**장점:**
1. **비용과 효율의 균형 ★★★**
   - 완전 자체 구축보다 저렴
   - 완전 아웃소싱보다 통제력 높음

2. **빠른 초기 대응**
   - 내부 팀이 1차 대응
   - 즉각적인 조치

3. **전문성 보완**
   - 복잡한 분석은 MSSP 활용
   - APT, 포렌식 등

4. **정보 보호**
   - 민감 데이터는 내부 처리
   - 필요한 것만 외부 공유

**단점:**
1. **복잡한 운영**
   - 두 조직 간 협력 필요
   - 명확한 역할 분담 필요

2. **여전히 비용**
   - 자체 인력 + MSSP 비용

**적합 조직:**
```
- 중견기업
- 보안 성숙도가 중간인 조직
- 점진적 내재화 계획
```

## 2. SIEM

### 문제 2-1: SIEM의 정의와 주요 기능 5가지를 설명하고, 로그 상관 분석 예시를 제시하시오 (15점) ★★★

#### ✅ 모범 답안:

**[SIEM 정의]**

**SIEM (Security Information and Event Management) ★★★**
```
정의:
보안 정보 및 이벤트 관리 시스템

= SIM (Security Information Management)
  + SEM (Security Event Management)

목적:
다양한 보안 장비와 시스템의 로그를 수집하여
실시간으로 분석하고 보안 위협을 탐지
```

**[SIEM 아키텍처]**

```
[로그 소스들]
  |
  ├─ 방화벽
  ├─ IDS/IPS
  ├─ 웹 서버
  ├─ DB 서버
  ├─ Windows/Linux
  ├─ Active Directory
  └─ 애플리케이션
      |
      ↓ (로그 수집)
[SIEM 시스템]
  |
  ├─ 로그 수집 (Collection)
  ├─ 정규화 (Normalization)
  ├─ 상관 분석 (Correlation)
  ├─ 경보 생성 (Alerting)
  └─ 시각화 (Visualization)
      |
      ↓
[보안 관제 요원]
```

---

**[SIEM 주요 기능 8가지]**

**1. 로그 수집 (Log Collection) ★★★**

```
다양한 소스로부터 로그 수집:

수집 방법:
- Syslog (UDP 514, TCP 514)
- Agent 기반 (파일 수집)
- SNMP Trap
- API 연동
- Database 쿼리

수집 대상:
- 보안 장비: 방화벽, IPS, WAF
- 서버: Windows, Linux, Unix
- 네트워크: 스위치, 라우터
- 애플리케이션: 웹, DB, 메일
- 인증: AD, LDAP, SSO
```

**예시:**
```bash
# Syslog 설정 (Linux)
*.* @@siem.company.com:514

# Windows Event Forwarding
wecutil qc
```

---

**2. 정규화 (Normalization) ★★★**

```
목적:
다양한 형식의 로그를 통일된 형식으로 변환

예시:

[원본 로그 - 방화벽]
Jan 10 10:23:45 FW-01 denied tcp 1.2.3.4:12345 -> 192.168.1.100:22

[원본 로그 - IDS]
[2024-01-10 10:23:45] ALERT: Source=1.2.3.4 Dest=192.168.1.100 Port=22

[정규화 후 - SIEM]
{
  "timestamp": "2024-01-10T10:23:45Z",
  "source_ip": "1.2.3.4",
  "source_port": "12345",
  "dest_ip": "192.168.1.100",
  "dest_port": "22",
  "protocol": "TCP",
  "action": "DENY",
  "device_type": "Firewall",
  "severity": "High"
}
```

**이점:**
- 통합 검색 가능
- 상관 분석 가능
- 일관된 보고

---

**3. 상관 분석 (Correlation Analysis) ★★★**

```
정의:
여러 이벤트를 조합하여 복잡한 공격 패턴 탐지

단일 이벤트로는 탐지 불가
→ 시간적/논리적 연관성 분석
→ 공격 시나리오 매칭
```

**상관 분석 유형:**

**시간 기반 상관 분석:**
```
Rule: Brute Force 탐지

IF (동일 source_ip에서)
   AND (동일 dest_ip로)
   AND (SSH 로그인 실패)
   AND (5분 내 10회 이상)
THEN
   Alert: "SSH Brute Force Attack"
```

**순서 기반 상관 분석:**
```
Rule: 권한 상승 공격

1. Web 취약점 스캔 탐지 (IDS)
2. 웹 서버 비정상 접근 (웹 로그)
3. 새로운 관리자 계정 생성 (시스템 로그)
4. 민감 파일 접근 (파일 로그)

→ APT 공격 의심
```

**지리적 상관 분석:**
```
IF (사용자 A가 서울에서 로그인)
   AND (10분 후 미국에서 로그인)
THEN
   Alert: "Impossible Travel - 계정 탈취 의심"
```

---

**4. 실시간 모니터링 및 경보 (Real-time Monitoring & Alerting) ★★★**

```
실시간 대시보드:
┌─────────────────────────────────┐
│  보안 현황 대시보드               │
├─────────────────────────────────┤
│ 오늘 경보: 127건                 │
│ Critical: 3   High: 15           │
│                                  │
│ [실시간 이벤트 스트림]            │
│ 10:23:45 - SQL Injection 시도    │
│ 10:23:50 - 비정상 로그인 실패    │
│                                  │
│ [Top 공격 유형]                  │
│ 1. Port Scan (45%)              │
│ 2. Brute Force (30%)            │
│ 3. Web Attack (25%)             │
└─────────────────────────────────┘

경보 채널:
- 대시보드
- 이메일
- SMS
- Slack/Teams
- SOAR 연동 (자동 대응)
```

**경보 우선순위:**
```
Critical: 즉시 대응 필요 (침해 확인)
High: 30분 내 대응
Medium: 2시간 내 검토
Low: 일일 검토
```

---

**5. 검색 및 조사 (Search & Investigation) ★★★**

```
강력한 검색 기능:

1. 키워드 검색
   source_ip:1.2.3.4 AND action:deny

2. 시간 범위 검색
   timestamp:[2024-01-01 TO 2024-01-31]

3. 정규식 검색
   username:/admin.*/

4. 집계 쿼리
   stats count by source_ip | sort -count

5. 상관 쿼리
   transaction source_ip maxspan=5m
```

**사용 사례:**
```
사고 조사:
- 특정 IP의 모든 활동 추적
- 계정 탈취 후 행동 분석
- 공격 타임라인 재구성
- 영향 받은 시스템 식별
```

---

**6. 보고 (Reporting) ★★**

```
정기 보고서:

일일 보고서:
- 당일 주요 이벤트
- 처리된 사건
- 미해결 사건

주간 보고서:
- 주간 위협 동향

## 3. 보안관제 업무

### 문제 3-1: 보안관제 요원의 역할을 Tier별로 구분하여 설명하고, 사고 대응 절차 6단계를 설명하시오 (15점) ★★★

#### ✅ 모범 답안:

**[Tier별 역할 구분]**

```
        [경영진/CISO]
              ↑ 보고
        ─────────────
        [Tier 3]
        고급 분석가
              ↑ 에스컬레이션
        ─────────────
        [Tier 2]
        분석가
              ↑ 에스컬레이션
        ─────────────
        [Tier 1]
        모니터링 요원
              ↑ 경보
        ─────────────
        [SIEM/보안장비]
```

---

**[Tier 1 - 모니터링 요원 (1차 대응)] ★★★**

**역할:**
```
24/7 실시간 모니터링 및 1차 분류
"보안의 눈과 귀"
```

**주요 업무:**

1. **경보 모니터링**
   ```
   - SIEM 대시보드 모니터링
   - IDS/IPS 경보 확인
   - 방화벽 이벤트 검토
   - 엔드포인트 알림 확인
   ```

2. **경보 분류 (Triage)**
   ```
   각 경보에 대해:
   - True Positive (실제 공격) → 에스컬레이션
   - False Positive (오탐) → 종결
   - Benign Positive (의심 없음) → 종결
   ```

3. **초기 대응**
   ```
   명확한 공격:
   - 악성 IP 차단
   - 계정 임시 정지
   - 시스템 네트워크 격리
   ```

4. **문서화**
   ```
   - 티켓 생성 (Incident Ticket)
   - 경보 정보 기록
   - 초기 조치 내역
   ```

**필요 역량:**
```
- 보안 기본 지식
- SIEM 사용법
- 경보 분류 능력
- 빠른 판단력
```

**처리 시간:**
```
- 경보당 5~15분
- 일일 100~200건 처리
```

**에스컬레이션 기준:**
```
Tier 2로 전달:
- 불명확한 공격
- 복잡한 패턴
- 고위험 시스템 관련
- Critical/High 우선순위
```

---

**[Tier 2 - 분석가 (2차 분석)] ★★★**

**역할:**
```
심층 분석 및 사고 조사
"보안의 탐정"
```

**주요 업무:**

1. **상세 분석**
   ```
   - 공격 벡터 파악
   - 공격 단계 추적
   - 영향 범위 분석
   - 공격자 프로파일링
   ```

2. **로그 상관 분석**
   ```
   다양한 로그 종합:
   - 방화벽 + IDS + 서버 로그
   - 시간대별 이벤트 매핑
   - 공격 타임라인 구성
   ```

3. **위협 인텔리전스 활용**
   ```
   - 공격자 IP/도메인 조회
   - 악성코드 해시 검색
   - IOC 매칭
   - 유사 공격 사례 검색
   ```

4. **대응 조치**
   ```
   - 정교한 차단 규칙 생성
   - 시스템 패치 지시
   - 정책 업데이트 권고
   ```

5. **보고서 작성**
   ```
   - 사고 분석 보고서
   - 근본 원인 분석
   - 재발 방지 대책
   ```

**필요 역량:**
```
- 네트워크/시스템 전문 지식
- 공격 기법 이해
- 로그 분석 능력
- 포렌식 기술
- Threat Hunting
```

**처리 시간:**
```
- 사건당 1~4시간
- 복잡한 사건: 수일
```

**에스컬레이션 기준:**
```
Tier 3로 전달:
- APT 의심
- 대규모 침해
- 포렌식 필요
- 새로운 공격 기법
```

---

**[Tier 3 - 고급 분석가 (전문가)] ★★★**

**역할:**
```
고도화된 위협 대응 및 전략 수립
"보안의 마스터"
```

**주요 업무:**

1. **APT 분석**
   ```
   - 장기간 공격 추적
   - 공격자 TTP 분석
     (Tactics, Techniques, Procedures)
   - MITRE ATT&CK 매핑
   ```

2. **디지털 포렌식**
   ```
   - 메모리 덤프 분석
   - 디스크 이미징
   - 악성코드 리버스 엔지니어링
   - 증거 수집 및 보전
   ```

3. **Threat Hunting**
   ```
   수동적 탐지가 아닌 능동적 위협 사냥:
   - 가설 수립
   - 데이터 분석
   - 숨은 위협 발굴
   ```

4. **전략 수립**
   ```
   - 보안 아키텍처 개선
   - 탐지 규칙 개발
   - 대응 플레이북 작성
   - 보안 도구 선정
   ```

5. **교육 및 멘토링**
   ```
   - Tier 1/2 교육
   - 최신 위협 동향 공유
   - 모의 훈련 실시
   ```

**필요 역량:**
```
- 10년+ 보안 경력
- 고급 포렌식 능력
- 리버스 엔지니어링
- 프로그래밍 (Python, PowerShell)
- 침투 테스트 경험
- 보안 인증: CISSP, GCIA, GCFE
```

**처리 시간:**
```
- 프로젝트 단위 (수주~수개월)
```

---

**[사고 대응 절차 6단계 - NIST 기반] ★★★**

**1. 준비 (Preparation) ★★★**

```
사전 준비 단계:

정책 및 절차:
- 사고 대응 계획 수립
- 대응 플레이북 작성
- 역할 및 책임 정의
- 연락망 구축

도구 준비:
- 포렌식 도구
- 백업 시스템
- 격리 네트워크
- 통신 채널 (암호화)

교육:
- 대응 팀 훈련
- 모의 훈련 (Table-top Exercise)
- 시나리오 기반 연습
```

**중요성:**
```
"평상시 준비가 사고 대응의 80%를 결정"
```

---

**2. 탐지 및 분석 (Detection & Analysis) ★★★**

```
사고 식별 및 초기 분석:

탐지:
- SIEM 경보
- IDS/IPS 알림
- 사용자 제보
- Threat Intelligence

초기 분석:
- 경보 검증 (오탐 여부)
- 사고 유형 분류
  - 악성코드
  - 침입
  - DDoS
  - 데이터 유출
- 심각도 평가
  - Critical: 즉시 대응
  - High: 30분 내
  - Medium: 2시간 내
  - Low: 일일 검토

상세 분석:
- 공격 벡터 파악
- 영향 받은 시스템 식별
- 공격 타임라인 구성
- IOC 추출
```

**문서화:**
```
- 사고 번호 부여
- 최초 탐지 시간
- 탐지 방법
- 초기 증거 수집
```

---

**3. 격리 (Containment) ★★★**

```
확산 방지 및 피해 최소화:

단기 격리 (Short-term):
- 악성 IP 차단
- 감염 시스템 네트워크 격리
- 계정 비활성화
- 서비스 임시 중단

장기 격리 (Long-term):
- 백업에서 복원
- 임시 시스템 구축
- 서비스 우회 경로
- 사용자 통지

격리 시 고려사항:
- 비즈니스 영향 최소화
- 증거 보전
- 공격자에게 탐지 사실 숨김
  (공격자 추적 목적)
```

**예시:**
```
랜섬웨어 감염:
1. 감염 PC 네트워크 즉시 차단
2. 동일 네트워크 세그먼트 격리
3. 공유 폴더 접근 차단
4. 백업 서버 격리 (2차 감염 방지)
```

---

**4. 제거 (Eradication) ★★★**

```
위협 완전 제거:

악성코드 제거:
- 악성 파일 삭제
- 레지스트리 정리
- 백도어 제거
- Persistence 메커니즘 제거

취약점 제거:
- 패치 적용
- 설정 강화
- 패스워드 변경
- 불필요한 계정/서비스 삭제

검증:
- 백신 전체 스캔
- IOC 재검색
- 네트워크 트래픽 모니터링
- 재감염 여부 확인 (24~48시간)
```

**체크리스트:**
```
□ 모든 악성 파일 삭제됨
□ 백도어 없음 확인
□ 취약점 패치 완료
□ 패스워드 변경 완료
□ IOC 재검색 결과 음성
□ 포렌식 증거 확보 완료
```

---

**5. 복구 (Recovery) ★★★**

```
정상 운영 재개:

시스템 복구:
- 백업에서 복원
- 또는 클린 OS 재설치
- 최신 패치 적용
- 보안 설정 강화

서비스 재개:
- 점진적 복구
  1. 내부 테스트 환경
  2. 일부 사용자
  3. 전체 서비스
- 집중 모니터링
- 이상 징후 즉시 보고

검증:
- 기능 테스트
- 성능 테스트
- 보안 스캔

**2. 로그 무결성 (Integrity) ★★★**

```
로그 위변조 방지:

위협:
- 공격자가 로그 삭제로 흔적 제거
- 내부자가 로그 조작
- 시스템 장애로 로그 손실

보호 방법:

A. 중앙 집중화 ★★★
   ```
   [서버] --즉시 전송--> [중앙 로그 서버]

   - 원본 서버에서 로그 삭제해도 중앙에 보관
   - 실시간 전송 (Syslog, Agent)
   ```

B. 읽기 전용 권한
   ```bash
   # 로그 디렉토리 권한 설정
   chmod 644 /var/log/*
   chown root:root /var/log/*

   # 로그 서버 접근 제한
   - 관리자만 읽기 권한
   - 수정/삭제 불가
   ```

C. 해시 및 전자서명
   ```
   로그 생성 시 해시 계산:
   SHA-256(log_entry) → 블록체인 저장

   위변조 검증:
   현재 해시 == 저장된 해시 → 무결성 확인
   ```

D. WORM (Write Once Read Many) 스토리지
   ```
   - 한 번 기록 후 수정 불가
   - 물리적 보호
   - 규제 산업 필수 (금융, 의료)
   ```

E. 백업
   ```
   - 다른 위치에 백업
   - 암호화 보관
   - 정기 백업 (일일/주간)
   ```
```

**3. 로그 동기화 (Time Synchronization) ★★★**

```
정확한 시간 기록:

중요성:
- 사고 타임라인 재구성
- 상관 분석 정확도
- 포렌식 증거 능력

문제 상황:
```
[웹 서버 로그] 10:00:00 - SQL Injection 시도
[DB 서버 로그]  09:59:50 - 대량 쿼리 실행

→ 시간 불일치로 상관 분석 실패!
```

해결 방법: NTP (Network Time Protocol)

설정:
```bash
# Linux NTP 설정
apt-get install ntp
vi /etc/ntp.conf

server time.google.com iburst
server time.windows.com iburst
server kr.pool.ntp.org iburst

systemctl restart ntp

# 시간 동기화 확인
ntpq -p
```

권장사항:
- 모든 시스템 NTP 설정
- 내부 NTP 서버 구축
- 시간 오차 ±1초 이내
- Stratum 3 이하 (정확도)
- 백업 NTP 서버 설정
```

**4. 로그 보존 기간 (Retention) ★★★**

```
적절한 기간 동안 로그 보관:

고려사항:
- 법적 요구사항
- 규정 준수
- 디스크 용량
- 비용

단계별 보관:

Hot Storage (SSD/고속):
- 기간: 최근 30일
- 목적: 실시간 분석, 빠른 검색
- 비용: 높음

Warm Storage (HDD):
- 기간: 31일 ~ 1년
- 목적: 사고 조사, 정기 분석
- 비용: 중간

Cold Storage (Tape/Cloud):
- 기간: 1년 ~ 보존 기간
- 목적: 규정 준수, 장기 보관
- 비용: 낮음

예시:
```
금융권:
- Hot: 30일 (SSD)
- Warm: 1년 (HDD)
- Cold: 5년 (Tape)
- 총 보관: 5년

일반 기업:
- Hot: 30일
- Warm: 6개월
- Cold: 1년
- 총 보관: 1년
```

압축 및 아카이빙:
```bash
# 30일 이상 로그 압축
find /var/log -name "*.log" -mtime +30 -exec gzip {} \;

# 1년 이상 로그 아카이브
tar -czf logs_2023.tar.gz /var/log/archive/2023/
```
```

총 비용: 약 $260 + $60/년

1. **비교표 활용**: SOC 유형, Tier별 역할
2. **실제 예시**: 로그 상관 분석 시나리오
3. **단계별 설명**: 사고 대응 절차
4. **수치 제시**: 로그 보관 기간, 용량 계산
5. **Best Practice**: 실무 권장사항

### 실전 시험 전략

- SOC 유형은 **장단점 비교** 필수
- SIEM 상관 분석 **시나리오 작성** 연습
- Tier 1/2/3 **역할 차이** 명확히
- 사고 대응 6단계 **순서 암기**
- 로그 보관 기간 **법적 근거** 제시
