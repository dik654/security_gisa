## 📝 기출 유형 1: 보안 관제 3요소 설명 ★★★

### 문제 1-1 (2024년 실기)
```
보안 관제의 3요소를 쓰고, 모니터링 단계에서 각각의 역할을 설명하시오.
```

**✅ 정답:**

**보안 관제 3요소:**
```
1. 탐지 (Detection)
2. 대응 (Response)
3. 복구 (Recovery)
```

**모니터링 단계에서의 역할:**

**1. 탐지 (Detection) 단계**
```
목적: 보안 위협 및 이상 징후 조기 발견

주요 활동:
ㄱ. 로그 수집 및 분석
   - 방화벽, IDS/IPS, 서버, 네트워크 장비 로그
   - Syslog, Windows Event Log 수집
   - SIEM (Security Information and Event Management)으로 통합

ㄴ. 실시간 모니터링
   - 트래픽 패턴 분석 (정상/비정상 트래픽 구분)
   - 이상 징후 탐지 (Anomaly Detection)
   - 공격 패턴 매칭 (Signature-based Detection)

ㄷ. 위협 인텔리전스 활용
   - 알려진 악성 IP, 도메인 차단 리스트
   - CVE 취약점 정보 수집
   - IOC (Indicators of Compromise) 모니터링

ㄹ. 경보 발생
   - 임계값 초과 시 경보 (예: 5분간 로그인 실패 100회)
   - 공격 패턴 탐지 시 알림 (SQL Injection, DDoS)

사용 도구:
- IDS/IPS: Snort, Suricata, Zeek
- SIEM: Splunk, ELK Stack, QRadar
- 패킷 분석: Wireshark, tcpdump
- 트래픽 분석: NetFlow, sFlow
```

**2. 대응 (Response) 단계**
```
목적: 탐지된 위협에 대한 즉각적 조치

주요 활동:
ㄱ. 긴급 차단
   - 공격 IP 차단 (방화벽 ACL 추가)
   - 악성 트래픽 필터링 (IPS 차단 룰)
   - 감염 시스템 네트워크 격리

   명령어 예시:
   iptables -A INPUT -s 공격IP -j DROP
   fw acl add deny src 공격IP

ㄴ. 침해사고 대응
   - NIST 침해사고 대응 절차 수행
     (Identification → Containment → Eradication)
   - 증거 수집 및 보존 (메모리 덤프, 로그 백업)
   - 관련 부서 통보 (경영진, IT팀, 법무팀)

ㄷ. 우회 경로 확인
   - 공격자가 다른 경로로 재침투 시도하는지 점검
   - 백도어, 웹셸 존재 여부 확인

ㄹ. 피해 범위 파악
   - 감염 시스템 대수
   - 유출된 데이터 확인
   - 영향받은 서비스

사용 도구:
- 방화벽: iptables, firewalld, pfSense
- WAF: ModSecurity, AWS WAF
- EDR: CrowdStrike, Carbon Black
- 포렌식: FTK, EnCase
```

**3. 복구 (Recovery) 단계**
```
목적: 시스템 정상화 및 재발 방지

주요 활동:
ㄱ. 시스템 복구
   - 악성코드 제거
   - 백업에서 데이터 복원
   - 또는 시스템 재설치

ㄴ. 취약점 패치
   - 침투에 사용된 취약점 패치
   - 긴급 보안 업데이트 적용
   - 설정 강화 (계정 정책, 방화벽 룰)

ㄷ. 보안 강화
   - 패스워드 변경 (노출 가능성 있는 계정)
   - 2FA (이중 인증) 활성화
   - 불필요한 서비스 중지

ㄹ. 재발 방지 대책
   - 공격 경로 차단 (취약한 포트 닫기)
   - 모니터링 강화 (1주일간 집중 관찰)
   - 보안 정책 업데이트

ㅁ. 사후 분석 보고서
   - 사고 경위 및 원인
   - 피해 규모 및 영향
   - 대응 조치 내역
   - 재발 방지 계획

사용 도구:
- 백신: V3, 알약, Windows Defender
- 패치 관리: WSUS, Ansible, Puppet
- 백업: Veeam, Commvault
```

## 📝 기출 유형 3: SIEM 기반 관제 ★★

### SIEM (Security Information and Event Management)

**정의:**
```
보안 정보 및 이벤트 관리 시스템
다양한 보안 장비와 시스템의 로그를 수집·분석·상관관계 분석하여
통합 관제하는 솔루션
```

**주요 기능:**
```
1. 로그 수집 (Log Collection)
   - Syslog, SNMP, API 등으로 로그 수집
   - 정규화 (Normalization): 다양한 형식을 통일

2. 이벤트 상관 분석 (Correlation)
   - 여러 이벤트의 연관성 분석
   - 예: 로그인 실패 10회 + 다른 IP에서 로그인 성공
        → 계정 탈취 의심

3. 실시간 모니터링
   - 대시보드로 실시간 현황 표시
   - 경보 발생 시 알림 (이메일, SMS)

4. 보고서 생성
   - 일/주/월 보안 현황 리포트
   - 규정 준수 (Compliance) 리포트
   - 경영진 보고용 요약
```

**주요 제품:**
```
- Splunk (상용)
- IBM QRadar (상용)
- ELK Stack (오픈소스: Elasticsearch, Logstash, Kibana)
- Graylog (오픈소스)
```

## 💡 실기 답안 작성 팁

### Tip 1: 3요소는 맥락에 맞게
```
문제가 "예방-탐지-대응" 맥락이면:
✅ 1. 예방 (Prevention)
   2. 탐지 (Detection)
   3. 대응 (Response)

문제가 "사고 대응" 맥락이면:
✅ 1. 탐지 (Detection)
   2. 대응 (Response)
   3. 복구 (Recovery)

문제: "모니터링 단계" → 탐지-대응-복구
```

### Tip 2: 구체적 도구 명시
```
✅ 탐지: IDS/IPS (Snort), SIEM (Splunk)
   대응: 방화벽 (iptables), WAF (ModSecurity)

❌ 탐지: 네트워크 모니터링 (도구 없이 추상적)
```

### Tip 3: 단계별 역할 명확히
```
✅ 탐지: 로그 수집 → 분석 → 경보 발생
   대응: IP 차단 → 격리 → 증거 수집
   복구: 악성코드 제거 → 패치 → 모니터링 강화

❌ 탐지: 모니터링 (역할 설명 부족)
```

### Tip 4: 명령어 예시 포함 시 가산점
```
✅ 대응: iptables -A INPUT -s 공격IP -j DROP
   탐지: tcpdump -i eth0 -w capture.pcap

점수 향상 가능!
```

## 📝 종합 문제: 보안 관제 시나리오

### 종합 문제 1
```
SOC 관제 중 SIEM에서 다음 경보가 발생했다.

경보 내용:
- 출발지: 203.0.113.50 (중국)
- 목적지: 웹 서버 (192.168.1.100:80)
- 패턴: SQL Injection 시도 (100회/분)
- 시간: 14:00~14:30 (30분간 지속)

보안 관제 3요소에 따라 대응 절차를 단계별로 작성하시오.
```

**✅ 답안:**

**1. 탐지 (Detection) 단계**
```
SIEM 경보 분석:
- IDS/IPS 시그니처 매칭: SQL Injection 패턴 탐지
- 위협 인텔리전스 확인: 203.0.113.50은 알려진 공격 IP
- 로그 상관 분석: 동일 IP에서 포트 스캔도 시도 (14:00 직전)

추가 확인:
- 웹 서버 로그 분석:
  tail -f /var/log/apache2/access.log | grep "203.0.113.50"

- SQL Injection 성공 여부 확인:
  HTTP 응답 코드: 200 (일부 성공 의심)
  에러 메시지 노출: SQL syntax error 확인

판단:
→ 실제 공격으로 판단 (False Positive 아님)
→ Tier 2로 에스컬레이션
```

**2. 대응 (Response) 단계**
```
즉시 조치:
ㄱ. 공격 IP 차단
   iptables -A INPUT -s 203.0.113.50 -j DROP
   또는 WAF에서 차단

ㄴ. 웹 서버 격리 (선택적)
   - 중요 데이터 처리 중이면 임시 서비스 중지
   - 백업 서버로 전환

ㄷ. 증거 수집
   - 웹 로그 백업: cp /var/log/apache2/access.log /evidence/
   - 패킷 캡처 (향후 분석용):
     tcpdump -i eth0 src 203.0.113.50 -w attack.pcap
   - DB 쿼리 로그 확인

ㄹ. 피해 범위 파악
   - DB 접속 로그 확인: 비정상 쿼리 실행 여부
   - 데이터 유출 여부: SELECT 쿼리로 민감 정보 조회 시도
   - 웹셸 업로드 시도: 파일 시스템 점검

ㅁ. 관련 부서 통보
   - SOC 센터장 보고
   - 웹 서비스 담당자 통보
   - 필요 시 경영진 보고
```

**3. 복구 (Recovery) 단계**
```
ㄱ. 취약점 패치
   - 웹 애플리케이션 코드 점검
   - SQL Injection 취약점 제거 (Prepared Statement 적용)

   수정 전:
   $query = "SELECT * FROM users WHERE id='$id'";

   수정 후:
   $stmt = $conn->prepare("SELECT * FROM users WHERE id=?");
   $stmt->bind_param("s", $id);

ㄴ. WAF 룰 강화
   - SQL Injection 패턴 차단 룰 추가
   - ModSecurity CRS (Core Rule Set) 업데이트

ㄷ. 입력값 검증 강화
   - Whitelist 방식 필터링
   - 특수문자 필터링 (, ", --, ; 등)

ㄹ. 모니터링 강화
   - 동일 공격 재시도 여부 1주일간 집중 관찰
   - 다른 IP에서 유사 공격 시도 모니터링

ㅁ. 사후 분석 보고서 작성
   - 공격 타임라인
   - 피해 규모 (데이터 유출 없음 확인)
   - 대응 조치 내역
   - 재발 방지 대책 (코드 수정, WAF 강화)
```
