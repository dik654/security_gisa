# 암호화 추가 개념 - PKI, Endianness, 알고리즘

## 🔴 PKI 구성요소 ★★★

### 문제 (2024년 기출)
```
PKI 구성요소는?
```

### ✅ 정답
```
PKI (Public Key Infrastructure) = 공개키 기반 구조

주요 구성요소: ★★★

1. CA (Certificate Authority) - 인증기관 ★★★
   - 디지털 인증서 발급
   - 공개키 인증
   - 신뢰의 뿌리 (Root CA)

   한국 Root CA:
   - KISA (한국인터넷진흥원) ★★★
   - 금융결제원
   - 한국전자인증
   - 코스콤

2. RA (Registration Authority) - 등록기관 ★★
   - 인증서 발급 신청 접수
   - 신원 확인
   - CA의 부담 경감

3. 인증서 저장소 (Certificate Repository)
   - 발급된 인증서 보관
   - 공개키 배포

4. CRL (Certificate Revocation List) - 인증서 폐기 목록 ★★
   - 폐기된 인증서 목록
   - 주기적으로 발행 (예: 매일, 매주)
   - 단점: 크기가 커짐, 실시간 확인 불가

5. OCSP (Online Certificate Status Protocol) ★★★
   - 인증서 유효성 실시간 확인
   - CRL의 단점 보완
   - 요청/응답 방식
   - 더 빠르고 효율적

구조도:
┌──────────────────────────────────────┐
│         Root CA (KISA)               │
│       최상위 인증기관 ★★★           │
└──────────────┬───────────────────────┘
               │
      ┌────────┴────────┐
      │                 │
┌─────▼─────┐    ┌──────▼──────┐
│ Sub CA 1  │    │  Sub CA 2   │
│ (은행)    │    │  (정부)     │
└─────┬─────┘    └──────┬──────┘
      │                 │
      ▼                 ▼
┌──────────┐      ┌──────────┐
│   RA     │      │   RA     │
│ 등록기관 │      │ 등록기관 │
└──────────┘      └──────────┘

PKI 프로세스:
1. 사용자 → RA: 인증서 신청 + 신원확인
2. RA → CA: 신청 전달 (신원 확인 완료)
3. CA: 인증서 발급 (개인키로 서명)
4. 인증서 배포: 저장소에 저장
5. 검증:
   - CRL 확인 (주기적)
   - OCSP 확인 (실시간) ★

CRL vs OCSP:
┌────────────┬──────────┬──────────┐
│   구분     │   CRL    │  OCSP    │
├────────────┼──────────┼──────────┤
│ 확인 방식  │ 주기적   │ 실시간 ★│
│ 크기       │ 큼       │ 작음     │
│ 효율       │ 낮음     │ 높음 ★  │
│ 네트워크   │ 다운로드 │ 요청응답 │
└────────────┴──────────┴──────────┘
```

## 🔴 Endianness (바이트 순서) ★★

### 문제 (2024년 기출)
```
Little-Endian과 Big-Endian의 차이는?
```

### ✅ 정답
```
Endianness = 다중 바이트 데이터의 저장 순서

예시: 0x12345678 (4바이트)

1. Little-Endian ★★★
   = 작은 바이트(하위)부터 저장

   메모리 저장 순서:
   ┌──────┬──────┬──────┬──────┐
   │ 주소 │0x100 │0x101 │0x102 │0x103│
   ├──────┼──────┼──────┼──────┼─────┤
   │ 값   │ 0x78 │ 0x56 │ 0x34 │ 0x12│
   └──────┴──────┴──────┴──────┴─────┘
           하위 ←─────────→ 상위

   사용:
   - Intel x86/x64 ★★★
   - AMD 프로세서
   - ARM (기본 모드)

2. Big-Endian ★★
   = 큰 바이트(상위)부터 저장

   메모리 저장 순서:
   ┌──────┬──────┬──────┬──────┐
   │ 주소 │0x100 │0x101 │0x102 │0x103│
   ├──────┼──────┼──────┼──────┼─────┤
   │ 값   │ 0x12 │ 0x34 │ 0x56 │ 0x78│
   └──────┴──────┴──────┴──────┴─────┘
           상위 ─────────→ 하위

   사용:
   - 네트워크 프로토콜 (Network Byte Order) ★★★
   - SPARC, PowerPC
   - 모토로라 프로세서

비교:
┌──────────────┬──────────────┬──────────────┐
│    구분      │Little-Endian │ Big-Endian   │
├──────────────┼──────────────┼──────────────┤
│ 저장 순서    │ 하위 바이트  │ 상위 바이트  │
│              │ 먼저 ★      │ 먼저         │
├──────────────┼──────────────┼──────────────┤
│ 사용         │ Intel x86 ★ │ 네트워크 ★  │
├──────────────┼──────────────┼──────────────┤
│ 장점         │ 연산 빠름    │ 직관적       │
├──────────────┼──────────────┼──────────────┤
│ 포렌식       │ 메모리 분석  │ 패킷 분석   │
│              │ 시 고려 ★★ │ 시 고려 ★★ │
└──────────────┴──────────────┴──────────────┘

포렌식 중요성:
- 메모리 덤프 분석 시 Endian 고려 필수 ★★★
- 네트워크 패킷은 Big-Endian
- 시스템 메모리는 Little-Endian (Intel)
- 잘못 해석하면 데이터 오분석!

예시:
메모리: 0x78 0x56 0x34 0x12
→ Little-Endian: 0x12345678
→ Big-Endian: 0x78563412 (틀림!)

변환:
- htonl() : Host to Network Long (Little → Big)
- ntohl() : Network to Host Long (Big → Little)
```

## 🔴 암호 알고리즘 상세 ★★

### 문제 (2024년 기출)
```
MD5, SHA-1, RSA, RC5의 특징은?
```

### ✅ 정답
```
1. MD5 (Message Digest 5) ★★

   분류: 해시 함수
   출력: 128bit (16바이트)

   특징:
   - 빠른 속도
   - 충돌 취약점 발견 ★★★
   - 보안용도 사용 금지 (권고)

   용도:
   - 파일 무결성 검증 (체크섬)
   - 비보안 용도

2. SHA-1 (Secure Hash Algorithm 1) ★★

   분류: 해시 함수
   출력: 160bit (20바이트)

   특징:
   - MD5보다 안전했으나
   - 2017년 충돌 발견 (Google) ★★
   - 현재 사용 금지 권고

   용도:
   - Git (커밋 해시)
   - 기존 시스템 (레거시)

3. SHA-256 (권장) ★★★

   분류: 해시 함수 (SHA-2 계열)
   출력: 256bit (32바이트)

   특징:
   - 현재 권장 해시 함수 ★★★
   - 충돌 미발견
   - 블록체인에서 사용 (비트코인)

4. RSA (Rivest-Shamir-Adleman) ★★★

   분류: 공개키 암호 (비대칭키)
   키 크기: 1024bit, 2048bit, 4096bit

   특징:
   - 소인수분해 난이도 기반
   - 느린 속도
   - 디지털 서명, 키 교환에 사용

   용도:
   - SSL/TLS 인증서 ★★★
   - 디지털 서명
   - 세션키 암호화 (하이브리드 암호)

5. RC5 (Rivest Cipher 5) ★

   분류: 대칭키 블록 암호
   블록 크기: 32, 64, 128bit (가변)
   키 크기: 0~2040bit (가변)
   라운드: 0~255 (가변)

   특징:
   - 가변 파라미터 ★
   - 빠른 속도
   - 단순한 구조

   현재:
   - 특허 만료
   - AES에 밀려 사용 감소

비교표:
┌──────┬─────┬────────┬────────┬────────┐
│ 알고 │분류 │  크기  │  보안  │  용도  │
├──────┼─────┼────────┼────────┼────────┤
│ MD5  │해시 │ 128bit │ 취약 ✗│체크섬  │
├──────┼─────┼────────┼────────┼────────┤
│SHA-1 │해시 │ 160bit │ 취약 ✗│레거시  │
├──────┼─────┼────────┼────────┼────────┤
│SHA256│해시 │ 256bit │ 안전 ✓│권장 ★ │
├──────┼─────┼────────┼────────┼────────┤
│ RSA  │공개키│2048bit│ 안전 ✓│인증서★│
├──────┼─────┼────────┼────────┼────────┤
│ RC5  │대칭키│가변   │ 보통  │레거시  │
└──────┴─────┴────────┴────────┴────────┘

권장 조합 (하이브리드 암호):
1. RSA로 대칭키(AES 키) 암호화 ★★★
2. AES로 데이터 암호화
3. SHA-256으로 해시/서명

예: SSL/TLS
- RSA: 키 교환
- AES: 데이터 암호화
- SHA-256: 메시지 인증 (HMAC)
```

## 🔴 ISO 27000 시리즈 ★★

### 문제 (2024년 기출)
```
ISO 27000 시리즈와 ISMS-P의 관계는?
```

### ✅ 정답
```
ISO 27000 시리즈 = 국제 정보보안 표준

주요 표준:

1. ISO 27001 ★★★
   - 정보보호 관리체계(ISMS) 요구사항
   - 인증 표준
   - 한국의 ISMS-P와 유사 ★★

2. ISO 27002
   - 정보보호 통제 지침
   - 구현 가이드

3. ISO 27005
   - 정보보호 위험관리

4. ISO 27017
   - 클라우드 보안

5. ISO 27018
   - 클라우드 개인정보보호

비교: ISO 27001 vs ISMS-P
┌──────────────┬────────────┬────────────┐
│    구분      │ ISO 27001  │  ISMS-P    │
├──────────────┼────────────┼────────────┤
│ 범위         │ 국제       │ 한국 ★    │
├──────────────┼────────────┼────────────┤
│ 인증기관     │ 국제인증   │ KISA ★★  │
├──────────────┼────────────┼────────────┤
│ 개인정보     │ 별도       │ 통합 ★★★ │
│              │(ISO 27701) │            │
├──────────────┼────────────┼────────────┤
│ 법적 효력    │ 없음       │ 있음 ★    │
│              │            │(정보통신망법)│
└──────────────┴────────────┴────────────┘

ISMS-P 특징:
- ISMS (정보보호) + PIMS (개인정보보호) 통합
- 한국 법령 반영
- 의무인증 대상 존재 ★★★
  1. 정보통신서비스 제공자 (전년도 매출 100억 이상)
  2. 전년도 3개월간 일평균 이용자 100만명 이상

PIA (Privacy Impact Assessment) ★★
= 개인정보 영향평가

대상:
- 구축/운영 전 개인정보 침해 위험 평가
- 공공기관: 5만명 이상 개인정보 보유 시스템
- 민간: 100만명 이상

평가 항목:
1. 개인정보 보호 계획 적정성
2. 위험도 분석
3. 안전성 확보 조치
4. 사후관리 계획
```

## 🎯 암호화/포렌식 핵심 암기 카드

### 카드 1: PKI 구성요소
```
CA: 인증기관 (KISA) ★★★
RA: 등록기관
CRL: 폐기 목록 (주기적)
OCSP: 실시간 확인 ★★
```

### 카드 2: Endianness
```
Little-Endian: 하위 바이트 먼저 (Intel x86) ★★★
Big-Endian: 상위 바이트 먼저 (네트워크) ★★
포렌식 시 반드시 고려!
```

### 카드 3: 해시 함수
```
MD5: 128bit, 충돌 취약 ✗
SHA-1: 160bit, 충돌 발견 ✗
SHA-256: 256bit, 권장 ★★★
```

### 카드 4: RSA
```
공개키 암호 (비대칭키)
2048bit 이상 권장
SSL/TLS 인증서에 사용 ★★★
```

### 카드 5: ISO 27001
```
국제 ISMS 표준
한국의 ISMS-P와 유사
KISA 인증 (한국)
```

## 💡 실기 답안 작성 팁

### Tip 1: PKI 구성요소
```
✅ CA (인증기관), RA (등록기관), OCSP (실시간 확인), CRL (폐기 목록)

❌ CA만 쓰기 (불완전)
```

### Tip 2: Endianness
```
✅ Little-Endian: 하위 바이트 먼저, Intel x86 사용
✅ Big-Endian: 상위 바이트 먼저, 네트워크 바이트 순서

❌ Little이 더 빠르다 (핵심 아님)
```

### Tip 3: 해시 함수 선택
```
✅ SHA-256 권장, MD5/SHA-1은 충돌 취약 ★★★

❌ MD5가 빠르니까 MD5 사용 (보안 취약!)
```

### Tip 4: KISA Root CA
```
✅ KISA (한국인터넷진흥원)가 한국 최상위 인증기관 ★★★

❌ 금융결제원이 최상위 (Sub CA임)
```
