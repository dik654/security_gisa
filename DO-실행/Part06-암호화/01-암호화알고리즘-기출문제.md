## 📝 기출 유형 1: 알고리즘 스펙 문제

### 문제 1-1 (2023년 기출 유사)
```
다음 중 AES-256 암호 알고리즘에 대한 설명으로 옳은 것은?

① 키 길이는 256비트이고, 블록 크기는 256비트이다.
② 라운드 수는 10라운드이다.
③ Feistel 구조를 사용한다.
④ 키 길이는 256비트이고, 라운드 수는 14라운드이다.
```

**✅ 정답: ④**

**📌 해설:**
- AES-256: 키 256비트, 블록 128비트, 14라운드, SPN 구조
- AES-128: 10라운드
- AES-192: 12라운드
- AES-256: 14라운드

### 문제 1-3 (실무 적용)
```
공공기관에서 주민등록번호를 암호화하려고 한다.
다음 중 가장 적절한 암호화 방법은?

① SHA-256
② MD5
③ AES-256
④ RSA 공개키로만 암호화
```

**✅ 정답: ③**

**📌 해설:**
- 주민등록번호: 양방향 암호화 필요 (복호화 가능해야 함)
- SHA-256, MD5: 일방향 해시 (복호화 불가)
- AES-256: 양방향 대칭키 암호 (적합)
- RSA: 비대칭키 (가능하지만 속도 느림)

**국가기관 기준:**
```
일방향 (해시): 비밀번호, 바이오정보 → SHA-256 이상
양방향 (대칭키): 주민번호, 카드번호 → AES, SEED, ARIA
```

## 📝 기출 유형 2: 블록암호 운용 모드

### 문제 2-1 (2022년 기출 유사)
```
다음 중 블록암호 운용 모드에 대한 설명으로 틀린 것은?

① ECB 모드는 동일한 평문 블록이 동일한 암호문 블록을 생성한다.
② CBC 모드는 IV(초기화 벡터)를 사용한다.
③ CTR 모드는 병렬 처리가 가능하다.
④ GCM 모드는 기밀성만 제공하고 무결성은 제공하지 않는다.
```

**✅ 정답: ④**

**📌 해설:**
```
┌──────┬────────────┬──────────┬──────────┐
│ 모드 │    특징     │  IV 사용 │ 병렬처리 │
├──────┼────────────┼──────────┼──────────┤
│ ECB  │ 패턴 노출   │    X     │    O     │
│ CBC  │ 이전블록XOR │    O     │    X     │
│ CTR  │ 카운터암호화│    O     │    O     │
│ GCM  │ 기밀+무결성 │    O     │    O     │
└──────┴────────────┴──────────┴──────────┘
```

**GCM (Galois/Counter Mode):**
- AEAD (Authenticated Encryption with Associated Data)
- 기밀성 + 무결성 모두 제공 ✓
- TLS 1.3, IPSec에서 사용

### 문제 2-2 (운용 모드 선택)
```
다음 상황에 가장 적합한 블록암호 운용 모드는?

"웹 서버와 클라이언트 간 HTTPS 통신에서 데이터의 기밀성과
무결성을 모두 보장하면서 빠른 속도가 필요하다."

① ECB
② CBC
③ CTR
④ GCM
```

**✅ 정답: ④**

**📌 해설:**
- GCM: 기밀성 + 무결성, 병렬처리 가능 (빠름)
- TLS 1.3 표준 암호 스위트: TLS_AES_128_GCM_SHA256

## 📝 기출 유형 3: 패스워드 해싱

### 문제 3-1 (2023년 실기)
```
웹 애플리케이션에서 사용자 패스워드를 안전하게 저장하기 위한
방법으로 가장 적절하지 않은 것은?

① SHA-256으로 해싱하여 저장
② Salt를 추가하고 PBKDF2로 저장
③ bcrypt를 사용하여 저장
④ AES-256으로 암호화하여 저장
```

**✅ 정답: ④**

**📌 해설:**
```
비밀번호 저장 원칙:
1. 일방향 해시 사용 (복호화 불가능해야 함)
2. Salt 추가 (Rainbow Table 방어)
3. 반복 해싱 (Brute Force 방어)

❌ 틀린 방법:
- AES 암호화: 양방향 (복호화 가능) → 키 탈취시 위험
- MD5, SHA-1 단순 해시: Rainbow Table 공격 취약

✅ 올바른 방법:
- PBKDF2 (10,000회 이상 반복)
- bcrypt (Cost Factor 10~12)
- scrypt (메모리 하드)
- Argon2 (최신, 권장)
```

---

### 문제 3-2 (KISA 가이드라인)
```
KISA 패스워드 선택 및 이용 가이드에 따르면,
PBKDF2를 사용할 때 최소 반복 횟수는?

① 1,000회
② 5,000회
③ 10,000회
④ 100,000회
```

**✅ 정답: ③**

**📌 KISA 권장 기준:**
```python
# PBKDF2 예제
import hashlib

password = "user_password"
salt = os.urandom(16)  # 랜덤 Salt
iterations = 10000      # 최소 10,000회

key = hashlib.pbkdf2_hmac(
    'sha256',
    password.encode(),
    salt,
    iterations
)
```

```
② 송신자 개인키로 암호화 → 수신자 공개키로 복호화
③ 송신자 개인키로 서명 → 송신자 공개키로 검증
```

**📌 디지털 서명 프로세스:**

```
2. 서명을 송신자 공개키로 복호화
3. 두 해시 비교 → 검증

제공 기능:
✓ 인증 (Authentication)
✓ 무결성 (Integrity)
✓ 부인방지 (Non-repudiation)
```

## 📝 서술형 답안 작성 요령

### 문제: "대칭키 암호와 비대칭키 암호의 차이점을 설명하시오."

**✅ 모범 답안:**
```
1. 키 사용 방식
   - 대칭키: 암호화와 복호화에 동일한 키 사용
   - 비대칭키: 공개키(암호화)와 개인키(복호화) 사용

2. 속도
   - 대칭키: 빠름 (대용량 데이터 암호화에 적합)
   - 비대칭키: 느림 (키 교환, 디지털 서명에 사용)

3. 키 관리
   - 대칭키: 안전한 키 분배 어려움 (n(n-1)/2개 키 필요)
   - 비대칭키: 공개키 배포 용이 (2n개 키 필요)

4. 사용 예
   - 대칭키: AES (파일 암호화), SEED (전자상거래)
   - 비대칭키: RSA (SSL/TLS), ECC (모바일 인증)

5. 실무 적용
   - 하이브리드 방식: 비대칭키로 대칭키 전송 (전자봉투)
   - 예: HTTPS (RSA로 AES 키 교환 → AES로 데이터 암호화)
```

## 🎯 암호화 실기 핵심 암기 카드

### 카드 1: 국산 암호 (공공기관 필수)
```
SEED  : 128bit 키/블록, 16라운드, Feistel
ARIA  : 128/192/256bit 키, 128bit 블록, SPN
LEA   : 경량 암호, 소프트웨어 최적화
HIGHT : 64bit 블록, IoT/RFID용

공공기관: 국정원 검증필 암호만 사용 가능!
```

### 카드 2: 패스워드 저장
```
일방향 해시 + Salt + 반복
- PBKDF2: 10,000회 이상 (KISA 권장)
- bcrypt: Cost 10~12
- Argon2: 최신 표준

❌ 절대 금지: 평문 저장, 단순 해시, 양방향 암호화
```

### 카드 3: 개인정보 암호화 (법적 의무)
```
일방향 (SHA-256+):
- 비밀번호, 바이오정보

양방향 (AES/SEED/ARIA):
- 주민등록번호, 여권번호, 운전면허번호
- 외국인등록번호
- 신용카드번호, 계좌번호
```

### 카드 4: 블록암호 모드 선택
```
파일 암호화 → CBC (IV 사용, 순차)
디스크 암호화 → CTR (병렬, 빠름)
TLS/IPSec   → GCM (기밀성+무결성)
절대 사용 금지 → ECB (패턴 노출)
```

## 📊 그림으로 이해하기

### 대칭키 vs 비대칭키
```
[대칭키 암호화]
평문 ──[동일한 키]──> 암호문 ──[동일한 키]──> 평문
      AES 암호화              AES 복호화

장점: 빠름, 단순
단점: 키 분배 어려움


[비대칭키 암호화]
평문 ──[공개키]──> 암호문 ──[개인키]──> 평문
      RSA 암호화           RSA 복호화

장점: 키 분배 용이, 디지털 서명 가능
단점: 느림, 복잡
```

### 전자봉투 (Hybrid)
```
1. 대칭키 생성 (AES 키)
   ┌────────┐
   │ AES 키 │ (랜덤 생성)
   └────────┘

2. 데이터 암호화
   평문 ──[AES 키]──> 암호화된 데이터

3. 키 암호화
   AES 키 ──[수신자 공개키]──> 암호화된 AES 키

4. 전송
   { 암호화된 데이터 + 암호화된 AES 키 }

5. 수신자
   암호화된 AES 키 ──[개인키]──> AES 키
   암호화된 데이터 ──[AES 키]──> 평문

빠르고(AES) + 안전함(RSA)
```
