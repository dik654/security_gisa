# IPSec 및 VPN - 실기 필수 암기

## 🔴 IPSec 핵심 개념

### IPSec이란?
```
IP Security Protocol
네트워크 계층(Layer 3)에서 데이터를 암호화하고 인증하는 프로토콜

목적:
- 기밀성 (Confidentiality): 데이터 암호화
- 무결성 (Integrity): 데이터 변조 방지
- 인증 (Authentication): 송신자 신원 확인
- 재전송 방지 (Anti-Replay): 패킷 재사용 공격 방지
```

## 📝 기출 유형 1: IPSec 구성 요소 ★★★

### 필수 암기 표
```
┌──────────────┬─────────────────────────────────────┐
│   구성 요소   │              설명                   │
├──────────────┼─────────────────────────────────────┤
│ AH           │ Authentication Header               │
│              │ - 인증 + 무결성                     │
│              │ - 암호화 X                          │
│              │ - 프로토콜 번호: 51                 │
├──────────────┼─────────────────────────────────────┤
│ ESP          │ Encapsulating Security Payload     │
│              │ - 암호화 + 인증 + 무결성            │
│              │ - 가장 많이 사용 ★★★               │
│              │ - 프로토콜 번호: 50                 │
├──────────────┼─────────────────────────────────────┤
│ IKE          │ Internet Key Exchange               │
│              │ - 키 교환 프로토콜                  │
│              │ - Phase 1: ISAKMP SA 수립           │
│              │ - Phase 2: IPSec SA 수립            │
│              │ - 포트: UDP 500                     │
├──────────────┼─────────────────────────────────────┤
│ SA           │ Security Association                │
│              │ - 보안 연결 정보                    │
│              │ - SPI, 암호화 알고리즘, 키 등 포함  │
└──────────────┴─────────────────────────────────────┘
```

### 문제 1-1 (2023년 실기)
```
IPSec의 AH와 ESP의 차이점을 설명하시오.
```

**✅ 답안:**
```
AH (Authentication Header):
- 기능: 인증 + 무결성
- 암호화: 지원하지 않음 (데이터 평문 전송)
- 프로토콜 번호: 51
- NAT 통과: 불가능 (IP 헤더 보호로 인해)
- 사용 사례: 기밀성이 필요 없고 무결성만 필요한 경우

ESP (Encapsulating Security Payload):
- 기능: 암호화 + 인증 + 무결성
- 암호화: 지원 (데이터 암호화)
- 프로토콜 번호: 50
- NAT 통과: 가능 (NAT-T 사용 시)
- 사용 사례: 대부분의 IPSec VPN ★★★

실무에서는 ESP를 주로 사용함
```

## 📝 기출 유형 2: IPSec 동작 모드 ★★★

### Transport Mode vs Tunnel Mode
```
┌──────────────┬────────────────┬────────────────────┐
│    구분      │ Transport Mode │   Tunnel Mode      │
├──────────────┼────────────────┼────────────────────┤
│ 암호화 범위  │ 페이로드만     │ 전체 IP 패킷       │
│ IP 헤더 변경 │ 원본 유지      │ 새로운 IP 헤더 추가│
│ 사용 환경    │ End-to-End     │ Gateway-to-Gateway │
│ 오버헤드     │ 작음           │ 큼 (IP 헤더 추가)  │
│ 사용 예      │ 호스트 간 통신 │ Site-to-Site VPN ★│
└──────────────┴────────────────┴────────────────────┘
```

### 문제 2-1 (2022년 실기)
```
IPSec의 Transport Mode와 Tunnel Mode의 차이를
패킷 구조와 함께 설명하시오.
```

**✅ 답안:**
```
[Transport Mode]
원본 패킷:
[ IP 헤더 | TCP 헤더 | 데이터 ]

IPSec 적용 (ESP):
[ 원본 IP 헤더 | ESP 헤더 | TCP 헤더 | 데이터 | ESP Trailer | ESP Auth ]
                └───────────────────────────┘
                      암호화 구간

특징:
- 원본 IP 헤더 유지 (출발지/목적지 IP 그대로)
- 페이로드만 암호화
- End-to-End 통신 (호스트 간)
- 오버헤드 작음


[Tunnel Mode]
원본 패킷:
[ IP 헤더 | TCP 헤더 | 데이터 ]

IPSec 적용 (ESP):
[ 새 IP 헤더 | ESP 헤더 | 원본 IP 헤더 | TCP 헤더 | 데이터 | ESP Trailer | ESP Auth ]
               └──────────────────────────────────────────────┘
                            암호화 구간

특징:
- 전체 원본 패킷 암호화
- 새로운 IP 헤더 추가 (VPN 게이트웨이 주소)
- Gateway-to-Gateway (Site-to-Site VPN) ★
- 오버헤드 큼 (IP 헤더 중복)
- 내부 네트워크 구조 숨김

사용 사례:
- Transport: 본사-지사 간 서버 직접 통신
- Tunnel: 본사-지사 간 전체 네트워크 연결 (VPN) ★★★
```

## 📝 기출 유형 3: IKE (Internet Key Exchange) ★★

### IKE Phase
```
┌─────────┬──────────────────────────────────────┐
│  Phase  │              설명                    │
├─────────┼──────────────────────────────────────┤
│ Phase 1 │ ISAKMP SA (IKE SA) 수립              │
│         │ - 양방향 인증                        │
│         │ - 키 교환 (Diffie-Hellman)           │
│         │ - 암호화 알고리즘 협상               │
│         │ - Main Mode (6개 메시지) ★          │
│         │ - Aggressive Mode (3개 메시지)      │
├─────────┼──────────────────────────────────────┤
│ Phase 2 │ IPSec SA 수립                        │
│         │ - 실제 데이터 암호화용 SA            │
│         │ - Quick Mode (3개 메시지)            │
│         │ - Phase 1의 보호 하에 수행           │
└─────────┴──────────────────────────────────────┘
```

### 문제 3-1 (2023년 실기)
```
IKE Phase 1과 Phase 2의 역할을 각각 설명하시오.
```

**✅ 답안:**
```
Phase 1 (ISAKMP SA 수립):
목적: 안전한 관리 채널 생성
역할:
1. 양방향 인증 (Mutual Authentication)
   - Pre-Shared Key (PSK) 또는 인증서 사용
2. 키 교환
   - Diffie-Hellman 알고리즘으로 세션키 생성
3. 암호화 알고리즘 협상
   - 암호화: AES, 3DES
   - 해시: SHA-256, SHA-1
   - DH 그룹: Group 2, 5, 14 등
4. SA 생성: ISAKMP SA (양방향 1개)

모드:
- Main Mode: 6개 메시지, 신원 보호 (기본값)
- Aggressive Mode: 3개 메시지, 빠르지만 신원 노출

Phase 2 (IPSec SA 수립):
목적: 실제 데이터 전송용 SA 생성
역할:
1. IPSec 프로토콜 협상 (AH 또는 ESP)
2. 암호화 키 생성 (Phase 1과 다른 키)
3. PFS (Perfect Forward Secrecy) 옵션
4. SA 생성: IPSec SA (단방향 2개, 총 양방향 4개)

모드:
- Quick Mode: 3개 메시지, Phase 1 보호 하에 수행

관계:
Phase 1은 Phase 2를 보호하기 위한 터널
Phase 2는 실제 사용자 데이터를 암호화
```

## 📝 기출 유형 4: VPN 종류 ★★

### VPN 유형 비교
```
┌──────────────┬────────────────────────────────────┐
│   VPN 종류    │              설명                  │
├──────────────┼────────────────────────────────────┤
│ IPSec VPN    │ - Layer 3 (네트워크 계층)          │
│              │ - Site-to-Site, Remote Access      │
│              │ - 프로토콜: AH(51), ESP(50)        │
│              │ - 포트: UDP 500 (IKE)              │
├──────────────┼────────────────────────────────────┤
│ SSL/TLS VPN  │ - Layer 7 (응용 계층)              │
│              │ - 웹 브라우저 기반 (에이전트 불필요)│
│              │ - 포트: TCP 443 (HTTPS)            │
│              │ - 방화벽 통과 용이 ★               │
├──────────────┼────────────────────────────────────┤
│ PPTP VPN     │ - Point-to-Point Tunneling         │
│              │ - 포트: TCP 1723                   │
│              │ - 보안 취약 (사용 권장 안 함) ❌   │
├──────────────┼────────────────────────────────────┤
│ L2TP VPN     │ - Layer 2 Tunneling Protocol       │
│              │ - IPSec과 함께 사용 (L2TP/IPSec)  │
│              │ - 포트: UDP 1701                   │
└──────────────┴────────────────────────────────────┘
```

### 문제 4-1 (2022년 실기)
```
IPSec VPN과 SSL VPN의 차이점을 설명하고,
각각의 사용 사례를 쓰시오.
```

**✅ 답안:**
```
IPSec VPN:
계층: Layer 3 (네트워크 계층)
프로토콜: ESP(50), AH(51), IKE(UDP 500)
클라이언트: VPN 클라이언트 소프트웨어 필요
암호화: 모든 IP 트래픽
장점:
- 강력한 보안
- 모든 애플리케이션 지원
단점:
- 클라이언트 설치 필요
- NAT 통과 어려움 (NAT-T 필요)
- 방화벽 설정 복잡

사용 사례:
- Site-to-Site VPN (본사-지사 연결) ★
- Remote Access VPN (재택근무)
- 모든 네트워크 트래픽 보호 필요 시


SSL/TLS VPN:
계층: Layer 7 (응용 계층)
프로토콜: HTTPS (TCP 443)
클라이언트: 웹 브라우저만 있으면 됨 (에이전트 불필요)
암호화: 특정 애플리케이션 트래픽만
장점:
- 클라이언트 설치 불필요
- 방화벽/NAT 통과 용이 (HTTPS 포트 사용)
- 웹 기반 간편 접속
단점:
- IPSec보다 성능 낮음
- 특정 애플리케이션만 지원

사용 사례:
- 외부 사용자 웹메일/그룹웨어 접속 ★
- 협력업체 제한적 시스템 접근
- BYOD (개인 기기로 업무 시스템 접속)


비교 정리:
┌─────────────┬─────────────┬──────────────┐
│    항목     │  IPSec VPN  │  SSL VPN     │
├─────────────┼─────────────┼──────────────┤
│ OSI 계층    │  Layer 3    │  Layer 7     │
│ 포트        │  50,51,500  │  443         │
│ 클라이언트  │  필요       │  불필요      │
│ NAT 통과    │  어려움     │  쉬움 ★     │
│ 사용 환경   │ Site-to-Site│ Remote Access│
└─────────────┴─────────────┴──────────────┘
```

## 🎯 IPSec/VPN 핵심 암기 카드

### 카드 1: IPSec 프로토콜 (최빈출!)
```
AH (51)  : 인증 + 무결성, 암호화 X
ESP (50) : 암호화 + 인증 + 무결성 ★★★
IKE (500): 키 교환 (Phase 1 + Phase 2)
```

### 카드 2: IPSec 모드
```
Transport Mode:
- 페이로드만 암호화
- 원본 IP 헤더 유지
- End-to-End 통신

Tunnel Mode: ★★★
- 전체 패킷 암호화
- 새 IP 헤더 추가
- Gateway-to-Gateway (Site-to-Site VPN)
```

### 카드 3: IKE Phase
```
Phase 1 (ISAKMP SA):
- 관리 채널 수립
- 양방향 인증
- Main Mode (6 메시지) / Aggressive Mode (3 메시지)

Phase 2 (IPSec SA):
- 데이터 암호화용 SA
- Quick Mode (3 메시지)
- Phase 1 보호 하에 수행
```

### 카드 4: VPN 포트
```
IPSec: ESP(50), AH(51), IKE(UDP 500)
SSL VPN: TCP 443
PPTP: TCP 1723 (보안 취약)
L2TP: UDP 1701
```

## 📝 서술형: IPSec VPN 구축 시나리오

### 종합 문제 1 (2023년 실기 유사)
```
본사(192.168.1.0/24)와 지사(192.168.2.0/24) 간
IPSec VPN을 구축하려고 한다.

1) 사용해야 할 IPSec 모드는?
2) 사용해야 할 IPSec 프로토콜은? (AH/ESP 중 선택)
3) IKE Phase 1과 Phase 2의 역할은?
4) 방화벽에서 허용해야 할 포트는?
```

**✅ 답안:**
```
1) IPSec 모드
   Tunnel Mode ★
   이유: Site-to-Site VPN이므로 게이트웨이 간 연결
        전체 패킷 암호화로 내부 네트워크 구조 숨김

2) IPSec 프로토콜
   ESP (Encapsulating Security Payload)
   이유: 암호화 + 인증 + 무결성 모두 제공
        AH는 암호화 미지원으로 부적합

3) IKE Phase 역할
   Phase 1:
   - 본사-지사 VPN 게이트웨이 간 상호 인증
   - 키 교환 (Diffie-Hellman)
   - 암호화 알고리즘 협상 (AES-256, SHA-256 등)
   - ISAKMP SA 수립 (관리 채널)

   Phase 2:
   - 실제 데이터 암호화용 IPSec SA 생성
   - 192.168.1.0/24 ↔ 192.168.2.0/24 트래픽 보호
   - Quick Mode로 빠른 SA 수립

4) 방화벽 허용 포트
   인바운드/아웃바운드 모두 허용:
   - UDP 500 (IKE)
   - Protocol 50 (ESP)
   - UDP 4500 (NAT-T, NAT 환경인 경우)

   방화벽 룰 예시:
   allow protocol esp any any
   allow udp any any port 500
```

### 종합 문제 2 (VPN 선택 문제)
```
다음 요구사항에 적합한 VPN 종류를 선택하고 이유를 설명하시오.

시나리오 1:
재택근무 직원이 개인 노트북으로 회사 웹메일과
그룹웨어에만 접속해야 함. 클라이언트 설치는 불가능.

시나리오 2:
본사와 지사 간 모든 네트워크 트래픽(파일 공유, DB 접속,
내부 시스템 등)을 암호화하여 전송해야 함.
```

**✅ 답안:**
```
시나리오 1: SSL/TLS VPN

선택 이유:
1. 클라이언트 설치 불필요
   - 웹 브라우저만으로 접속 가능
   - 개인 PC에 소프트웨어 설치 권한 불필요

2. 특정 애플리케이션 접근
   - 웹메일, 그룹웨어 등 웹 기반 서비스 접속
   - 전체 네트워크 접근 불필요

3. 방화벽 통과 용이
   - HTTPS(443) 포트 사용
   - 대부분의 방화벽에서 허용됨

4. 보안
   - TLS 1.2/1.3으로 암호화
   - 사용자 인증 (ID/PW + OTP)

구성 예시:
직원 PC → HTTPS(443) → SSL VPN 게이트웨이 → 웹메일/그룹웨어


시나리오 2: IPSec VPN (Tunnel Mode)

선택 이유:
1. 전체 네트워크 연결
   - Site-to-Site VPN
   - 모든 IP 트래픽 암호화 (Layer 3)

2. 투명한 연결
   - 사용자는 지사에서 본사 시스템을 로컬처럼 사용
   - 애플리케이션 수정 불필요

3. 강력한 보안
   - ESP로 암호화 + 인증 + 무결성
   - AES-256, SHA-256 등 강력한 알고리즘

4. 상시 연결
   - Always-on VPN
   - 게이트웨이 간 자동 연결 유지

구성 예시:
본사 네트워크 ↔ VPN GW ↔ [인터넷] ↔ VPN GW ↔ 지사 네트워크
            (Tunnel Mode ESP)


비교:
┌──────────────┬─────────────┬──────────────┐
│   요구사항   │  시나리오1  │  시나리오2   │
├──────────────┼─────────────┼──────────────┤
```

## 📊 그림으로 이해하기

### IPSec Tunnel Mode 패킷 구조
```
[원본 패킷]
┌─────────────┬─────────────┬──────────┐
│  IP 헤더    │  TCP 헤더   │  데이터  │
│ (192.168.1.1│             │          │
│→192.168.2.1)│             │          │
└─────────────┴─────────────┴──────────┘

[IPSec Tunnel Mode 적용]
┌──────────────┬────────────┬─────────────┬─────────────┬──────────┬────────────┬─────────┐
│  새 IP 헤더  │ ESP 헤더   │  원본 IP    │  TCP 헤더   │  데이터  │ESP Trailer │ESP Auth │
│ (VPN GW 주소)│            │   헤더      │             │          │            │         │
│  (공인IP)    │            │(내부 IP)    │             │          │            │         │
└──────────────┴────────────┴─────────────┴─────────────┴──────────┴────────────┴─────────┘
                              └──────────────────────────────────────────┘
                                          암호화 구간
                              └──────────────────────────────────────────────────┘
                                              인증 구간

특징:
- 새 IP 헤더: VPN 게이트웨이 간 주소
- 원본 IP 헤더 암호화 → 내부 네트워크 구조 숨김
- ESP Trailer: 패딩, 프로토콜 정보
- ESP Auth: 무결성 검증 (HMAC)
```

### Site-to-Site VPN 구성도
```
본사 네트워크                                   지사 네트워크
┌──────────────────┐                       ┌──────────────────┐
│ 192.168.1.0/24   │                       │ 192.168.2.0/24   │
│                  │                       │                  │
│ ┌─────┐ ┌─────┐ │                       │ ┌─────┐ ┌─────┐ │
│ │ PC1 │ │ PC2 │ │                       │ │ PC3 │ │ PC4 │ │
│ └─────┘ └─────┘ │                       │ └─────┘ └─────┘ │
│        │         │                       │        │         │
│     ┌──┴───┐    │                       │     ┌──┴───┐    │
│     │Switch│    │                       │     │Switch│    │
│     └──┬───┘    │                       │     └──┬───┘    │
│        │         │                       │        │         │
│   ┌────┴─────┐  │                       │   ┌────┴─────┐  │
│   │ VPN GW   │  │                       │   │ VPN GW   │  │
│   │ (본사)   │  │                       │   │ (지사)   │  │
└───┴────┬─────┴──┘                       └───┴────┬─────┴──┘
         │                                          │
         │ 공인 IP: 1.1.1.1                        │ 공인 IP: 2.2.2.2
         │                                          │
         └──────────────┐    인터넷    ┌───────────┘
                        │              │
                        └──────────────┘
                    IPSec Tunnel Mode ESP

전송 예시:
PC1(192.168.1.10) → PC3(192.168.2.10) 통신

1. PC1이 패킷 전송: 192.168.1.10 → 192.168.2.10
2. 본사 VPN GW가 패킷 캡처
3. IPSec Tunnel Mode로 캡슐화
   - 새 IP 헤더: 1.1.1.1 → 2.2.2.2
   - 원본 패킷 암호화
4. 인터넷으로 전송
5. 지사 VPN GW가 패킷 수신 및 복호화
6. PC3으로 전달

PC1과 PC3은 암호화 과정을 알지 못함 (투명한 암호화)
```

## 💡 실기 답안 작성 팁

### Tip 1: 모드와 프로토콜 구별
```
✅ Tunnel Mode ESP
✅ Transport Mode AH

❌ ESP Tunnel (순서 바뀜)
❌ ESP만 작성 (모드 누락)
```

### Tip 2: 포트 vs 프로토콜 번호
```
IKE → UDP 포트 500
ESP → 프로토콜 번호 50 (포트 X)
AH  → 프로토콜 번호 51 (포트 X)

✅ "ESP 프로토콜 번호 50"
❌ "ESP 포트 50" (틀림!)
```

### Tip 3: Phase 구별
```
Phase 1: ISAKMP SA (관리용)
Phase 2: IPSec SA (데이터용)

✅ "Phase 1에서 인증 및 키 교환"
✅ "Phase 2에서 IPSec SA 생성"
```

### Tip 4: VPN 선택 근거 명시
```
문제: "적합한 VPN은?"

✅ SSL VPN
   이유: 웹 기반 접속, 클라이언트 불필요

❌ SSL VPN (이유 없이 답만 작성)
```
