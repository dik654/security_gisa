# 네트워크 보안 추가 기출 - 필수 암기

## 🔴 NAC 호스트 방식 vs 네트워크 방식 ★★★

### NAC (Network Access Control) 정의
```
네트워크 접근 제어
- 네트워크에 접속하는 단말의 보안 상태를 검사
- 보안 정책 준수 여부 확인 후 접근 허용/차단
```

### 문제 (2024년 기출)
```
NAC의 호스트 방식과 네트워크 방식을 무결성, 가용성 측면에서
설명한 것으로 올바른 것은?
```

### ✅ 정답
```
┌──────────┬────────────────────┬────────────────────┐
│  구분    │   호스트 방식       │  네트워크 방식     │
│          │ (Agent 방식)       │ (Agentless 방식)  │
├──────────┼────────────────────┼────────────────────┤
│ 무결성   │   높음 ✓           │   낮음             │
│(Integrity│ - 에이전트가 직접  │ - 네트워크 레벨    │
│          │   단말 검사        │   간접 검사        │
│          │ - 상세한 검사 가능 │ - 제한적 검사      │
├──────────┼────────────────────┼────────────────────┤
│ 가용성   │   낮음             │   높음 ✓           │
│(Availabi │ - 에이전트 설치    │ - 에이전트 불필요  │
│ lity)    │   필요             │ - 즉시 적용 가능   │
│          │ - 호환성 문제 가능 │ - 관리 용이        │
└──────────┴────────────────────┴────────────────────┘

요약:
호스트 방식 (Agent): 무결성 높음, 가용성 낮음
네트워크 방식 (Agentless): 무결성 낮음, 가용성 높음
```

### 상세 비교
```
[호스트 방식 (Agent-based)]
장점:
+ 무결성 높음: 단말 내부까지 상세 검사
+ 정확한 보안 상태 확인 (백신, 패치, 방화벽 등)
+ 강제 조치 가능 (격리, 패치 강제 설치)

단점:
- 가용성 낮음: 모든 단말에 에이전트 설치 필요
- 관리 부담: 에이전트 업데이트 관리
- 호환성 문제: 다양한 OS 지원 어려움

[네트워크 방식 (Agentless)]
장점:
+ 가용성 높음: 에이전트 설치 불필요
+ 즉시 적용: 스위치/라우터에 설정만 하면 됨
+ 관리 용이: 중앙 집중 관리

단점:
- 무결성 낮음: 네트워크 레벨 검사만 가능
- 제한적 검사: MAC 주소, IP 등 기본 정보만
- 우회 가능성: 네트워크 장비 우회 시 탐지 어려움
```

## 🔴 IPSEC 구성요소 ★★★

### 문제 (2024년 기출)
```
IPSEC의 구성요소가 아닌 것은?

ㄱ. AH (Authentication Header)
ㄴ. ESP (Encapsulating Security Payload)
ㄷ. IKE (Internet Key Exchange)
ㄹ. SSL (Secure Sockets Layer)
```

### ✅ 정답
```
ㄹ. SSL (Secure Sockets Layer)

이유:
SSL은 IPSEC 구성요소가 아니라 별도의 암호화 프로토콜
(Layer 7 응용 계층, HTTPS에 사용)

IPSEC 구성요소:
1. AH (프로토콜 51) - 인증 + 무결성
2. ESP (프로토콜 50) - 암호화 + 인증 + 무결성
3. IKE (UDP 500) - 키 교환
4. SA (Security Association) - 보안 연결 정보
```

## 🔴 SSL Handshake 과정 ★★★

### 문제 (2024년 기출)
```
SSL Handshaking 과정으로 올바른 것은?
```

### ✅ 정답 (SSL/TLS Handshake 4단계)
```
[1단계: Client Hello]
   클라이언트 → 서버
   - 지원하는 SSL/TLS 버전
   - 지원하는 암호화 알고리즘 (Cipher Suite)
   - 랜덤 데이터 (Client Random)

[2단계: Server Hello + Certificate]
   서버 → 클라이언트
   - 선택한 SSL/TLS 버전
   - 선택한 암호화 알고리즘
   - 랜덤 데이터 (Server Random)
   - 서버 인증서 (공개키 포함)
   - Server Hello Done

[3단계: Key Exchange]
   클라이언트 → 서버
   - Pre-Master Secret 생성 (랜덤 값)
   - 서버 공개키로 암호화하여 전송
   - Change Cipher Spec (암호화 시작 알림)
   - Finished (핸드셰이크 완료 메시지, 암호화됨)

   양측에서 세션키 생성:
   Session Key = f(Client Random, Server Random, Pre-Master Secret)

[4단계: Finished]
   서버 → 클라이언트
   - Change Cipher Spec
   - Finished (암호화됨)

[통신 시작]
   양측이 Session Key로 데이터 암호화/복호화
```

### 그림으로 이해
```
클라이언트                         서버
    │                               │
    │  1. Client Hello              │
    │ ─────────────────────────────>│
    │  (TLS 버전, Cipher Suite)    │
    │                               │
    │  2. Server Hello              │
    │ <─────────────────────────────│
    │  (선택된 Cipher, 인증서)     │
    │                               │
    │  3. Pre-Master Secret         │
    │ ─────────────────────────────>│
    │  (서버 공개키로 암호화)       │
    │                               │
    │  양측에서 Session Key 생성    │
    │                               │
    │  4. Change Cipher Spec        │
    │ <────────────────────────────>│
    │     Finished                  │
    │                               │
    │  [암호화 통신 시작]           │
    │ <────────────────────────────>│
```

## 🔴 SDN (Software-Defined Networking) ★★

### 문제 (2024년 기출)
```
SDN은 무엇인가?
```

### ✅ 정답
```
SDN (Software-Defined Networking)
= 소프트웨어 정의 네트워킹

정의:
네트워크의 제어 평면(Control Plane)과 데이터 평면(Data Plane)을
분리하여, 소프트웨어로 네트워크를 중앙 집중식으로 제어하는 기술

핵심 개념:
1. Control Plane 분리
   - SDN Controller가 중앙에서 네트워크 제어
   - 정책 및 라우팅 결정

2. Data Plane
   - 스위치/라우터는 데이터 전달만 담당
   - Controller의 지시에 따라 동작

3. OpenFlow 프로토콜
   - Controller와 스위치 간 통신 프로토콜
```

### SDN 구조
```
┌─────────────────────────────────────┐
│   Application Layer (응용 계층)    │
│   - 방화벽, 로드밸런서, 보안정책   │
└─────────────────────────────────────┘
              ↕ (Northbound API)
┌─────────────────────────────────────┐
│   Control Plane (제어 평면)         │
│   - SDN Controller                  │
│   - 중앙 집중 제어                  │
└─────────────────────────────────────┘
              ↕ (Southbound API - OpenFlow)
┌─────────────────────────────────────┐
│   Data Plane (데이터 평면)          │
│   - 스위치, 라우터                  │
│   - 패킷 전달만 담당                │
└─────────────────────────────────────┘

기존 네트워크:
각 장비가 독립적으로 제어 + 데이터 처리

SDN:
중앙 Controller가 제어, 장비는 데이터 전달만
```

### 장점
```
1. 중앙 집중 관리
   - 전체 네트워크를 하나의 지점에서 제어
   - 정책 변경 용이

2. 프로그래밍 가능
   - 소프트웨어로 네트워크 동작 정의
   - 자동화 가능

3. 유연성
   - 네트워크 구성 변경 신속
   - 가상화 친화적
```

## 🔴 NAT 종류 ★★

### 문제 (2024년 기출)
```
NAT 종류는?
```

### ✅ 정답
```
1. Static NAT (정적 NAT)
   - 1:1 매핑 (사설 IP 1개 ↔ 공인 IP 1개)
   - 예: 192.168.1.10 → 1.1.1.10 (고정)

2. Dynamic NAT (동적 NAT)
   - 1:1 매핑이지만 동적으로 할당
   - 공인 IP 풀에서 필요할 때 할당

3. PAT (Port Address Translation)
   = NAPT (Network Address and Port Translation)
   = Overloading NAT
   - N:1 매핑 (여러 사설 IP → 1개 공인 IP)
   - 포트 번호로 구분
   - 가장 많이 사용 ★★★

4. Overlapping NAT
   - 양쪽 네트워크에 중복 IP 존재 시 사용
```

### PAT 동작 예시
```
[내부 네트워크]                    [인터넷]
192.168.1.10:5000  ──┐
192.168.1.20:6000  ──┼─> NAT 라우터 ─> 1.1.1.1:10001 → 웹서버
192.168.1.30:7000  ──┘                 1.1.1.1:10002 → 웹서버
                                       1.1.1.1:10003 → 웹서버

NAT 테이블:
┌─────────────────┬─────────────────┐
│  내부 (사설 IP) │ 외부 (공인 IP)  │
├─────────────────┼─────────────────┤
│192.168.1.10:5000│ 1.1.1.1:10001   │
│192.168.1.20:6000│ 1.1.1.1:10002   │
│192.168.1.30:7000│ 1.1.1.1:10003   │
└─────────────────┴─────────────────┘

하나의 공인 IP로 여러 내부 사용자가 인터넷 사용 가능!
```

## 🔴 S-HTTP ★

### 문제 (2024년 기출)
```
S-HTTP는?
```

### ✅ 정답
```
S-HTTP (Secure HTTP)
= 보안 HTTP

정의:
HTTP 메시지 자체를 암호화하는 프로토콜
(HTTPS와 다름!)

S-HTTP vs HTTPS:
┌──────────┬────────────────┬────────────────┐
│   구분   │    S-HTTP      │     HTTPS      │
├──────────┼────────────────┼────────────────┤
│ 암호화   │ 메시지 암호화  │ 전송 채널 암호화│
│ 레벨     │                │                │
├──────────┼────────────────┼────────────────┤
│ 프로토콜 │ HTTP 확장      │ HTTP + SSL/TLS │
├──────────┼────────────────┼────────────────┤
│ 사용     │ 거의 사용 안함 │ 표준 ★★★      │
├──────────┼────────────────┼────────────────┤
│ 포트     │ 80             │ 443            │
└──────────┴────────────────┴────────────────┘

현재:
S-HTTP는 사실상 폐기, HTTPS가 표준
```

## 🔴 DNS MX 레코드 ★★

### 문제 (2024년 기출)
```
DNS 레코드 중 메일 서버를 지정하는 것은?
```

### ✅ 정답
```
MX (Mail eXchange) 레코드
```

### DNS 레코드 종류
```
┌────────┬──────────────────────────────┐
│ 레코드 │          설명                │
├────────┼──────────────────────────────┤
│   A    │ 도메인 → IPv4 주소           │
│        │ example.com → 1.2.3.4        │
├────────┼──────────────────────────────┤
│  AAAA  │ 도메인 → IPv6 주소           │
├────────┼──────────────────────────────┤
│  CNAME │ 도메인 별칭 (Alias)          │
│        │ www.example.com → example.com│
├────────┼──────────────────────────────┤
│   MX   │ 메일 서버 지정 ★★           │
│        │ example.com → mail.example.com│
│        │ 우선순위 값 포함 (낮을수록 우선)│
├────────┼──────────────────────────────┤
│   NS   │ 네임 서버 지정               │
│        │ DNS 권한 있는 서버           │
├────────┼──────────────────────────────┤
│  PTR   │ IP → 도메인 (역방향 조회)   │
├────────┼──────────────────────────────┤
│  TXT   │ 텍스트 정보 (SPF, DKIM 등)  │
└────────┴──────────────────────────────┘
```

### MX 레코드 예시
```
example.com.  IN  MX  10  mail1.example.com.
example.com.  IN  MX  20  mail2.example.com.

설명:
- 우선순위 10: mail1.example.com (주 메일 서버)
- 우선순위 20: mail2.example.com (백업 메일 서버)
- 숫자가 낮을수록 우선순위 높음
- mail1 장애 시 mail2로 자동 전환
```

## 🔴 ICMP 타입 번호 ★★

### 문제 (2024년 기출)
```
ICMP 타입 번호?
```

### ✅ 정답 (주요 ICMP 타입)
```
┌──────┬────────────────────────────────┐
│ Type │          설명                  │
├──────┼────────────────────────────────┤
│  0   │ Echo Reply (Ping 응답) ★      │
├──────┼────────────────────────────────┤
│  3   │ Destination Unreachable ★★    │
│      │ (목적지 도달 불가)            │
│      │ - Code 0: Network Unreachable  │
│      │ - Code 1: Host Unreachable     │
│      │ - Code 3: Port Unreachable     │
├──────┼────────────────────────────────┤
│  5   │ Redirect (경로 재지정)         │
├──────┼────────────────────────────────┤
│  8   │ Echo Request (Ping 요청) ★★★  │
├──────┼────────────────────────────────┤
│  11  │ Time Exceeded ★                │
│      │ (시간 초과, TTL=0)            │
│      │ traceroute에 사용             │
└──────┴────────────────────────────────┘

가장 중요:
Type 8 (Echo Request) + Type 0 (Echo Reply) = Ping
```

### Ping 동작
```
PC A                           PC B
  │                             │
  │ ICMP Type 8 (Echo Request) │
  │ ──────────────────────────>│
  │                             │
  │ ICMP Type 0 (Echo Reply)   │
  │ <──────────────────────────│
  │                             │
 연결 정상!
```

## 🎯 네트워크 보안 핵심 암기 카드

### 카드 1: NAC 비교 (최빈출!)
```
호스트 방식 (Agent):
- 무결성: 높음
- 가용성: 낮음

네트워크 방식 (Agentless):
- 무결성: 낮음
- 가용성: 높음
```

### 카드 2: IPSEC 구성요소
```
○ AH (51) - 인증+무결성
○ ESP (50) - 암호화+인증+무결성
○ IKE (500) - 키 교환
○ SA - 보안 연결 정보

✗ SSL - IPSEC 아님!
```

### 카드 3: SSL Handshake 4단계
```
1. Client Hello
2. Server Hello + Certificate
3. Key Exchange (Pre-Master Secret)
4. Finished
→ 세션키로 암호화 통신 시작
```

### 카드 4: DNS 레코드
```
A: IPv4 주소
AAAA: IPv6 주소
CNAME: 별칭
MX: 메일 서버 ★
NS: 네임 서버
```

### 카드 5: ICMP 타입
```
Type 0: Echo Reply (Ping 응답)
Type 3: Unreachable (도달 불가)
Type 8: Echo Request (Ping 요청) ★
Type 11: Time Exceeded (TTL 초과)
```

