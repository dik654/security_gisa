## 1. 악성코드 유형

### 문제 1-1: 악성코드의 주요 유형 6가지를 설명하고, 각각의 특징과 예방 방법을 제시하시오 (15점) ★★★

#### ✅ 모범 답안:

**[악성코드 (Malware) 정의]**

```
Malware = Malicious + Software
악의적인 목적으로 제작된 소프트웨어

목적:
- 정보 탈취
- 시스템 파괴
- 금전 요구
- 좀비PC 확보
- 스파이 활동
```

**[1. 바이러스 (Virus)] ★★★**

**특징:**
```
정의:
정상 파일에 기생하여 자기 복제하는 악성코드
숙주 파일 필요 (단독 실행 불가)

동작:
1. 정상 파일(EXE, DOC 등)에 코드 삽입
2. 사용자가 감염 파일 실행
3. 바이러스 코드 먼저 실행
4. 다른 파일로 전파
5. 원래 프로그램 실행 (위장)

감염 대상:
- 실행 파일 (.exe, .com)
- 문서 파일 (.doc, .xls) - 매크로 바이러스
- 부트 섹터 - 부트 바이러스
- 스크립트 파일 (.vbs, .js)

전파 경로:
- USB 메모리
- 이메일 첨부파일
- 파일 공유
- 다운로드
```

**예시:**
```
CIH 바이러스 (1998):
- 매월 26일 발동
- BIOS 파괴
- 하드디스크 데이터 삭제

매크로 바이러스 (Melissa, 1999):
- Word 문서 감염
- 자동으로 이메일 전송
- 50명에게 전파
```

**예방:**
```
1. 백신 설치 및 실시간 감시
2. 출처 불명 파일 실행 금지
3. 매크로 비활성화
   - Word: 파일 → 옵션 → 보안 센터 → 매크로 설정
4. USB 자동실행 비활성화
   - 레지스트리: HKLM\Software\Microsoft\Windows\CurrentVersion\Policies\Explorer
   - NoDriveTypeAutoRun = 0xFF
5. 정기 백업
```

**[2. 웜 (Worm)] ★★★**

**특징:**
```
정의:
독립적으로 실행되며 스스로 전파하는 악성코드
숙주 파일 불필요 (단독 실행 가능)

바이러스 vs 웜:
- 바이러스: 숙주 필요, 사용자 실행 필요
- 웜: 독립 실행, 자동 전파

동작:
1. 취약점 스캔
2. 네트워크를 통해 전파
3. 자동 실행
4. 추가 전파

전파 방식:
- 네트워크 취약점 악용
- 이메일 자동 발송
- P2P 네트워크
- 공유 폴더

피해:
- 네트워크 대역폭 소진
- 시스템 리소스 고갈
- DDoS 공격 수행
```

**대표 사례:**
```
Code Red (2001):
- IIS 웹 서버 취약점
- 24시간 내 35만 대 감염
- 백악관 DDoS 공격

WannaCry (2017):
- SMB 취약점 (EternalBlue)
- 150개국 30만 대 감염
- 랜섬웨어 + 웜
- 피해액: 수십억 달러

Conficker (2008):
- MS08-067 취약점
- 1천만 대 이상 감염
- 봇넷 구축
```

**예방:**
```
1. 패치 관리 ★★★
   - 정기 보안 패치
   - Windows Update 활성화
   - 자동 업데이트 설정

2. 방화벽 설정
   - 불필요한 포트 차단
   - SMB 포트 차단 (445)
   - NetBIOS 차단 (137-139)

3. 네트워크 분리
   - VLAN 분리
   - 중요 시스템 격리

4. IDS/IPS 운영
   - 웜 전파 패턴 탐지
   - 자동 차단

5. 계정 관리
   - 강력한 패스워드
   - 관리자 계정 제한
```

**[3. 트로이목마 (Trojan Horse)] ★★★**

**특징:**
```
정의:
정상 프로그램으로 위장한 악성코드
자기 복제 기능 없음

특징:
- 유용한 프로그램으로 위장
- 사용자를 속여 설치 유도
- 백도어, 키로거 등 설치
- 스스로 전파 안 함

동작:
1. 정상 프로그램으로 가장
   (게임, 유틸리티, 크랙 등)
2. 사용자가 자발적으로 설치
3. 백그라운드에서 악성 행동
4. 원래 기능도 제공 (위장)

목적:
- 원격 제어 (RAT)
- 정보 탈취
- 다운로더 (추가 악성코드 다운)
- 백도어 설치
```

**대표 유형:**
```
RAT (Remote Access Trojan):
- 원격 제어
- 화면 캡처
- 키로거
- 파일 전송
- 예: NetBus, Back Orifice, DarkComet

뱅킹 트로이목마:
- 금융 정보 탈취
- 키로거
- 화면 오버레이
- 예: Zeus, SpyEye, Emotet

다운로더:
- 추가 악성코드 다운로드
- 모듈형 구조
- 업데이트 기능
```

**실제 사례:**
```
Zeus (2007~):
- 온라인 뱅킹 정보 탈취
- 전 세계 수백만 PC 감염
- 피해액: 1억 달러 이상

Emotet (2014~):
- 뱅킹 트로이목마로 시작
- 이후 다운로더로 진화
- 랜섬웨어 전파
- 2021년 국제 공조로 제거
```

**예방:**
```
1. 신뢰할 수 없는 소프트웨어 설치 금지
   - 공식 사이트에서만 다운로드
   - 크랙, 키젠 사용 금지

2. 백신 실시간 감시

3. 방화벽 아웃바운드 규칙
   - 허가되지 않은 프로그램 통신 차단

4. 애플리케이션 화이트리스트
   - 승인된 프로그램만 실행

5. 사용자 교육
   - 의심스러운 프로그램 주의
   - 출처 확인
```

**[4. 랜섬웨어 (Ransomware)] ★★★**

**특징:**
```
정의:
파일을 암호화하고 금전을 요구하는 악성코드

동작:
1. 시스템 감염
2. 파일 암호화 (AES, RSA)
3. 복호화 키 삭제
4. 몸값 요구 (비트코인)
5. 지불 시 복호화 키 제공 (보장 안 됨)

대상:
- 문서 (.doc, .pdf, .xls)
- 이미지 (.jpg, .png)
- 데이터베이스 (.db, .sql)
- 백업 파일
- 공유 폴더
```

**진화:**
```
1세대: 화면 잠금
- 간단한 해제 가능

2세대: 파일 암호화
- 강력한 암호화 (AES-256)
- 복호화 어려움

3세대: Double Extortion (이중 협박)
- 암호화 + 데이터 유출 위협
- "지불 안 하면 공개"
```

**대표 사례:**
```
WannaCry (2017):
- SMB 취약점 악용
- 전 세계 동시 감염
- 피해: 의료, 제조, 정부

REvil (2019~2021):
- RaaS (Ransomware as a Service)
- 대기업 타겟
- 수백만~수천만 달러 요구

Ryuk (2018~):
- 표적형 랜섬웨어
- 기업 네트워크 장악
- 백업 서버 먼저 공격
```

**예방:**
```
1. 백업 (3-2-1 규칙) ★★★
   - 3개 복사본
   - 2개 다른 매체
   - 1개 오프사이트
   - 오프라인 백업

2. 패치 관리

3. 매크로 비활성화
   - 이메일 첨부 주의

4. 네트워크 분리
   - 백업 서버 격리

5. EDR (Endpoint Detection and Response)
   - 행위 기반 탐지
   - 대량 파일 암호화 차단

6. 권한 관리
   - 최소 권한 원칙
   - 관리자 권한 제한

7. 교육
   - 피싱 메일 주의
   - 첨부파일 실행 전 확인
```

**대응:**
```
감염 시:
1. 네트워크 즉시 차단
2. 시스템 종료 (추가 암호화 방지)
3. 전문가 상담 (경찰, 보안업체)
4. 복호화 도구 확인
   - No More Ransom Project
5. 백업 복원

주의:
- 몸값 지불 권장 안 함
  - 복호화 보장 없음
  - 범죄 조직 자금 지원
  - 재공격 대상 가능
```

**[5. 스파이웨어 (Spyware)] ★★**

**특징:**
```
정의:
사용자 정보를 몰래 수집하는 악성코드

수집 정보:
- 웹 브라우징 기록
- 검색어
- 패스워드
- 신용카드 정보
- 개인 정보
- 위치 정보

종류:

키로거 (Keylogger):
- 키보드 입력 기록
- 패스워드, 계좌번호 탈취

애드웨어 (Adware):
- 강제 광고 표시
- 브라우저 하이재킹
- 홈페이지 변경

트래킹 쿠키:
- 사용자 추적
- 행동 패턴 수집
```

**동작:**
```
1. 무료 소프트웨어에 번들
2. 설치 시 동의 (숨김)
3. 백그라운드 실행
4. 정보 수집
5. 외부 서버 전송
```

**예방:**
```
1. 소프트웨어 설치 시 주의
   - 사용자 정의 설치 선택
   - 추가 프로그램 확인
   - 이용 약관 읽기

2. 안티스파이웨어 도구
   - Malwarebytes
   - Spybot Search & Destroy

3. 브라우저 보안
   - 광고 차단기
   - 쿠키 관리
   - 추적 방지

4. 정기 점검
   - 설치된 프로그램 검토
   - 시작 프로그램 확인
```

**[6. 루트킷 (Rootkit)] ★★★**

**특징:**
```
정의:
시스템 깊숙이 숨어 관리자 권한을 획득하고
자신의 존재를 숨기는 악성코드

목적:
- 지속적인 접근 유지
- 탐지 회피
- 다른 악성코드 은폐

동작 계층:

User-mode Rootkit:
- 응용 프로그램 레벨
- API 후킹
- DLL 인젝션

Kernel-mode Rootkit:
- 커널 레벨
- 시스템 호출 후킹
- 디바이스 드라이버
- 탐지/제거 매우 어려움

Bootkit:
- 부트로더 감염
- OS 로딩 전 실행
- 가장 위험

Firmware Rootkit:
- BIOS/UEFI 감염
- OS 재설치해도 유지
```

**은폐 기법:**
```
프로세스 숨김:
- 프로세스 목록에서 제거
- tasklist, ps 명령어 속임

파일 숨김:
- 파일 시스템 필터
- dir, ls 명령어 속임

네트워크 연결 숨김:
- netstat 결과 조작

레지스트리 숨김:
- 레지스트리 키 숨김
```

**대표 사례:**
```
Sony BMG Rootkit (2005):
- 음악 CD에 루트킷
- DRM 목적
- 사용자 동의 없이 설치
- 대규모 소송

Stuxnet (2010):
- 이란 핵시설 타겟
- 루트킷 + 웜
- 제로데이 취약점 4개
- 국가 지원 추정
```

**탐지:**
```
1. 루트킷 스캐너
   - GMER
   - RootkitRevealer
   - Kaspersky TDSSKiller

2. 시그니처 비교
   - 실행 중인 프로세스
   - 디스크의 파일 목록
   - 차이 발견 → 루트킷 의심

3. 메모리 분석
   - Volatility
   - 숨겨진 프로세스 탐지

4. 무결성 검사
   - 시스템 파일 해시 비교
   - Tripwire
```

**제거:**
```
Kernel-mode Rootkit:
- 일반 방법으로 제거 어려움
- 클린 OS 재설치 권장
- 데이터만 백업 (실행 파일 제외)

Bootkit:
- 부트 섹터 복구
- MBR 재작성
- 또는 클린 설치

Firmware Rootkit:
- BIOS/UEFI 업데이트
- 또는 하드웨어 교체
```

**예방:**
```
1. 최소 권한 운영
   - 관리자 권한 최소 사용

2. 보안 부팅 (Secure Boot)
   - UEFI Secure Boot 활성화
   - 서명된 코드만 실행

3. 드라이버 서명 확인
   - Windows: Driver Signature Enforcement

4. 정기 무결성 검사

5. 최신 패치 적용
```

**[종합 예방 대책]**

**기술적 통제:**
```
1. 백신 (안티바이러스)
   - 실시간 감시
   - 정기 스캔
   - 정의 파일 업데이트

2. 방화벽
   - 인바운드/아웃바운드 필터링

3. IDS/IPS
   - 악성코드 전파 패턴 탐지

4. EDR
   - 행위 기반 탐지
   - 자동 격리

5. 패치 관리
   - 정기 보안 업데이트

6. 백업
   - 3-2-1 규칙
   - 오프라인 백업
```

**관리적 통제:**
```
1. 보안 정책
   - USB 사용 제한
   - 소프트웨어 설치 제한
   - 이메일 첨부파일 정책

2. 접근 통제
   - 최소 권한 원칙
   - 권한 분리

3. 사용자 교육
   - 피싱 메일 인식
   - 안전한 다운로드
   - 의심스러운 파일 신고

4. 사고 대응 계획
   - 감염 시 절차
   - 격리 방법
   - 복구 계획
```

## 2. 랜섬웨어

### 문제 2-1: 랜섬웨어의 동작 원리를 단계별로 설명하고, 조직 차원의 랜섬웨어 대응 전략 5가지를 제시하시오 (15점) ★★★

#### ✅ 모범 답안:

**[랜섬웨어 동작 원리 - Kill Chain] ★★★**

**1단계: 초기 침투 (Initial Compromise)**

```
침투 경로:

피싱 이메일 (가장 흔함):
- 악성 첨부파일
  - 매크로 문서 (.doc, .xls)
  - 압축 파일 (.zip) 내 실행 파일
  - 스크립트 (.vbs, .js)
- 악성 링크
  - 다운로드 사이트로 유도

RDP 공격:
- 취약한 패스워드 brute force
- 포트 3389 공개된 서버
- 많은 기업 공격에 사용

취약점 악용:
- 패치되지 않은 시스템
- 예: WannaCry (EternalBlue)
- VPN 취약점

소프트웨어 공급망:
- 정상 소프트웨어 업데이트 위장
- 예: SolarWinds 공급망 공격

웹사이트 해킹:
- 워터링 홀 공격
- Drive-by Download
```

**2단계: 권한 상승 (Privilege Escalation)**

```
목표: 관리자 권한 획득

방법:
- OS 취약점 악용
- 패스워드 추출 (Mimikatz)
- 토큰 탈취
- UAC 우회
```

**3단계: 내부 이동 (Lateral Movement)**

```
목표: 네트워크 내 확산

동작:
- 네트워크 스캔
  - 활성 호스트 탐색
  - 공유 폴더 탐색
- 계정 탈취
  - 도메인 관리자 계정
  - 서비스 계정
- 추가 시스템 감염
  - SMB, WMI, PsExec 사용
  - 원격 실행

목표 우선순위:
1. 도메인 컨트롤러
2. 파일 서버
3. 백업 서버 ★★★
4. 데이터베이스 서버
```

**4단계: 데이터 수집 (Data Collection)**

```
최신 랜섬웨어(Double Extortion):

파일 탐색:
- 중요 파일 검색
  - 재무 정보
  - 고객 정보
  - 영업 기밀
  - 연구 개발 자료

데이터 유출:
- 외부 서버로 전송
- 암호화 전에 수행
- 협상 카드로 사용
  - "지불 안 하면 공개"
```

**5단계: 백업 파괴 (Backup Destruction)**

```
목표: 복구 불가능하게 만들기

대상:
- 백업 서버
- 스냅샷
- 클라우드 백업
- Volume Shadow Copy

방법:
```cmd
# Volume Shadow Copy 삭제
vssadmin delete shadows /all /quiet
wmic shadowcopy delete

# 백업 서비스 중지
net stop "Windows Backup"
net stop "SQL Server VSS Writer"

# 백업 파일 삭제
del /s /f /q *.bak
del /s /f /q *.backup
```
```

**6단계: 암호화 (Encryption)**

```
암호화 알고리즘:

대칭키 암호화 (파일):
- AES-256
- ChaCha20
- Salsa20

비대칭키 암호화 (대칭키):
- RSA-2048/4096
- 공개키로 대칭키 암호화
- 개인키는 공격자만 보유

암호화 과정:
1. 랜덤 대칭키 생성 (각 파일마다)
2. 파일을 대칭키로 암호화
3. 대칭키를 공격자 공개키로 암호화
4. 암호화된 키를 파일에 저장
5. 원본 대칭키 삭제

대상 파일:
- 문서: .doc, .docx, .pdf, .xls, .ppt
- 이미지: .jpg, .png, .raw
- 데이터베이스: .db, .sql, .mdb
- 압축: .zip, .rar
- 백업: .bak, .backup

제외 파일:
- 시스템 파일 (OS 작동 유지)
- 실행 파일 (일부)
- 랜섬노트
```

**7단계: 몸값 요구 (Ransom Demand)**

내용:

화면 변경:

- 로그인 화면 차단
- 모든 폴더에 README.txt 생성

금액:
- 개인: $300~$5,000
- 기업: $50,000~$수백만
- 대기업: $수천만

지불 방식:
- 비트코인
- 모네로 (익명성 높음)

협상:
- Tor 네트워크

```

**1. 백업 전략 (3-2-1-1 규칙) ★★★**

```
3-2-1-1 규칙:

3: 데이터 3개 복사본
- 원본 1개
- 백업 2개

2: 2개의 다른 매체
- 디스크
- 테이프
- 클라우드

1: 1개는 오프사이트
- 물리적으로 다른 위치
- 재해 대비

1: 1개는 오프라인 (Air-gap)
- 네트워크 연결 안 됨
- 랜섬웨어가 접근 불가 ★★★

구체적 방법:

오프라인 백업:
```bash

rsync -av /data/ /backup/

# 2. 백업 검증

# 3. 네트워크 연결 해제

# 4. 물리적 분리
# 백업 디스크 분리 보관
```

- 한 번 쓰면 수정/삭제 불가
- WORM (Write Once Read Many)
- 클라우드: AWS S3 Object Lock

백업 암호화:
- 백업 데이터 암호화
- 키 별도 보관

백업 테스트:
- 정기적 복원 테스트 (월 1회)
- 복구 시간 측정
- 절차 검증

보관 기간:
- 최소 30일
- 권장: 90일
- 랜섬웨어 잠복 기간 고려
```

## ✅ 핵심 요약

### 가장 자주 출제되는 Top 5 ★★★

1. **악성코드 6가지 유형**: 바이러스, 웜, 트로이목마, 랜섬웨어, 스파이웨어, 루트킷

1. **유형별 특징**: 각 악성코드의 차이점 명확히

3. **구체적 방법**: 명령어, 설정 포함
4. **우선순위**: 백업이 최우선 강조
5. **Kill Chain**: 단계별 설명
