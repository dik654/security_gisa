# 포렌식 분석 - 상세 개념

## 🔴 메모리 포렌식 ★★★

### 문제 (2024년 기출)
```
메모리 포렌식의 장점은?
```

### ✅ 정답
```
메모리 포렌식 (Memory Forensics)
= 휘발성 메모리(RAM) 분석

장점: ★★★

1. 휘발성 데이터 확보
   - 실행 중인 프로세스
   - 네트워크 연결 정보
   - 암호화되지 않은 데이터 ★★
   - 메모리 상의 평문 패스워드

2. 디스크에 없는 정보
   - 파일리스(Fileless) 악성코드 탐지 ★★★
   - 메모리에만 존재하는 악성코드
   - 프로세스 인젝션 탐지

3. 실시간 상태 분석
   - 현재 실행 중인 악성코드
   - 열린 파일/네트워크
   - 로그인 세션

4. 안티포렌식 대응
   - 삭제된 프로세스 복구
   - 루트킷 탐지
   - 숨겨진 프로세스 발견

분석 도구:
1. Volatility ★★★
   - 오픈소스
   - 메모리 덤프 분석
   - 플러그인 기반

2. Rekall
   - Volatility 포크
   - 실시간 분석 지원

3. WinDbg
   - Microsoft 디버거
   - 커널 분석

주요 분석 항목:
┌────────────────┬──────────────────────┐
│   분석 항목    │       명령어         │
├────────────────┼──────────────────────┤
│ 프로세스 목록  │ pslist, psscan ★    │
├────────────────┼──────────────────────┤
│ 네트워크 연결  │ netscan, connscan   │
├────────────────┼──────────────────────┤
│ DLL 로드       │ dlllist              │
├────────────────┼──────────────────────┤
│ 레지스트리     │ hivelist, printkey   │
├────────────────┼──────────────────────┤
│ 파일 핸들      │ handles, filescan   │
├────────────────┼──────────────────────┤
│ 악성코드 탐지  │ malfind ★★         │
└────────────────┴──────────────────────┘

Volatility 사용 예시:
volatility -f memory.dmp --profile=Win7SP1x64 pslist
volatility -f memory.dmp --profile=Win7SP1x64 malfind
volatility -f memory.dmp --profile=Win7SP1x64 netscan
```

## 🔴 비활성 데이터 분석 ★★

### 문제 (2024년 기출)
```
비활성 데이터(Inactive Data)란?
```

### ✅ 정답
```
비활성 데이터 (Inactive Data, Data at Rest)

정의:
저장 매체에 저장되어 있지만
현재 사용/전송되지 않는 데이터

특징:
- 디스크, USB, 백업 테이프 등에 저장
- 장기간 보관
- 암호화 필요 ★★★

분석 대상:
1. 삭제된 파일 복구
   - 파일 시스템 슬랙
   - 언알로케이트 영역

2. 타임라인 분석 ★★
   - 파일 생성/수정/접근 시간 (MAC Time)
   - 이벤트 순서 재구성

3. 파일 카빙 (File Carving)
   - 파일 시그니처 기반 복구
   - 예: JPEG (FF D8 FF), PNG (89 50 4E 47)

4. 슬랙 공간 분석
   - 파일 슬랙: 마지막 클러스터 남은 공간
   - RAM 슬랙: 마지막 섹터 남은 공간

vs 활성 데이터:
┌──────────┬──────────────┬──────────────┐
│   구분   │ 비활성 데이터│ 활성 데이터  │
├──────────┼──────────────┼──────────────┤
│ 위치     │ 저장 매체 ★ │ 메모리/전송중│
├──────────┼──────────────┼──────────────┤
│ 상태     │ 정적         │ 동적         │
├──────────┼──────────────┼──────────────┤
│ 위험     │ 탈취/유출    │ 가로채기     │
├──────────┼──────────────┼──────────────┤
│ 보호     │ 암호화 ★★  │ TLS/VPN      │
└──────────┴──────────────┴──────────────┘

보안 대책:
- FDE (Full Disk Encryption)
- TDE (Transparent Data Encryption) ★★
- 백업 암호화
- 물리적 보안
```

## 🔴 악성코드 패킹/언패킹 ★★★

### 문제 (2024년 기출)
```
패킹(Packing)이란?
```

### ✅ 정답
```
패킹 (Packing)

정의:
실행 파일을 압축/암호화하여
원본 코드를 숨기는 기법

목적:
1. 악성코드 은닉 ★★★
   - 시그니처 탐지 우회
   - 정적 분석 방해

2. 파일 크기 감소
   - 원래 목적 (정상 소프트웨어)

3. 안티디버깅
   - 리버스 엔지니어링 방해

대표 패커:
1. UPX (Ultimate Packer for eXecutables) ★★
   - 오픈소스
   - 가장 많이 사용
   - 언패킹 가능

2. ASPack
   - 상용 패커

3. Themida
   - 강력한 보호
   - 안티디버깅

4. 커스텀 패커
   - 악성코드 제작자가 직접 개발
   - 탐지 어려움 ★★

패킹된 파일 특징:
- 엔트로피(Entropy) 높음 ★★★
  (랜덤하게 보임)
- Import Table 단순
- 섹션 이름 특이 (UPX0, UPX1)
- 실행 시 언패킹 루틴 실행

언패킹 (Unpacking):
1. 자동 언패킹
   - UPX: upx -d malware.exe ★
   - 패커 식별: PEiD, Detect It Easy

2. 수동 언패킹
   - OEP (Original Entry Point) 찾기
   - 디버거로 언패킹 루틴 추적
   - 메모리 덤프

3. 동적 언패킹
   - 실행 후 메모리에서 추출

탐지:
- 높은 엔트로피 (7.0 이상) ★★
- 섹션 이름 패턴 (UPX, ASPACK)
- 실행 압축 시그니처
```

## 🔴 정적 분석 vs 동적 분석 ★★★

### 문제 (2024년 기출)
```
악성코드 정적 분석과 동적 분석의 차이는?
```

### ✅ 정답
```
정적 분석 (Static Analysis) ★★

정의:
악성코드를 실행하지 않고
파일 자체를 분석

방법:
1. 파일 정보 확인
   - 해시값 (MD5, SHA-256) ★
   - 파일 크기, 타입

2. 문자열 추출
   - strings 명령어
   - URL, IP, 파일 경로

3. PE 구조 분석
   - Import/Export Table
   - 섹션 정보
   - 리소스

4. 디스어셈블리
   - IDA Pro ★★★
   - Ghidra (NSA, 무료)
   - 어셈블리 코드 분석

장점:
- 안전 (실행 안 함)
- 빠름

단점:
- 패킹 시 분석 어려움 ★★
- 동적 행위 파악 불가

동적 분석 (Dynamic Analysis) ★★★

정의:
악성코드를 실제로 실행하여
행위를 관찰

방법:
1. 샌드박스 실행 ★★★
   - Cuckoo Sandbox
   - Any.Run
   - Joe Sandbox

2. 프로세스 모니터링
   - Process Monitor (ProcMon) ★★
   - Process Explorer
   - API Monitor

3. 네트워크 모니터링
   - Wireshark ★★
   - Fiddler
   - C&C 서버 통신 확인

4. 파일 시스템 변경
   - 생성/수정/삭제된 파일
   - 레지스트리 변경

5. 디버깅
   - OllyDbg ★★
   - x64dbg
   - WinDbg

장점:
- 실제 행위 확인 ★★★
- 패킹 우회
- C&C 통신 확인

단점:
- 위험 (격리 필요)
- 느림
- 안티분석 기법 회피 가능

비교:
┌────────────┬──────────────┬──────────────┐
│   구분     │  정적 분석   │  동적 분석   │
├────────────┼──────────────┼──────────────┤
│ 실행       │ X            │ O ★★       │
├────────────┼──────────────┼──────────────┤
│ 안전성     │ 안전 ★      │ 위험 (격리) │
├────────────┼──────────────┼──────────────┤
│ 속도       │ 빠름         │ 느림         │
├────────────┼──────────────┼──────────────┤
│ 패킹 대응  │ 어려움 ✗   │ 가능 ✓★★   │
├────────────┼──────────────┼──────────────┤
│ 행위 파악  │ 어려움       │ 명확 ★★★  │
├────────────┼──────────────┼──────────────┤
│ 도구       │ IDA, strings │ Cuckoo, ★★ │
│            │ PEiD         │ ProcMon      │
└────────────┴──────────────┴──────────────┘

권장 순서:
1. 정적 분석 (기본 정보 수집)
2. 동적 분석 (행위 확인)
3. 정적 분석 (코드 상세 분석)
```

## 🔴 VM 기반 악성코드 분석 ★★

### 문제 (2024년 기출)
```
VM을 이용한 악성코드 분석의 장점은?
```

### ✅ 정답
```
VM (Virtual Machine) 악성코드 분석

장점: ★★★

1. 격리된 환경 ★★★
   - 호스트 시스템 보호
   - 악성코드 확산 방지

2. 스냅샷 기능 ★★
   - 감염 전 상태로 즉시 복구
   - 반복 실험 가능

3. 네트워크 분리
   - NAT 또는 Host-Only
   - C&C 통신 모니터링
   - 인터넷 차단 가능

4. 다양한 환경 테스트
   - 여러 OS 버전
   - 다양한 설정

5. 비용 절감
   - 물리 장비 불필요

단점:

1. VM 탐지 (Anti-VM) ★★★
   악성코드가 VM 환경 탐지 시 작동 중단

   탐지 기법:
   - VMware 드라이버 확인 (vmware.sys)
   - 레지스트리 키 확인
   - MAC 주소 확인 (00:0C:29 = VMware)
   - CPU 명령어 (CPUID)

2. 성능 저하
   - 느린 실행

대응:
- 가상화 흔적 제거
- VirtualBox, VMware 커스터마이징
- 베어메탈(Bare-metal) 분석 병행

권장 VM 설정:
1. 스냅샷 생성 (Clean State) ★★
2. 네트워크: Host-Only (격리)
3. 공유 폴더 비활성화
4. 클립보드 공유 비활성화
5. VM Tools 제거 고려
```

## 🔴 보안 도구 비교 ★★

### 문제 (2024년 기출)
```
Nmap, Tripwire, Hydra, John the Ripper의 용도는?
```

### ✅ 정답
```
보안 도구 비교:

1. Nmap ★★★
   용도: 포트 스캐너, 네트워크 탐색

   기능:
   - 열린 포트 탐지
   - OS 탐지 (-O)
   - 서비스 버전 탐지 (-sV)
   - 스크립트 엔진 (NSE)

   예시:
   nmap -sS -p- 192.168.1.1       # SYN 스캔
   nmap -O 192.168.1.1            # OS 탐지
   nmap -sV 192.168.1.1           # 서비스 버전

2. Tripwire ★★
   용도: 파일 무결성 검사 (FIM)

   기능:
   - 파일 변경 탐지
   - 해시 기반 검증
   - 정책 기반 모니터링

   동작:
   1. 베이스라인 생성 (초기 해시)
   2. 주기적 검사
   3. 변경 사항 보고

   대안:
   - AIDE (Advanced Intrusion Detection Environment)
   - OSSEC

3. Hydra ★★★
   용도: 네트워크 로그온 크래커 (무차별 대입)

   기능:
   - 다양한 프로토콜 지원
     SSH, FTP, HTTP, RDP, SMTP 등
   - 병렬 공격

   예시:
   hydra -l admin -P pass.txt ssh://192.168.1.1
   hydra -L users.txt -P pass.txt ftp://192.168.1.1

4. John the Ripper ★★★
   용도: 패스워드 크래커

   기능:
   - 오프라인 패스워드 크랙
   - 해시 크래킹
   - 다양한 해시 지원
     (MD5, SHA, NTLM 등)

   예시:
   john --wordlist=rockyou.txt hashes.txt
   john --show hashes.txt

비교표:
┌───────────┬──────────┬──────────────┐
│   도구    │   분류   │     용도     │
├───────────┼──────────┼──────────────┤
│ Nmap      │ 스캐너   │ 포트/네트워크│
│           │          │ 탐색 ★★★   │
├───────────┼──────────┼──────────────┤
│ Tripwire  │ 무결성   │ 파일 변경    │
│           │ 검사 ★  │ 탐지         │
├───────────┼──────────┼──────────────┤
│ Hydra     │ 공격도구 │ 온라인 무차별│
│           │          │ 대입 ★★★   │
├───────────┼──────────┼──────────────┤
│ John the  │ 공격도구 │ 오프라인     │
│ Ripper    │          │ 해시 크랙 ★★│
└───────────┴──────────┴──────────────┘

구분:
- Nmap, Tripwire: 방어 도구
- Hydra, John: 공격 도구 (침투 테스트)
```

## 💡 실기 답안 작성 팁

### Tip 1: 메모리 포렌식
```
✅ 휘발성 데이터 확보, 파일리스 악성코드 탐지, Volatility 사용

❌ 빠르다 (장점이지만 핵심 아님)
```

### Tip 2: 패킹
```
✅ 악성코드 은닉, 시그니처 탐지 우회, 엔트로피 높음 ★★★

❌ 파일 크기 감소 (원래 목적이지만 보안 관점 아님)
```

### Tip 3: VM 악성코드 분석
```
✅ 격리 환경, 스냅샷 복구, 안티VM 탐지 주의 ★★

❌ 비용 절감 (맞지만 보안 이점 아님)
```

### Tip 4: 도구 구분
```
✅ Nmap (포트 스캔), Tripwire (무결성), Hydra (무차별 대입)

❌ 모두 해킹 도구 (Tripwire는 방어 도구!)
```
