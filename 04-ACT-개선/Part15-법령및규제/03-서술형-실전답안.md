## 1. 개인정보보호법 - 암호화

### 문제 1. 개인정보 암호화 대상 및 방법 (15점) ★★★

**문제**:
개인정보보호법에 따라 다음 개인정보 항목에 대한 적절한 암호화 방법을 설명하시오. (15점)

1) 사용자 로그인 비밀번호
2) 주민등록번호
3) 바이오정보 (지문, 홍채)
4) 신용카드번호

**✅ 모범 답안**:

#### 일방향 암호화 대상 - 7점

**1) 사용자 로그인 비밀번호** - 3점 ★★★
**암호화 방법**:
```
일방향 해시 함수 (SHA-256 이상)
```

**상세 설명**:
- 복호화가 불필요한 정보
- 원본을 저장하지 않아야 함
- Salt 추가 권장 (Rainbow Table 공격 방어)
- PBKDF2, bcrypt, Argon2 등 Key Derivation Function 사용 권장

**구현 예시**:
```python
import hashlib

# Salt 생성
salt = os.urandom(32)

# 비밀번호 해싱
password_hash = hashlib.pbkdf2_hmac(
    'sha256',
    password.encode('utf-8'),
    salt,
    100000  # iterations
)
```

**검증 방법**:
```
저장된 해시값과 입력값 해시 비교
동일하면 인증 성공
```

**3) 바이오정보 (지문, 홍채)** - 4점 ★★★
**암호화 방법**:
```
일방향 해시 함수 (SHA-256 이상)
```

**법적 근거**:
- 개인정보보호법 시행령 제21조
- 개인정보의 안전성 확보조치 기준 제7조

**상세 설명**:
- 바이오정보는 변경 불가능한 고유한 정보
- 유출 시 평생 피해 가능
- 반드시 일방향 암호화 적용
- 복호화 불가능하게 보관

**특징**:
```
- 재등록 불가: 한 번 유출되면 영구적 피해
- 템플릿 저장: 원본 이미지가 아닌 특징점만 추출 후 해싱
- 매칭: 입력된 바이오정보를 해싱하여 저장된 해시와 비교
```

#### 양방향 암호화 대상 - 8점

**2) 주민등록번호** - 4점 ★★★
**암호화 방법**:
```
양방향 대칭키 암호화
- AES-256
- SEED
- ARIA
```

**상세 설명**:
- 고유식별정보로 법적 암호화 의무
- 업무상 복호화가 필요한 경우 존재 (본인 확인 등)
- 안전한 키 관리 필수

**키 관리**:
```
1. 키 저장소 (HSM, Key Vault) 사용
2. 키 접근 권한 제한
3. 키 주기적 변경 (권장: 1년)
4. 키 백업 및 복구 절차 수립
```

**4) 신용카드번호** - 4점 ★★★
**암호화 방법**:
```
양방향 대칭키 암호화
- AES-256
- SEED
- ARIA
```

**상세 설명**:
- 결제 처리 시 복호화 필요
- PCI-DSS (Payment Card Industry Data Security Standard) 준수 필요
- 전송 시에도 암호화 (TLS/SSL)

**보안 강화**:
```
1. 토큰화 (Tokenization):
   - 실제 카드번호를 토큰으로 대체
   - 결제 시에만 실제 번호 사용

2. 마스킹:
   - 1234-****-****-5678
   - 일부만 표시

3. 전송 암호화:
   - TLS 1.2 이상
   - 종단간 암호화 (E2EE)
```

---

**채점 기준**:
- 일방향 암호화 대상 2가지 (비밀번호, 바이오정보) 정확히 구분 (4점)
- 일방향 암호화 방법 (SHA-256 이상) 명시 (2점)
- 양방향 암호화 대상 2가지 (주민번호, 카드번호) 정확히 구분 (4점)
- 양방향 암호화 방법 (AES, SEED, ARIA) 명시 (3점)
- 각 방법의 이유 및 특징 설명 (2점)

**핵심 요약**:
```
일방향 암호화 (복호화 불가): ★★★
- 비밀번호: SHA-256 이상 + Salt
- 바이오정보: SHA-256 이상

양방향 암호화 (복호화 가능): ★★★
- 주민등록번호: AES, SEED, ARIA
- 신용카드번호: AES, SEED, ARIA
- 여권번호: AES, SEED, ARIA
- 운전면허번호: AES, SEED, ARIA
- 외국인등록번호: AES, SEED, ARIA
- 계좌번호: AES, SEED, ARIA
```

**암기 팁**:
```
"비바는 일방" (비밀번호, 바이오정보는 일방향)
"주카여운외계는 양방" (주민번호, 카드번호, 여권, 운전면허, 외국인, 계좌는 양방향)
```

## 2. 개인정보보호법 - 안전성 확보조치

### 문제 2. 접속기록 보존 및 점검 (12점) ★★★

**문제**:
개인정보의 안전성 확보조치 기준에 따른 접속기록 보존 기간과 점검 주기를 설명하시오. (12점)

**✅ 모범 답안**:

#### 접속기록 보존 기간 - 6점 ★★★

**기본 원칙**:
```
1년 이상 보존 ★★★
```

**예외 (2년 이상 보존)**: ★★★
다음 중 하나에 해당하는 경우:
```
1. 정보주체 수가 5만명 이상인 경우
2. 고유식별정보를 처리하는 경우
3. 민감정보를 처리하는 경우
```

**법적 근거**:
- 개인정보보호법 제29조 (안전조치의무)
- 개인정보의 안전성 확보조치 기준 제8조

**보존 대상 접속기록**:
```
1. 접속자 (사용자 ID)
2. 접속 일시
3. 접속자 IP 주소
4. 처리한 개인정보 항목
5. 수행 업무 (조회, 수정, 삭제 등)
```

**보존 방법**:
```
- 별도 저장 (DB 테이블 분리 또는 로그 파일)
- 위변조 방지 조치 (해시, 전자서명)
- 안전한 보관 (암호화, 접근통제)
```

#### 접속기록 점검 주기 - 3점 ★★★

**점검 주기**:
```
월 1회 이상 ★★★
```

**점검 내용**:
```
1. 비인가 접속 여부
   - 권한 없는 사용자의 접근 시도
   - 비정상 시간대 접속

2. 개인정보 오남용 여부
   - 업무 목적 외 조회
   - 대량 다운로드
   - 특정 개인정보 반복 조회

3. 이상 접속 행위
   - 동일 IP에서 다수 ID 로그인
   - 짧은 시간 내 대량 접속
   - SQL Injection 시도

4. 관리자 권한 사용 내역
   - 관리자 계정 사용 이력
   - 권한 변경 이력
```

**점검 결과 조치**:
```
1. 이상 징후 발견 시 즉시 조사
2. 침해 사고 발생 시 보고 및 대응
3. 점검 결과 기록 유지 (3년)
```

#### 권한 부여/변경/말소 기록 보관 - 3점 ★★

**보관 기간**:
```
3년 보관 ★★★
```

**기록 대상**:
```
1. 권한 부여
   - 사용자 ID
   - 부여 권한 종류
   - 부여 일시
   - 부여 사유
   - 승인자

2. 권한 변경
   - 변경 전/후 권한
   - 변경 일시
   - 변경 사유
   - 승인자

3. 권한 말소
   - 말소 일시
   - 말소 사유 (퇴사, 업무 변경 등)
   - 승인자
```

---

**채점 기준**:
- 기본 보존 기간 (1년) 정확히 기재 (2점)
- 예외 사항 (5만명, 고유식별정보, 민감정보) 중 1가지 이상 (3점)
- 점검 주기 (월 1회) 정확히 기재 (3점)
- 권한 기록 보관 기간 (3년) 기재 (2점)
- 점검 내용 또는 조치사항 설명 (2점)

**핵심 요약**:
```
접속기록 보존: ★★★
- 기본: 1년 이상
- 예외: 2년 이상 (5만명↑, 고유식별정보, 민감정보)

접속기록 점검: ★★★
- 월 1회 이상

권한 기록: ★★
- 3년 보관
```

**암기 팁**:
```
"1년, 2년, 월1, 권3"
- 접속기록: 1년 (예외 2년)
- 점검: 월 1회
- 권한: 3년
```

### 문제 3. 안전성 확보조치 기준 (18점) ★★★

**문제**:
개인정보의 안전성 확보조치 기준에 따른 주요 보호조치를 관리적, 기술적, 물리적 보호조치로 구분하여 설명하시오. (18점)

**✅ 모범 답안**:

#### 1. 관리적 보호조치 - 6점

**1) 내부 관리계획 수립 및 시행** ★★★
```
내용:
- 개인정보 처리 방침 수립
- 접근 권한 관리
- 접근통제 정책
- 개인정보 보호책임자 지정

의무 대상:
- 개인정보 처리자 모두
```

**2) 접근 권한 관리** ★★★
```
- 개인정보 처리 업무 담당자만 권한 부여
- 최소 권한 원칙 (Least Privilege)
- 업무 변경 시 권한 즉시 변경/말소
- 퇴직자 권한 즉시 삭제
```

**3) 개인정보 보호 교육** ★★
```
주기: 연 1회 이상 ★★

대상: 전 직원

내용:
- 개인정보보호법 이해
- 개인정보 처리 방침
- 침해 사고 대응 절차
- 개인정보 보호 의무
```

**4) 개인정보 보호책임자 지정** ★★★
```
자격:
- 임원급 이상
- 개인정보 보호 업무 총괄

역할:
- 개인정보 보호 계획 수립
- 정책 시행 및 점검
- 침해사고 대응
- 개인정보 영향평가
```

#### 2. 기술적 보호조치 - 6점

**1) 개인정보 암호화** ★★★
```
일방향 암호화:
- 비밀번호: SHA-256 이상
- 바이오정보: SHA-256 이상

양방향 암호화:
- 주민등록번호: AES, SEED, ARIA
- 신용카드번호: AES, SEED, ARIA
- 계좌번호: AES, SEED, ARIA
```

**2) 접근통제** ★★★
```
1. 사용자 인증 강화
   - ID/PW + 2차 인증 (OTP, SMS)
   - 생체인증

2. 세션 관리
   - 비활성 시간 제한 (15분 권장)
   - 자동 로그아웃

3. 접근 제어 (ACL)
   - 역할 기반 접근통제 (RBAC)
   - IP 기반 접근 제한
```

**3) 접속기록 보관 및 점검** ★★★
```
- 접속기록 1년 이상 보관 (예외: 2년)
- 월 1회 이상 점검
- 위변조 방지 조치
```

**4) 보안 프로그램 설치 및 운영** ★★
```
1. 백신 프로그램
   - 최신 버전 유지
   - 실시간 감시
   - 정기 검사 (일 1회)

2. 방화벽
   - 외부 침입 차단
   - 불필요한 포트 차단

3. 침입탐지·차단시스템 (IDS/IPS)
   - 실시간 모니터링
   - 이상 행위 탐지
```

**5) 패스워드 정책** ★★
```
1. 복잡도
   - 10자 이상
   - 영문대소문자+숫자+특수문자 조합

2. 변경 주기
   - 90일마다 변경 권장

3. 재사용 제한
   - 최근 3~5개 패스워드 재사용 금지

4. 초기 패스워드 변경
   - 최초 로그인 시 즉시 변경
```

#### 3. 물리적 보호조치 - 6점

**1) 출입통제** ★★★
```
전산실/개인정보 보관 구역:

1. 출입 인증
   - 카드키, 생체인증
   - 이중 인증 권장

2. 출입 기록
   - 출입자, 일시, 목적 기록
   - 1년 이상 보관

3. 방문자 관리
   - 사전 승인
   - 담당자 동행
   - 출입증 발급
```

**2) 개인정보 보관** ★★
```
1. 잠금장치
   - 서류함, 캐비닛 잠금
   - 보관 구역 시건

2. 문서 관리
   - 불필요 시 즉시 파기
   - 파기 시 복구 불가능하게 (문서세단기)
   - 파기 기록 유지
```

**3) CCTV 설치** ★★
```
설치 위치:
- 전산실 입구
- 서버실
- 개인정보 보관 구역

설치 금지:
- 화장실, 탈의실, 목욕실 등
```

**4) 재해·재난 대비** ★★
```
1. 화재 대비
   - 소화기, 자동 소화 장치
   - 연기 감지기

2. 침수 대비
   - 배수 시설
```
