## 1. 제로 트러스트

### 문제 1. 제로 트러스트 개념 및 원칙 (20점) ★★★

**문제**:
제로 트러스트(Zero Trust) 보안 모델의 개념과 핵심 원칙을 기존 경계 기반 보안과 비교하여 설명하시오. (20점)

**✅ 모범 답안**:

#### 제로 트러스트 개념 - 5점 ★★★

**정의**:
```
"절대 신뢰하지 말고, 항상 검증하라"
(Never Trust, Always Verify)

모든 접근 시도를 신뢰하지 않고
매번 검증하는 보안 모델
```

**배경**:
```
전통적 경계 기반 보안 모델의 한계:
- 내부 네트워크는 안전하다는 가정 ❌
- 외부는 위험, 내부는 안전하다는 이분법
- 내부 침투 시 횡적 이동(Lateral Movement) 용이
- 재택근무, 클라우드 환경에서 경계 모호

제로 트러스트의 가정:
- 내부/외부 구분 없이 모두 신뢰하지 않음
- 침해는 언제나 발생할 수 있다고 가정
- 네트워크 위치와 무관하게 검증
```

#### 기존 경계 기반 보안 vs 제로 트러스트 - 5점

| 구분 | 경계 기반 (Castle-and-Moat) | 제로 트러스트 |
|-----|---------------------------|--------------|
| **신뢰 모델** | 내부 신뢰 ★ | 아무도 신뢰하지 않음 ★★★ |
| **검증** | 최초 1회 (로그인 시) | 지속적 검증 ★★★ |
| **경계** | 명확한 경계 (방화벽) | 경계 없음 (Perimeterless) |
| **접근 제어** | 네트워크 위치 기반 | 신원 기반 ★★★ |
| **가정** | "내부는 안전" ❌ | "모두 위협 가능" ★★★ |
| **이동** | 내부 자유 이동 | 최소 권한, 세그먼트화 |

**경계 기반 보안 문제점**:
```
1. 내부 침투 시 대응 어려움
   - APT 공격자가 내부 진입 후 자유로운 이동

2. 클라우드/모바일 환경 부적합
   - 명확한 경계 설정 불가

3. 내부자 위협 대응 부족
   - 내부 직원의 악의적 행위 탐지 어려움
```

#### 제로 트러스트 핵심 원칙 - 10점 ★★★

**1. 명시적 검증 (Verify Explicitly)** - 3점 ★★★
```
정의:
모든 접근 요청을 명시적으로 검증

검증 요소:
1. 사용자 신원 (Identity)
   - 다중 인증 (MFA) ★★★
   - 생체 인증

2. 디바이스 상태 (Device Health)
   - 보안 패치 상태
   - 백신 업데이트
   - 규정 준수 여부

3. 위치 (Location)
   - 접속 위치 (IP, GPS)
   - 비정상 위치 탐지

4. 행위 (Behavior)
   - 평소와 다른 행동 패턴
   - 이상 징후 탐지

5. 실시간 위험 평가 (Risk Score)
   - 위험도에 따라 접근 수준 조정
```

**예시**:
```
사용자 A의 접근 요청:
✓ 신원: MFA 인증 완료
✓ 디바이스: 회사 노트북, 보안 패치 최신
✓ 위치: 사무실 네트워크
✓ 행위: 평소 패턴과 일치
→ 접근 허용

사용자 B의 접근 요청:
✓ 신원: MFA 인증 완료
❌ 디바이스: 개인 스마트폰, 보안 패치 미적용
❌ 위치: 해외 (평소 접속하지 않던 곳)
❌ 행위: 새벽 시간 대량 파일 다운로드
→ 추가 인증 요구 또는 접근 거부
```

**2. 최소 권한 접근 (Least Privilege Access)** - 3점 ★★★
```
정의:
사용자에게 업무 수행에 필요한 최소한의 권한만 부여

원칙:
1. Just-In-Time (JIT) 접근
   - 필요한 시점에만 권한 부여
   - 시간 제한 (예: 1시간)

2. Just-Enough-Access (JEA)
   - 필요한 리소스에만 접근
   - 과도한 권한 방지

3. 역할 기반 접근 통제 (RBAC)
   - 업무 역할에 따른 권한

4. 정기적 권한 검토
   - 불필요한 권한 회수
```

**예시**:
```
개발자 A:
- 개발 서버: 읽기/쓰기 권한
- 운영 서버: 읽기 전용 ★
- DB: 개발 DB만 접근
- 시간: 근무 시간만

관리자 B:
- 특권 작업 시: 추가 인증 후 1시간 권한
- 평소: 일반 사용자 권한
```

**3. 침해 가정 (Assume Breach)** - 2점 ★★★
```
정의:
침해는 이미 발생했다고 가정하고 대응

대응 전략:
1. 마이크로 세그먼테이션 (Micro-Segmentation) ★★★
   - 네트워크를 작은 영역으로 분리
   - 횡적 이동 차단
   - 각 세그먼트 간 트래픽 검증

2. 지속적 모니터링
   - 모든 접근 로그 기록
   - 이상 행위 실시간 탐지

3. 빠른 격리
   - 의심 활동 즉시 격리
   - 피해 확산 방지
```

**마이크로 세그먼테이션 예시**:
```
기존:
[인터넷] → [방화벽] → [내부 네트워크 (자유 이동)]
                         ↑ 침투 후 전체 접근 가능 ❌

제로 트러스트:
[인터넷] → [Gateway]
              ↓
         [세그먼트 A (웹 서버)] ← 검증
         [세그먼트 B (DB 서버)] ← 검증
         [세그먼트 C (파일 서버)] ← 검증

각 세그먼트 간 이동 시 검증 필요 ★★★
침투 시 한 세그먼트에만 영향
```

**4. 모든 리소스 보호** - 2점
```
정의:
모든 데이터, 서비스, 디바이스를 보호 대상으로 간주

보호 대상:
- 데이터 (Data)
- 워크로드 (Workload)
- 디바이스 (Device)
- 네트워크 (Network)
- 애플리케이션 (Application)
- 사용자 (User/Identity)
```

#### 제로 트러스트 구현 기술 - 보너스

**1. IAM (Identity and Access Management)**
```
- SSO (Single Sign-On)
- MFA (Multi-Factor Authentication) ★★★
- 조건부 접근 (Conditional Access)
```

**2. 마이크로 세그먼테이션**
```
- 소프트웨어 정의 경계 (SDP: Software-Defined Perimeter)
- 네트워크 세분화
```

**3. 지속적 모니터링**
```
- SIEM (Security Information and Event Management)
- UEBA (User and Entity Behavior Analytics)
- EDR/XDR
```

**4. 암호화**
```
- 전송 중 암호화 (TLS)
- 저장 시 암호화 (AES)
- 엔드투엔드 암호화
```

---

**채점 기준**:
- 제로 트러스트 정의 및 배경 (5점)
- 경계 기반 보안과의 비교 (5점)
- 핵심 원칙 3가지 이상 상세 설명 (10점)

**핵심 요약**:
```
제로 트러스트 (Zero Trust): ★★★

개념: "절대 신뢰하지 말고, 항상 검증하라"

핵심 원칙:
1. 명시적 검증 (Verify Explicitly)
   - 사용자, 디바이스, 위치, 행위 검증
   - MFA 필수 ★★★

2. 최소 권한 접근 (Least Privilege)
   - 필요한 최소 권한만
   - JIT/JEA

3. 침해 가정 (Assume Breach)
   - 마이크로 세그먼테이션 ★★★
   - 횡적 이동 차단

vs 경계 기반:
- 경계 기반: 내부 신뢰, 1회 검증
- 제로 트러스트: 아무도 신뢰 안 함, 지속 검증 ★★★
```

**암기 팁**:
```
"명최침" (명시적 검증, 최소 권한, 침해 가정)

"Never Trust, Always Verify"
```

## 2. 보안 솔루션

### 문제 2. EDR과 XDR 비교 (18점) ★★★

**문제**:
EDR(Endpoint Detection and Response)과 XDR(Extended Detection and Response)의 개념과 차이점을 설명하시오. (18점)

**✅ 모범 답안**:

#### EDR (Endpoint Detection and Response) - 8점 ★★★

**정의**:
```
엔드포인트 탐지 및 대응
PC, 서버, 모바일 등 엔드포인트에서
위협을 탐지하고 대응하는 솔루션
```

**범위**: ★★★
```
엔드포인트 중심
- PC (데스크톱, 노트북)
- 서버 (물리/가상)
- 모바일 디바이스
```

**주요 기능**:

**1. 지속적 모니터링** ★★★
```
- 프로세스 실행
- 파일 생성/수정/삭제
- 레지스트리 변경
- 네트워크 연결
- 사용자 행위
```

**2. 위협 탐지** ★★★
```
탐지 방법:
- 시그니처 기반 (Signature)
- 행위 기반 (Behavior) ★★★
- 머신러닝/AI
- IoC (Indicators of Compromise)

탐지 대상:
- 악성코드
- 랜섬웨어 ★★★
- 파일리스 공격
- 제로데이 공격
- 내부자 위협
```

**3. 자동 대응** ★★★
```
- 프로세스 종료
- 파일 격리/삭제
- 네트워크 차단
- 엔드포인트 격리 (Isolation) ★★★
```

**4. 포렌식 및 조사**
```
- 타임라인 분석
- 공격 경로 추적
- 근본 원인 분석 (RCA: Root Cause Analysis)
```

**EDR vs 기존 백신**:

| 구분 | 기존 백신 (AV) | EDR |
|-----|--------------|-----|
| 탐지 | 시그니처 중심 | 행위 기반 ★★★ |
| 범위 | 파일 중심 | 엔드포인트 전체 |
| 대응 | 자동 치료/삭제 | 다양한 대응 (격리 등) |
| 조사 | 제한적 | 상세 포렌식 가능 ★★ |
| 제로데이 | 취약 | 탐지 가능 ★★★ |

**장점**:
```
✅ 엔드포인트 상세 가시성
✅ 제로데이 공격 탐지
✅ 자동 대응으로 빠른 차단
✅ 포렌식 조사 용이
```

**단점**:
```
❌ 엔드포인트에만 집중
❌ 네트워크/클라우드 가시성 부족
❌ 통합 관점 부족
```

#### XDR (Extended Detection and Response) - 8점 ★★★

**정의**:
```
확장 탐지 및 대응
엔드포인트, 네트워크, 클라우드, 이메일 등
다양한 보안 계층을 통합하여
위협을 탐지하고 대응하는 솔루션
```

**범위**: ★★★
```
전방위적 (Cross-layered)
- 엔드포인트 (EDR)
- 네트워크 (NDR: Network Detection and Response)
- 클라우드 (CWPP: Cloud Workload Protection Platform)
- 이메일 (Email Security)
- 애플리케이션
- 신원 (IAM)
```

**핵심 특징**:

**1. 통합 가시성** ★★★
```
모든 보안 계층의 데이터를 통합

수집 데이터:
- 엔드포인트 로그
- 네트워크 트래픽
- 클라우드 활동
- 이메일 로그
- 인증 로그
- 애플리케이션 로그

→ 단일 콘솔에서 전체 보기
```

**2. 상관 분석 (Correlation Analysis)** ★★★
```
다양한 소스의 데이터를 연결하여 공격 탐지

예시:
1. 이메일: 피싱 메일 수신
2. 엔드포인트: 악성 첨부파일 실행
3. 네트워크: C&C 서버 통신
4. 클라우드: 데이터 유출 시도

→ XDR이 전체 공격 체인 연결 및 탐지 ★★★
```

**3. 자동화된 대응** ★★★
```
통합 대응:
- 엔드포인트 격리
- 네트워크 차단
- 계정 비활성화
- 이메일 격리
- 클라우드 접근 차단

→ 한 번의 조치로 모든 계층에서 대응
```

**4. AI/ML 기반 위협 헌팅**
```
- 이상 행위 패턴 자동 탐지
- 알려지지 않은 위협 발견
- 허위 경보(False Positive) 감소
```

**XDR vs EDR**: ★★★

| 구분 | EDR | XDR |
|-----|-----|-----|
| **범위** | 엔드포인트만 | 전방위 (엔드포인트+네트워크+클라우드 등) ★★★ |
| **가시성** | 엔드포인트 중심 | 통합 가시성 ★★★ |
| **상관 분석** | 제한적 | 다중 소스 상관 분석 ★★★ |
| **공격 체인** | 부분적 | 전체 공격 체인 추적 ★★★ |
| **관리** | 개별 콘솔 | 단일 통합 콘솔 |
| **대응** | 엔드포인트만 | 모든 계층 통합 대응 |

**XDR 장점**:
```
✅ 전체적인 보안 가시성
✅ 복잡한 공격 탐지 (APT 등)
✅ 허위 경보 감소
✅ 빠른 위협 헌팅
✅ 효율적 관리 (단일 콘솔)
```

**XDR 단점**:
```
❌ 높은 비용
❌ 구축 복잡도
❌ 다양한 보안 제품 통합 필요
```

#### EDR → XDR 진화 - 2점

**보안 솔루션 진화**:
```
AV (Antivirus)
  → 시그니처 기반 악성코드 차단

EPP (Endpoint Protection Platform)
  → 통합 엔드포인트 보호

EDR (Endpoint Detection and Response) ★★
  → 엔드포인트 탐지 및 대응
  → 행위 기반, 포렌식

XDR (Extended Detection and Response) ★★★
  → 전방위 통합 탐지 및 대응
  → 엔드포인트 + 네트워크 + 클라우드
```

**XDR 예시 시나리오**:

```
공격: 피싱 메일 → 악성코드 실행 → 횡적 이동 → 데이터 유출

EDR만 사용 시:
❌ 피싱 메일: 탐지 못함 (이메일 보안 영역)
✓ 악성코드 실행: 탐지
❌ 횡적 이동: 제한적 탐지 (네트워크 보안 영역)
❌ 데이터 유출: 탐지 못함 (네트워크/클라우드 영역)

XDR 사용 시: ★★★
✓ 피싱 메일: 탐지 (이메일 통합)
✓ 악성코드 실행: 탐지 (EDR)
✓ 횡적 이동: 탐지 (NDR)
✓ 데이터 유출: 탐지 및 차단 (전체 통합)
→ 전체 공격 체인 시각화 및 자동 대응 ★★★
```

---

**채점 기준**:
- EDR 정의 및 주요 기능 (6점)
- XDR 정의 및 주요 기능 (6점)
- EDR과 XDR의 차이점 명확히 비교 (6점)

**핵심 요약**:
```
EDR (Endpoint Detection and Response): ★★★
- 엔드포인트 중심
- 행위 기반 탐지
- 자동 대응 (격리, 차단)
- 포렌식 가능

XDR (Extended Detection and Response): ★★★
- 전방위 통합 (엔드포인트+네트워크+클라우드 등)
- 통합 가시성 ★★★
- 상관 분석으로 전체 공격 체인 탐지
- 단일 콘솔 관리
- 모든 계층 통합 대응

차이: EDR(부분) < XDR(전체)
```

**암기 팁**:
```
"EDR = Endpoint (끝점만)"
"XDR = eXtended (확장, 전부)"

"XDR = EDR + NDR + 클라우드 + 이메일 + ..."
```

#### SASE 개념 - 5점 ★★★

**정의**:
```
Secure Access Service Edge (사세, 새시)
```

**배경**:
```
전통적 모델의 한계:
- 본사 중심 아키텍처 (Hub-and-Spoke)
- 모든 트래픽이 데이터센터 경유
- 원격 근무자 증가
- 클라우드 애플리케이션 증가
- 지연 시간 증가, 성능 저하

SASE의 해결:
- 사용자 위치와 가까운 엣지에서 처리
- 네트워크 + 보안 통합
- 클라우드 네이티브
```

**1. 클라우드 네이티브** ★★★
```

```

**2. 통합 서비스**
```
네트워크 + 보안 기능 통합

- 간소화된 관리
```

```

- 제로 트러스트 원칙 적용
```

### 문제 4. SOAR 개념 (12점) ★★

**문제**:
SOAR(Security Orchestration, Automation and Response)의 개념과 주요 기능을 설명하시오. (12점)

**✅ 모범 답안**:

#### SOAR 개념 - 4점 ★★★

**정의**:
```
Security Orchestration, Automation and Response
보안 오케스트레이션, 자동화 및 대응

보안 운영을 자동화하고 통합하여
보안 사고에 신속하게 대응하는 플랫폼
```

**배경**:
```
문제점:
- 보안 경보 폭증 (Alert Fatigue)
- 수동 대응으로 인한 지연
- 여러 보안 도구 개별 관리
- 보안 인력 부족

SOAR의 해결:
- 자동화된 대응
- 통합 관리
- 신속한 처리
```

#### SOAR 주요 기능 - 8점 ★★★

**1. Orchestration (오케스트레이션)** - 3점 ★★★
```
정의:
다양한 보안 도구를 연결하고 통합

기능:
- 보안 도구 간 연동
- 워크플로우 정의
- 데이터 공유

통합 대상:
- SIEM
- 방화벽
- IDS/IPS
- EDR
- 위협 인텔리전스
- 티켓 시스템
- 이메일

예시:
SIEM → (경보 발생) → SOAR → (자동 조사) →
방화벽 (IP 차단) + EDR (프로세스 종료) + 티켓 생성
```

**2. Automation (자동화)** - 3점 ★★★
```
정의:
반복적인 보안 작업을 자동화

자동화 작업:
1. 경보 분석
   - 허위 경보 필터링
   - 위험도 평가
   - 우선순위 지정

2. 조사 (Investigation)
   - IP/도메인 평판 조회
   - 위협 인텔리전스 검색
   - 관련 로그 수집

3. 대응 (Response)
   - IP 차단
   - 계정 비활성화
   - 파일 격리
   - 이메일 격리

4. 보고
   - 사고 보고서 자동 생성
   - 담당자 통보
```

**플레이북 (Playbook)**: ★★★
```
정의:
자동화된 대응 절차

예시: 피싱 메일 대응 플레이북
1. 피싱 메일 보고 접수
2. 메일 헤더 분석 (자동)
3. 첨부파일 샌드박스 분석 (자동)
4. URL 평판 조회 (자동)
5. 악성 판정 시:
   - 유사 메일 검색 및 격리 (자동)
   - 수신자 계정 패스워드 재설정 요청 (자동)
   - 방화벽에 악성 URL 차단 (자동)
   - 보안팀에 알림 (자동)
6. 사고 보고서 생성 (자동)
```

**3. Response (대응)** - 2점 ★★
```
정의:
신속하고 일관된 사고 대응

대응 유형:
1. 자동 대응 (Automated)
   - 사전 정의된 플레이북 실행
   - 인간 개입 없이 즉시 처리

2. 반자동 대응 (Semi-Automated)
   - SOAR가 조사 후 대응안 제시
   - 분석가 승인 후 실행

3. 수동 대응 (Manual)
   - 분석가가 직접 판단 및 실행
   - SOAR는 정보 제공만
```

#### SOAR vs SIEM

| 구분 | SIEM | SOAR |
|-----|------|------|
| 주요 기능 | 로그 수집, 분석, 경보 생성 | 자동화, 오케스트레이션, 대응 |
| 초점 | 탐지 (Detection) | 대응 (Response) ★★★ |
| 자동화 | 제한적 | 광범위한 자동화 |
| 통합 | 로그 중심 | 다양한 보안 도구 |
| 목적 | 가시성, 탐지 | 신속한 대응, 효율성 |

**관계**: ★★
```
SIEM + SOAR = 강력한 보안 운영

SIEM: 이상 탐지 및 경보
  ↓
SOAR: 자동 조사 및 대응
```

#### SOAR 장점

```
✅ 대응 시간 단축 (MTTR 감소)
✅ 인력 부족 해결
✅ 일관된 대응 (실수 감소)
✅ 허위 경보 감소
✅ 보안팀 효율성 향상
```

---

**채점 기준**:
- SOAR 정의 및 배경 (4점)
- 3가지 주요 기능 (Orchestration, Automation, Response) 설명 (8점)

**핵심 요약**:
```
SOAR (Security Orchestration, Automation and Response): ★★

개념:
보안 운영 자동화 및 통합 플랫폼

3대 기능:
1. Orchestration (오케스트레이션)
   - 보안 도구 통합

2. Automation (자동화) ★★★
   - 반복 작업 자동화
   - 플레이북 기반

3. Response (대응)
   - 신속한 사고 대응

플레이북:
- 자동화된 대응 절차
- IF-THEN 로직

vs SIEM:
- SIEM: 탐지
- SOAR: 대응 ★★★
```

**암기 팁**:
```
"SOAR = 보안 자동화"

"OAR (오토메이션이 핵심)"
Orchestration (통합)
Automation (자동화) ★★★
Response (대응)
```

### 문제 5. DevSecOps 개념 (15점) ★★★

**문제**:
DevSecOps의 개념과 전통적 개발 방식과의 차이점을 설명하시오. (15점)

**✅ 모범 답안**:

#### DevSecOps 개념 - 5점 ★★★

**정의**:
```
Development + Security + Operations

개발(Dev), 보안(Sec), 운영(Ops)을 통합하여
개발 생명주기 전반에 보안을 내재화하는 방법론
```

**핵심 원칙**:
```
"Shift Left" (왼쪽으로 이동) ★★★

보안을 개발 초기 단계부터 적용
- 기획/설계 단계부터 보안 고려
- 코딩 중 보안 검증
- 배포 전 보안 테스트
```

**배경**:
```
전통적 개발의 문제:
- 개발 완료 후 보안 테스트
- 뒤늦게 발견된 취약점 수정 비용 ↑
- 개발과 보안의 단절
- 느린 배포 주기

DevSecOps의 해결:
- 보안을 개발 프로세스에 통합
- 조기 취약점 발견 및 수정
- 자동화된 보안 검증
- 빠른 배포 유지
```

#### 진화 과정 - 3점

**1. 전통적 Waterfall**:
```
요구사항 → 설계 → 개발 → 테스트 → 배포 → [보안 테스트]
                                        ↑ 보안은 마지막
❌ 늦은 취약점 발견
❌ 높은 수정 비용
❌ 긴 배포 주기
```

**2. DevOps**:
```
개발(Dev) + 운영(Ops) 통합
지속적 통합/배포 (CI/CD)

개발 ⇄ 테스트 ⇄ 배포 (빠른 반복)

✅ 빠른 배포
❌ 보안은 여전히 별도 ★
```

**3. DevSecOps**: ★★★
```
개발(Dev) + 보안(Sec) + 운영(Ops) 통합

[계획] → [코딩] → [빌드] → [테스트] → [배포] → [운영]
   ↓       ↓       ↓        ↓        ↓       ↓
 [보안]  [보안]  [보안]   [보안]   [보안]  [보안]

모든 단계에 보안 내재화 ★★★

✅ 조기 취약점 발견
✅ 낮은 수정 비용
✅ 빠른 배포 유지
✅ 보안 자동화
```

#### DevSecOps 주요 활동 - 7점 ★★★

**1. 계획/설계 단계** - 1점
```
- 위협 모델링 (Threat Modeling)
- 보안 요구사항 정의
- 보안 아키텍처 설계
```

**2. 코딩 단계** - 2점 ★★★
```
- 보안 코딩 가이드라인 준수
- IDE 보안 플러그인
- 코드 리뷰 (Code Review)
- Pair Programming
```

**3. 빌드 단계** - 2점 ★★★
```
SAST (Static Application Security Testing) ★★★
- 정적 분석
- 소스 코드 취약점 검사
- 자동화된 검사

SCA (Software Composition Analysis)
- 오픈소스 라이브러리 취약점 검사
- 라이선스 검증
```

**4. 테스트 단계** - 2점 ★★★
```
DAST (Dynamic Application Security Testing) ★★★
- 동적 분석
- 실행 중인 애플리케이션 테스트
- 블랙박스 테스트

IAST (Interactive Application Security Testing)
- 대화형 분석
- 실행 중 코드 분석
- 그레이박스 테스트

침투 테스트 (Penetration Testing)
- 실제 공격 시뮬레이션
```

**5. 배포 단계** - 1점
```
- 컨테이너 이미지 스캔
- IaC (Infrastructure as Code) 보안 검사
- 설정 오류 검사
```

**6. 운영 단계** - 1점
```
- 런타임 보안 모니터링
- RASP (Runtime Application Self-Protection)
- 로그 분석
- 사고 대응
```

#### 주요 도구 및 기술

**SAST (정적 분석)**: ★★★
```
- SonarQube
- Checkmarx
- Fortify

시점: 코드 작성 후, 컴파일 전
장점: 조기 발견, 소스코드 접근 필요
단점: 오탐(False Positive) 많음
```

**DAST (동적 분석)**: ★★★
```
- OWASP ZAP
- Burp Suite
- Acunetix

시점: 애플리케이션 실행 중
장점: 실제 취약점 검증, 소스코드 불필요
단점: 늦은 발견, 런타임 필요
```

**CI/CD 통합**: ★★★
```
Jenkins, GitLab CI, GitHub Actions에 보안 도구 통합

Pipeline 예시:
1. Code Commit
2. SAST 실행
3. Unit Test
4. Build Docker Image
5. Container Scan
6. DAST 실행
7. Deploy (취약점 없을 경우만)
```

---

**채점 기준**:
- DevSecOps 정의 및 핵심 원칙 (Shift Left) (5점)
- 전통적 방식과의 차이 (3점)
- 주요 활동 및 도구 (SAST/DAST 등) (7점)

**핵심 요약**:
```
DevSecOps (Dev + Sec + Ops): ★★★

핵심: "Shift Left" (보안을 앞당김)
- 개발 초기부터 보안 통합
- 모든 단계에 보안 내재화

vs 전통적 개발:
- 전통적: 개발 후 보안 테스트 (뒤늦게)
- DevSecOps: 개발 중 지속적 보안 검증 ★★★

주요 활동:
- SAST: 정적 분석 (코드 검사) ★★★
- DAST: 동적 분석 (실행 중 검사) ★★★
- SCA: 오픈소스 라이브러리 검사
- CI/CD 통합

장점:
- 조기 취약점 발견
- 낮은 수정 비용
- 빠른 배포 유지
```

**암기 팁**:
```
"Shift Left" (왼쪽으로, 앞당김)

"SAST는 정적 (Static)"
"DAST는 동적 (Dynamic)"
```

## 4. 클라우드 및 공급망 보안

### 문제 6. 공급망 보안 (15점) ★★

**문제**:
소프트웨어 공급망 공격(Supply Chain Attack)의 개념과 대응 방안을 설명하시오. (15점)

**✅ 모범 답안**:

#### 공급망 공격 개념 - 5점 ★★★

**정의**:
```
Supply Chain Attack (공급망 공격)

소프트웨어 개발, 배포, 업데이트 과정의
공급망을 침투하여 다수의 최종 사용자를 공격
```

**특징**:
```
- 신뢰를 악용 (Trusted Relationship)
- 대규모 피해 (1:N 공격)
- 탐지 어려움
- 정상 업데이트로 위장
```

**공격 대상**: ★★★
```
1. 소프트웨어 개발사
   - 소스 코드 저장소
   - 빌드 시스템
   - 코드 서명 인증서

2. 오픈소스 라이브러리
   - npm, PyPI, Maven 등
   - 악성 패키지 업로드

3. 업데이트 서버
   - 소프트웨어 업데이트 시스템
   - 패치 배포 채널

4. 하드웨어 제조사
   - 펌웨어 조작
   - 하드웨어 백도어
```

#### 주요 사례 - 3점

**SolarWinds 공격 (2020)**: ★★★
```
공격 과정:
1. SolarWinds Orion 빌드 시스템 침투
2. 정상 업데이트에 백도어 삽입
3. 18,000개 고객사에 배포
4. 미국 정부기관, 대기업 침해

영향:
- 대규모 피해
- 국가 안보 위협
- 신뢰 붕괴
```

**Log4Shell (2021)**:
```
- Log4j 라이브러리 제로데이 취약점
- 전 세계 수많은 시스템 영향
- 공급망 의존성 위험
```

**Codecov 공격 (2021)**:
```
- Codecov Bash Uploader 스크립트 조작
- 고객의 CI/CD 환경 침투
- 환경 변수, 인증 정보 탈취
```

#### 대응 방안 - 7점 ★★★

**1. SBOM (Software Bill of Materials)** - 2점 ★★★
```
정의:
소프트웨어 구성 요소 목록

포함 정보:
- 사용된 모든 라이브러리
- 버전 정보
- 라이선스
- 의존성 관계

용도:
- 취약점 영향 범위 파악

예시:

- Axios 1.3.0
```

```
- 지속적 모니터링
```

**4. SCA (Software Composition Analysis)** - 1점 ★★★
```
- 오픈소스 라이브러리 취약점 스캔
- 라이선스 검증
- 자동화된 검사

도구:
```

## 💡 파트 전체 핵심 요약

### 제로 트러스트 ★★★
```
핵심: "Never Trust, Always Verify"

3대 원칙:
1. 명시적 검증 (MFA, 디바이스, 행위)
2. 최소 권한 (JIT, JEA)
3. 침해 가정 (마이크로 세그먼테이션)
```

### EDR / XDR ★★★
```
EDR: 엔드포인트만
- 행위 기반 탐지
- 자동 격리/대응

XDR: 전방위 통합 (엔드포인트+네트워크+클라우드)
- 통합 가시성
- 상관 분석으로 전체 공격 체인 탐지
```

### SASE ★★
```
네트워크 + 보안 통합 클라우드 서비스

구성 요소:
- SD-WAN (네트워크)
- CASB, SWG, ZTNA, FWaaS (보안)
```

### SOAR ★★
```
보안 자동화 플랫폼

OAR:
- Orchestration (통합)
- Automation (자동화) ★★★
- Response (대응)

플레이북 기반 자동 대응
```

### DevSecOps ★★★
```
Shift Left: 보안을 개발 초기부터

- SAST: 정적 분석 (코드)
- DAST: 동적 분석 (실행)
- CI/CD 통합
```

### 공급망 보안 ★★
```
Supply Chain Attack:
- 신뢰 관계 악용
- 대규모 피해

대응:
- SBOM (구성 요소 목록) ★★★

- 코드 서명 검증
```
