# 개인정보보호법 - 실기 필수 암기

## 🔴 암호화 대상 및 방법 (법적 의무!)

### 일방향 암호화 (복호화 불가)
```
┌───────────────┬─────────────────┐
│    대상       │   암호화 방법    │
├───────────────┼─────────────────┤
│ 비밀번호      │  SHA-256 이상   │
│ 바이오정보    │  SHA-256 이상   │
│ (지문, 홍채)  │                 │
└───────────────┴─────────────────┘

특징: 일방향 해시 함수 사용
     복호화 불가능 (원본 복원 불가)
     Salt 추가 권장
     PBKDF2, bcrypt, Argon2 등 사용
```

### 양방향 암호화 (복호화 가능)
```
┌──────────────────────┬─────────────────┐
│        대상          │   암호화 방법    │
├──────────────────────┼─────────────────┤
│ 주민등록번호         │ AES, SEED, ARIA │
│ 여권번호             │ AES, SEED, ARIA │
│ 운전면허번호         │ AES, SEED, ARIA │
│ 외국인등록번호       │ AES, SEED, ARIA │
│ 신용카드번호         │ AES, SEED, ARIA │
│ 계좌번호             │ AES, SEED, ARIA │
└──────────────────────┴─────────────────┘

특징: 대칭키 암호 알고리즘
     안전한 키 관리 필수
     전송 시에도 암호화 필요
```

## 📝 기출 유형 1: 암호화 대상 및 방법

### 문제 1-1 (2023년 실기 - 최빈출!)
```
다음 개인정보 항목에 대한 적절한 암호화 방법을 쓰시오.

1) 사용자 로그인 비밀번호
2) 주민등록번호
3) 신용카드번호
```

**✅ 답안:**
```
1) 사용자 로그인 비밀번호
   - 암호화 방법: 일방향 해시 (SHA-256 이상)
   - 이유: 복호화가 불필요하며, 원본을 저장하지 않아야 함
   - 추가: Salt 적용 및 PBKDF2/bcrypt 사용 권장

2) 주민등록번호
   - 암호화 방법: 양방향 대칭키 암호화 (AES, SEED, ARIA)
   - 이유: 업무상 복호화가 필요한 경우가 있음
   - 주의: 안전한 키 관리 필수

3) 신용카드번호
   - 암호화 방법: 양방향 대칭키 암호화 (AES, SEED, ARIA)
   - 이유: 결제 처리 시 복호화 필요
```

## 📝 서술형: 패스워드 안전한 저장 방법

### 문제 6-1
```
웹 애플리케이션에서 사용자 패스워드를 안전하게
저장하는 방법을 단계별로 설명하시오.
```

**✅ 답안:**
```
1. 암호화 방법 선택
   - 일방향 해시 함수 사용 (SHA-256 이상)
   - 절대 평문 저장 금지
   - 양방향 암호화(AES 등) 사용 금지

2. Salt 추가
   - 사용자마다 고유한 랜덤 Salt 생성
   - Salt 길이: 16바이트 이상 권장
   - Salt는 평문으로 저장 가능 (DB에 함께 저장)

3. 반복 해싱
   - PBKDF2: 최소 10,000회 반복 (KISA 권장)
   - bcrypt: Cost Factor 10~12
   - Argon2: 메모리 하드 함수 (최신 권장)

4. 저장 형식 예시
   ┌──────────┬──────────────────┬─────────────────┐
   │ 사용자ID │      Salt        │   Hash 값       │
   ├──────────┼──────────────────┼─────────────────┤
   │ user01   │ random_salt_1234 │ hashed_password │
   └──────────┴──────────────────┴─────────────────┘

5. 로그인 검증
   입력 패스워드 + 저장된 Salt → 해시 생성
   → 저장된 Hash와 비교

6. 추가 보안
   - 패스워드 복잡도 요구 (길이, 문자 종류)
   - 패스워드 변경 주기 설정 (90일 권장)
   - 이전 패스워드 재사용 방지
```

## 📊 그림으로 이해하기

### 패스워드 저장 프로세스
```
[회원가입]
사용자 입력: "MyPassword123!"
     ↓
Salt 생성: "abc123xyz"
     ↓
결합: "MyPassword123!abc123xyz"
     ↓
PBKDF2 (10,000회 반복)
     ↓
최종 Hash: "a7f4b9e2c..."
     ↓
DB 저장:
┌────────┬──────────┬──────────────┐
│UserID  │  Salt    │    Hash      │
├────────┼──────────┼──────────────┤
│user01  │abc123xyz │a7f4b9e2c...  │
└────────┴──────────┴──────────────┘


[로그인]
사용자 입력: "MyPassword123!"
     ↓
DB에서 Salt 조회: "abc123xyz"
     ↓
결합: "MyPassword123!abc123xyz"
     ↓
PBKDF2 (10,000회 반복)
     ↓
계산된 Hash: "a7f4b9e2c..."
     ↓
DB Hash와 비교 → 일치하면 로그인 성공
```

### 암호화 vs 해시
```
[대칭키 암호화 - 양방향]
주민번호: 123456-1234567
   ↓ [AES 암호화, 키: secret_key]
암호문: a7b3f9e2...
   ↓ [AES 복호화, 키: secret_key]
주민번호: 123456-1234567 ← 복원 가능!


[해시 - 일방향]
패스워드: MyPassword123!
   ↓ [SHA-256 + Salt]
Hash: a7f4b9e2c1d3...
   ↓ [복호화 불가능!]
???  ← 원본 복원 불가능
```
