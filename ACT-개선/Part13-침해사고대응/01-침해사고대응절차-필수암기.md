**✅ 답안:**
```
1. Preparation (준비)

3. Containment (억제, 차단)
4. Eradication (근절, 제거)

### 문제 1-2 (각 단계 설명)
```
침해사고 대응 단계 중 "Containment (억제)" 단계에서
수행해야 할 활동을 3가지 이상 쓰시오.
```

**✅ 답안:**
```
Containment (억제) 단계 활동:

1. 단기 억제 (Short-term Containment)
   - 감염된 시스템 네트워크 차단
   - 해당 계정 비활성화
   - 방화벽 룰 추가 (공격 IP 차단)
   - 서비스 중지 (추가 감염 방지)

2. 장기 억제 (Long-term Containment)
   - 임시 패치 적용
   - 백업 시스템으로 전환
   - 모니터링 강화

3. 증거 수집 및 보존
   - 메모리 덤프 생성
   - 로그 파일 백업
   - 디스크 이미징
   - Chain of Custody (증거 관리 대장) 작성

구체적 예시:
┌─────────────────┬──────────────────────────┐
│   상황          │     억제 조치            │
├─────────────────┼──────────────────────────┤
│ 랜섬웨어 감염   │ 1. 감염 PC 네트워크 차단 │
│                 │ 2. 파일 공유 중지        │
│                 │ 3. 백업 서버 격리        │
├─────────────────┼──────────────────────────┤
│ DDoS 공격       │ 1. 공격 IP 차단          │
│                 │ 2. CDN 활성화            │
│                 │ 3. Rate Limiting 적용    │
├─────────────────┼──────────────────────────┤
│ 내부 정보 유출  │ 1. 해당 계정 잠금        │
│                 │ 2. 네트워크 모니터링     │
│                 │ 3. 외부 전송 차단        │
└─────────────────┴──────────────────────────┘
```

## 📝 기출 유형 2: 침해 징후 탐지 ★★

### 문제 2-1 (2022년 실기)
```
다음은 서버의 비정상 징후이다. 의심되는 공격과
확인해야 할 사항을 쓰시오.

징후:
- CPU 사용률 100% 지속
- 네트워크 트래픽 급증 (평소의 50배)
- 알 수 없는 프로세스 다수 실행 중
```

**✅ 답안:**
```
의심되는 공격:

1차 의심: DDoS 공격 또는 좀비 PC (봇넷)
- CPU 100%: 공격 트래픽 처리 또는 공격 수행
- 네트워크 급증: DDoS 공격 대상 또는 공격 수행
- 알 수 없는 프로세스: 악성코드 또는 봇

2차 의심: 암호화폐 채굴 악성코드 (Cryptominer)
- CPU 100%: 채굴 작업
- 네트워크 급증: 채굴 풀 서버와 통신

확인해야 할 사항:

1. 프로세스 확인
   Linux: ps aux | grep -v root
         top (CPU 사용률 높은 프로세스)
         lsof -i (네트워크 연결 프로세스)

   Windows: tasklist
           Resource Monitor (리소스 모니터)

   확인 내용:
   - 프로세스 이름 (정상 프로세스인지)
   - 실행 경로 (/tmp, C:\Users\%USERNAME%\AppData는 의심)
   - 실행 사용자 (root, SYSTEM으로 실행 시 위험)

2. 네트워크 연결 확인
   Linux: netstat -anp | grep ESTABLISHED
         ss -tulpn

   Windows: netstat -ano
           TCPView (Sysinternals)

   확인 내용:
   - 외부 연결 IP 및 포트
   - 알 수 없는 국가 IP (중국, 러시아 등)
   - 비정상 포트 (IRC 6667, P2P 포트 등)

3. 로그 분석
   - /var/log/auth.log (인증 로그)
   - /var/log/secure (SSH 로그)
   - Windows 이벤트 로그 (이벤트 ID 4625, 4720 등)

   확인 내용:
   - 비정상 로그인 시도
   - 신규 계정 생성 (백도어)
   - 권한 변경

4. 파일 무결성 검사
   - 시스템 파일 변조 여부
   - 웹 셸 존재 여부 (/var/www/html/)
   - 최근 생성/수정된 파일 확인

   find / -mtime -1 -type f (1일 내 수정 파일)

5. 안티바이러스 검사
   - 전체 시스템 스캔
   - 정의 파일 최신 업데이트 후 재검사

즉시 조치:
1. 의심 프로세스 중지: kill -9 [PID]
2. 네트워크 격리 (Containment)
3. 메모리 덤프 및 로그 백업 (증거 보존)
```

## 📝 기출 유형 3: 증거 수집 및 보존 ★★

### 문제 3-1 (2023년 실기)
```
디지털 포렌식 증거 수집 시 지켜야 할 원칙과
증거 수집 우선순위를 설명하시오.
```

**✅ 답안:**
```
증거 수집 원칙:

1. 무결성 (Integrity)
   - 원본 데이터 훼손 금지
   - 해시값으로 무결성 검증 (MD5, SHA-256)
   - Write Blocker 사용 (쓰기 방지)

2. 정당성 (Legality)
   - 적법한 절차에 따라 수집
   - 영장 또는 권한 확인
   - 수집 과정 문서화

3. 재현성 (Reproducibility)
   - 동일한 결과 재현 가능
   - 수집 도구 및 절차 기록

4. 연속성 (Chain of Custody)
   - 증거 관리 대장 작성
   - 수집 → 보관 → 분석 → 법정 제출까지 추적 가능
   - 담당자, 일시, 장소 기록


증거 수집 우선순위 (휘발성 순서):

RFC 3227 기준 - 휘발성이 높은 순서대로 수집 ★★★

1순위: CPU 레지스터, 캐시
   - 가장 빠르게 소멸
   - 수집 방법: 메모리 덤프 도구

2순위: 라우팅 테이블, ARP 캐시, 프로세스 테이블, 커널 통계
   - 시스템 재부팅 시 소멸
   - 수집 명령어:
     netstat -rn (라우팅 테이블)
     arp -a (ARP 캐시)
     ps aux (프로세스 목록)

3순위: 메모리 (RAM)
   - 휘발성 메모리
   - 전원 꺼지면 소멸
   - 수집 도구: FTK Imager, Volatility, dd

4순위: 임시 파일 시스템
   - /tmp, Swap 파일
   - 재부팅 또는 시간 경과 시 삭제

5순위: 하드 디스크 (비휘발성 저장 장치)
   - 상대적으로 안정적
   - 수집 방법: 디스크 이미징 (dd, EnCase)

6순위: 로그 파일, 백업 데이터
   - 원격지 백업 (가장 안정적)
   - 수집 방법: 복사 및 해시 확인


수집 절차 예시:

[Live Response - 시스템 가동 중]
1. 메모리 덤프 생성
   dd if=/dev/mem of=/mnt/usb/memory.img
   또는 FTK Imager 사용

2. 휘발성 데이터 수집
   date > /mnt/usb/evidence.txt
   netstat -anp >> /mnt/usb/evidence.txt
   ps aux >> /mnt/usb/evidence.txt
   arp -a >> /mnt/usb/evidence.txt
   lsof >> /mnt/usb/evidence.txt

3. 해시값 생성
   md5sum memory.img > memory.img.md5
   sha256sum memory.img > memory.img.sha256

[Post-mortem - 시스템 종료 후]
4. 디스크 이미징
   - Write Blocker 연결
   - dd if=/dev/sda of=/mnt/evidence/disk.img bs=4096
   - 해시값 생성 및 비교

5. Chain of Custody 작성
   ┌──────────────┬────────────────┬──────────┐
   │  증거물      │   담당자       │   일시   │
   ├──────────────┼────────────────┼──────────┤
   │ memory.img   │ 홍길동 (수집)  │ 14:00    │
   │ memory.img   │ 김철수 (보관)  │ 14:30    │
   │ memory.img   │ 이영희 (분석)  │ 15:00    │
   └──────────────┴────────────────┴──────────┘
```

## 📝 기출 유형 4: 랜섬웨어 대응 ★★★

### 문제 4-1 (2023년 실기)
```
랜섬웨어에 감염된 것으로 의심되는 PC가 발견되었다.
침해사고 대응 절차에 따라 취해야 할 조치를 단계별로 쓰시오.
```

**✅ 답안:**
```
랜섬웨어 침해사고 대응 절차:

1단계: Identification (탐지 및 식별)
   □ 랜섬노트 파일 확인 (README.txt, HOW_TO_DECRYPT.html)
   □ 파일 확장자 변경 확인 (.encrypt, .locked, .crypted 등)
   □ 감염 범위 파악 (로컬 PC만? 네트워크 공유 폴더?)
   □ 랜섬웨어 종류 식별 (No More Ransom 사이트 활용)

2단계: Containment (억제, 차단) ★ 최우선!
   □ 즉시 네트워크 차단
      - 유선: 랜선 제거
      - 무선: Wi-Fi 비활성화
      - 목적: 추가 감염 및 전파 방지

   □ 감염 PC 전원 유지 (끄지 말 것!)
      - 이유: 메모리에 복호화 키 존재 가능
      - 메모리 덤프 필요 시 전원 켜진 상태 유지

   □ 다른 시스템 격리
      - 동일 네트워크의 다른 PC 점검
      - 파일 서버, NAS 격리

   □ 백업 서버 즉시 오프라인 전환
      - 백업까지 암호화되면 복구 불가

3단계: Eradication (근절, 제거)
   □ 안티바이러스 검사
      - 정의 파일 최신 업데이트 (USB 이용)
      - 전체 시스템 스캔

   □ 악성코드 제거
      - 랜섬웨어 실행 파일 삭제
      - 레지스트리 자동 실행 항목 제거
        HKLM\Software\Microsoft\Windows\CurrentVersion\Run

   □ 취약점 패치
      - Windows 보안 업데이트
      - 서비스 최신 버전 업데이트

4단계: Recovery (복구)
   □ 복구 우선순위 결정
      1순위: 백업에서 복구 (가장 안전)
      2순위: 복호화 도구 시도 (No More Ransom)
      3순위: 시스템 재설치

   □ 백업에서 복구
      - 감염 전 백업 시점 확인
      - 백업 무결성 검증
      - 복구 후 악성코드 재검사

   □ 복호화 시도 (가능한 경우)
      - No More Ransom Project 확인
        (https://www.nomoreransom.org/)
      - 무료 복호화 도구 존재 여부 확인

   □ 시스템 모니터링 강화
      - 재감염 여부 확인 (1주일)
      - 이상 징후 모니터링

5단계: Lessons Learned (사후 분석)
   □ 침투 경로 분석
      - 피싱 메일? 취약점? RDP 무차별 대입?

   □ 재발 방지 대책
      - 백업 정책 강화 (3-2-1 백업)
        * 3개 복사본
        * 2개 다른 매체
        * 1개 오프사이트
      - 이메일 보안 강화 (첨부파일 차단)
      - RDP 비활성화 또는 VPN 필수화
      - 사용자 보안 교육 실시

   □ 보고서 작성
      - 사고 경위
      - 피해 규모
      - 대응 조치
      - 개선 사항


절대 하지 말아야 할 행동:
✗ 몸값 지불 (복호화 보장 없음, 추가 공격 표적)
✗ 즉시 전원 끄기 (메모리 증거 소멸)
✗ 파일 복구 시도 후 재부팅 (증거 훼손)


체크리스트:
□ 네트워크 차단했는가?
□ 백업 서버 격리했는가?
□ 증거 수집 완료했는가?
□ 악성코드 제거 확인했는가?
□ 재감염 방지 조치 완료했는가?
```

## 🎯 침해사고 대응 핵심 암기 카드

### 카드 1: NIST 6단계 (최빈출!)
```
1. Preparation (준비)
2. Identification (탐지/식별)
3. Containment (억제/차단) ★ 즉시 조치!
4. Eradication (근절/제거)
5. Recovery (복구)
6. Lessons Learned (사후분석)

암기: "준탐억근복사"
```

### 카드 2: 증거 수집 우선순위 (RFC 3227)
```
휘발성 높은 순서:
1. CPU, 캐시
2. 라우팅 테이블, ARP, 프로세스
3. 메모리 (RAM) ★★
4. 임시 파일
5. 하드 디스크
6. 로그, 백업

메모리 먼저, 디스크 나중!
```

### 카드 3: 랜섬웨어 대응 3대 원칙
```
1. 즉시 네트워크 차단 (전파 방지)
2. 전원 끄지 말기 (메모리 보존)
3. 백업 격리 (2차 피해 방지)

절대 금지: 몸값 지불!
```

### 카드 4: Chain of Custody (증거 관리)
```
증거물 → 수집 → 보관 → 분석 → 법정

각 단계마다 기록:
- 담당자 이름
- 날짜 및 시간
- 수행 작업
- 해시값 (무결성)
```

[2. Identification - 사고 발생]
   │
   ├─ IDS/IPS 경보
   ├─ 로그 분석
   ├─ 사용자 신고
   └─ 이상 징후 탐지
   │
   ▼
   사고 판단 (True/False Positive?)
   │
   ▼
[3. Containment - 긴급 대응]
   │
   ├─ 단기 억제
   │   ├─ 네트워크 차단
   │   ├─ 계정 잠금
   │   └─ 방화벽 차단
   │
   ├─ 증거 수집
   │   ├─ 메모리 덤프
   │   ├─ 디스크 이미징
   │   └─ 로그 백업
   │
   └─ 장기 억제
       ├─ 임시 패치
       └─ 백업 시스템 전환
   │
   ▼
[4. Eradication - 원인 제거]
   │
   ├─ 악성코드 삭제
   ├─ 취약점 패치
   ├─ 계정 재설정
   └─ 시스템 강화
   │
   ▼
[5. Recovery - 정상화]
   │
   ├─ 시스템 복구
   ├─ 서비스 재개
   ├─ 모니터링 강화
   └─ 재발 여부 확인
   │
   ▼
[6. Lessons Learned - 개선]
   │
   ├─ 사고 분석 보고서
   ├─ 재발 방지 대책
   ├─ 정책 및 절차 개선
   └─ 교육 훈련 실시
   │
   ▼
   다시 Preparation으로 순환
```

### 랜섬웨어 대응 타임라인
```
[T+0분: 감염 발견]
   랜섬노트 발견, 파일 암호화 확인
   │
   ▼
[T+5분: 즉시 차단]
   ✓ 랜선 제거 (네트워크 차단)
   ✓ 백업 서버 격리
   ✓ 관련 부서 비상 소집
   │
   ▼
[T+10분: 증거 수집]
   ✓ 메모리 덤프
   ✓ 프로세스 목록 백업
   ✓ 네트워크 연결 기록
   ✓ 사진 촬영 (화면, 랜섬노트)
   │
   ▼
[T+30분: 피해 범위 파악]
   ✓ 감염 PC 대수 확인
   ✓ 암호화된 파일 목록
   ✓ 백업 상태 확인
   ✓ 랜섬웨어 종류 식별
   │
   ▼
[T+1시간: 복구 계획 수립]
   ✓ 복구 우선순위 결정
   ✓ 백업 가용성 확인
   ✓ 복호화 도구 검색 (No More Ransom)
   │
   ▼
[T+2시간: 복구 시작]
   ✓ 악성코드 제거
   ✓ 백업에서 데이터 복원
   ✓ 또는 시스템 재설치
   │
   ▼
[T+1일: 모니터링]
   ✓ 재감염 여부 확인
   ✓ 시스템 정상 작동 확인
   │
   ▼
[T+1주: 사후 분석]
   ✓ 침투 경로 분석
   ✓ 재발 방지 대책
   ✓ 보고서 작성
```

## 💡 실기 답안 작성 팁

### Tip 1: 단계는 영문과 한글 모두 가능
```
✅ Identification (탐지 및 식별)
✅ 탐지 및 식별
✅ Identification

채점 기준에 따라 영문/한글 모두 정답
```

### Tip 2: 순서가 중요!
```
✅ 1.Preparation → 2.Identification → 3.Containment ...

❌ 1.Recovery → 2.Containment ... (순서 틀림)

Containment는 반드시 Identification 다음!
```

### Tip 3: 구체적인 조치 작성
```
문제: "Containment 단계 조치는?"

✅ 감염 PC 네트워크 차단 (랜선 제거)
   방화벽에서 공격 IP 차단
   해당 계정 비활성화

❌ 차단 조치 (구체성 부족)
```

### Tip 4: 증거 수집 시 휘발성 순서
```
✅ 메모리 (휘발성 높음) → 디스크 (휘발성 낮음)

❌ 디스크 먼저, 메모리 나중 (틀림!)

전원 꺼지면 메모리 소멸!
```
