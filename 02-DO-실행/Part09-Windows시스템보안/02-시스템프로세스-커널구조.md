# 시스템 프로세스 및 커널 구조

## 🔴 svchost.exe ★★★

### 문제 (2024년 기출)
```
svchost.exe 프로세스의 역할과 악성코드 위장 탐지 방법은?
```

### ✅ 정답
```
svchost.exe (Service Host)

역할: ★★★
Windows 서비스를 호스팅하는 프로세스
여러 서비스가 하나의 svchost.exe에서 실행

특징:
- 정상적으로 여러 개 실행됨 ★★★
- DLL 형태의 서비스 로드
- 시스템 계정으로 실행

정상 경로:
C:\Windows\System32\svchost.exe ★★★

정상 실행 예시:
svchost.exe -k netsvcs
            ↑
         서비스 그룹

주요 서비스 그룹:
- netsvcs: 네트워크 서비스
- LocalService: 로컬 서비스
- NetworkService: 네트워크 서비스
- DcomLaunch: DCOM 서비스

확인 방법:

1. 작업 관리자 (Task Manager)
   - 여러 개의 svchost.exe 정상 ★★
   - "세부 정보" 탭에서 경로 확인

2. Process Explorer (Sysinternals) ★★★
   - svchost.exe 우클릭 → Properties
   - Services 탭: 호스팅하는 서비스 목록
   - Image 탭: 경로 확인

3. 명령어
   tasklist /svc
   → svchost.exe와 호스팅하는 서비스 표시

악성코드 위장 탐지: ★★★

1. 경로 확인 ★★★
   ✅ 정상: C:\Windows\System32\svchost.exe
   ✗ 의심:
   - C:\Windows\svchost.exe (System32 아님!)
   - C:\Windows\Temp\svchost.exe
   - C:\Users\...\svchost.exe

2. 철자 확인
   ✗ 의심:
   - svch0st.exe (0은 숫자)
   - scvhost.exe
   - svchost32.exe

3. 부모 프로세스 확인 ★★★
   ✅ 정상: services.exe (부모)
   ✗ 의심: explorer.exe, 사용자 프로세스

4. 사용자 계정 확인
   ✅ 정상:
   - SYSTEM
   - LOCAL SERVICE
   - NETWORK SERVICE

   ✗ 의심: 일반 사용자 계정

5. 연결 확인
   netstat -ano | findstr [PID]
   → 의심스러운 외부 연결

6. 디지털 서명 확인
   ✅ 정상: Microsoft Corporation
   ✗ 의심: 서명 없음

Process Explorer로 확인:
1. svchost.exe 우클릭 → Properties
2. Image 탭:
   - Path: C:\Windows\System32\svchost.exe
   - Company Name: Microsoft Corporation
   - Verified Signer: Microsoft Windows

3. Services 탭:
   - 호스팅 서비스 목록 (정상적인 서비스명)

4. Threads 탭:
   - DLL 로드 확인

악성코드 예시:
- Conficker: svchost.exe 위장
- Zeus: svchost.exe로 인젝션
```

## 🔴 csrss.exe ★★★

### 문제 (2024년 기출)
```
csrss.exe 프로세스의 역할은?
```

### ✅ 정답
```
csrss.exe (Client/Server Runtime Subsystem)

역할: ★★★
Windows 콘솔 및 GUI 서브시스템 관리
필수 시스템 프로세스

주요 기능:
- 콘솔 창 관리
- 프로세스 및 스레드 생성/종료
- 16비트 가상 DOS 머신 (VDM) 지원
- 셧다운 프로세스

특징:
- Windows 부팅 시 자동 실행 ★★★
- 종료 불가 (시스템 크래시) ★★★
- SYSTEM 권한으로 실행

정상 경로:
C:\Windows\System32\csrss.exe ★★★

개수:
- Windows 7 이하: 1개
- Windows 8 이상: 2개 이상 ★★
  · 세션 0: 시스템 서비스용
  · 세션 1: 사용자 세션용

확인 방법:

1. Process Explorer
   - Path: C:\Windows\System32\csrss.exe
   - Parent: smss.exe (Session Manager) ★★★
   - User: SYSTEM

2. 부모 프로세스 확인
   ✅ 정상: smss.exe
   ✗ 의심: 다른 프로세스

3. 경로 확인
   ✅ 정상: C:\Windows\System32\csrss.exe
   ✗ 의심: System32 아닌 경로

악성코드 위장 탐지:

1. 경로 ★★★
   ✗ C:\Windows\csrss.exe (System32 아님!)
   ✗ C:\csrss.exe
   ✗ C:\Temp\csrss.exe

2. 철자
   ✗ crss.exe (철자 오류)
   ✗ cssrs.exe

3. 종료 가능 여부
   ✗ 정상 csrss.exe는 종료 불가
   ✗ 종료 가능하면 가짜!

4. 부모 프로세스
   ✅ smss.exe
   ✗ explorer.exe, 사용자 프로세스

5. 디지털 서명
   ✅ Microsoft Corporation
```

## 🔴 EPROCESS 구조 ★★

### 문제 (2024년 기출)
```
Windows 커널의 EPROCESS 구조체란?
```

### ✅ 정답
```
EPROCESS (Executive Process)

정의:
Windows 커널에서 프로세스를 나타내는 구조체

위치:
커널 메모리 공간 (User Mode에서 접근 불가)

주요 필드: ★★★

1. UniqueProcessId (PID)
   - 프로세스 ID
   - 시스템 내 고유 번호

2. ImageFileName
   - 실행 파일 이름 (최대 15자)
   - 예: "notepad.exe"

3. ActiveProcessLinks
   - 프로세스 리스트 연결
   - 이중 연결 리스트 (Doubly Linked List) ★★

4. Token
   - 보안 토큰 (권한, SID 등)
   - SeTokenObjectType

5. ObjectTable
   - 핸들 테이블
   - 파일, 레지스트리 핸들 등

6. VadRoot
   - VAD (Virtual Address Descriptor) 트리
   - 가상 메모리 영역 정보

7. InheritedFromUniqueProcessId
   - 부모 프로세스 PID ★★

8. CreateTime
   - 프로세스 생성 시간

9. ExitTime
   - 프로세스 종료 시간

10. Pcb (KPROCESS)
    - 프로세스 제어 블록
    - 스케줄링 정보

구조:
┌────────────────────────────┐
│ EPROCESS                   │
├────────────────────────────┤
│ UniqueProcessId (PID)      │
│ ImageFileName              │
│ ActiveProcessLinks ──┐     │
│ Token                │     │
│ ObjectTable          │     │
│ VadRoot              │     │
│ InheritedFromPPID    │     │
│ ...                  │     │
└──────────────────────┼─────┘
                       │
            ┌──────────▼──────────┐
            │ 다음 EPROCESS       │
            │ (이중 연결 리스트) │
            └─────────────────────┘

포렌식 활용: ★★★

1. 프로세스 목록 추출
   - ActiveProcessLinks 따라가기
   - PsActiveProcessHead (커널 변수)

2. 숨겨진 프로세스 탐지 ★★★
   - EPROCESS 리스트 vs pslist 비교
   - Direct Kernel Object Manipulation (DKOM) 탐지

   정상:
   pslist 출력 = EPROCESS 리스트

   루트킷:
   pslist에 없지만 EPROCESS에 존재
   → ActiveProcessLinks 조작

3. 부모-자식 관계 파악
   - InheritedFromUniqueProcessId
   - 프로세스 트리 재구성

4. 프로세스 생성 시간 확인
   - CreateTime, ExitTime
   - 타임라인 분석

Volatility 사용:

프로세스 목록 (EPROCESS 순회):
volatility -f memory.dmp --profile=Win7SP1x64 pslist

숨겨진 프로세스 탐지:
volatility -f memory.dmp --profile=Win7SP1x64 psscan
→ EPROCESS 시그니처 스캔 ★★★

프로세스 트리:
volatility -f memory.dmp --profile=Win7SP1x64 pstree

관련 구조체:

- KPROCESS (PCB):
  스케줄링, CPU 상태

- ETHREAD:
  스레드 구조체
  각 프로세스는 여러 ETHREAD 포함

- PEB (Process Environment Block):
  User Mode 프로세스 정보
  명령줄, 환경 변수, 로드된 DLL
```

## 🔴 Android 4대 컴포넌트 ★★★

### 문제 (2024년 기출)
```
Android의 4대 컴포넌트는?
```

### ✅ 정답
```
Android 4대 컴포넌트 (Application Components)

1. Activity ★★★

역할:
사용자 인터페이스 화면 하나

특징:
- 앱의 진입점
- UI 표시 및 사용자 입력 처리
- 생명주기 (Lifecycle) 존재
  onCreate() → onStart() → onResume() → ... → onDestroy()

예시:
- 로그인 화면
- 메인 화면
- 설정 화면

선언:
AndroidManifest.xml에 등록 필수 ★★

<activity android:name=".MainActivity">
  <intent-filter>
    <action android:name="android.intent.action.MAIN" />
  </intent-filter>
</activity>

2. Service ★★★

역할:
백그라운드 작업 수행 (UI 없음)

특징:
- 장시간 작업
- 백그라운드 실행
- UI 없음

예시:
- 음악 재생
- 파일 다운로드
- 네트워크 통신

유형:
- Foreground Service: 알림 표시
- Background Service: 백그라운드 작업
- Bound Service: 다른 컴포넌트와 바인딩

악용:
악성코드가 백그라운드에서 지속 실행 ★★

3. Broadcast Receiver ★★★

역할:
시스템 또는 앱의 브로드캐스트 메시지 수신

특징:
- 이벤트 리스너
- 앱 간 통신
- 시스템 이벤트 수신

예시 이벤트:
- 부팅 완료 (BOOT_COMPLETED) ★★★
- 배터리 부족 (BATTERY_LOW)
- 네트워크 연결 변경
- SMS 수신

악용:
악성코드가 BOOT_COMPLETED로 자동 실행 ★★★

<receiver android:name=".BootReceiver">
  <intent-filter>
    <action android:name="android.intent.action.BOOT_COMPLETED" />
  </intent-filter>
</receiver>

4. Content Provider ★★

역할:
데이터 공유 (앱 간 데이터 접근)

특징:
- 구조화된 데이터 제공
- URI 기반 접근
- SQLite DB, 파일 등

예시:
- 연락처 (Contacts)
- 미디어 (Media Store)
- 달력 (Calendar)

URI 형식:
content://com.example.app/users/1

악용:
권한 없는 데이터 접근 취약점 ★★

비교:
┌────────────────┬──────────────┬──────────────┐
│   컴포넌트     │     역할     │   UI 여부    │
├────────────────┼──────────────┼──────────────┤
│ Activity       │ 화면 표시    │ O ★★★      │
├────────────────┼──────────────┼──────────────┤
│ Service        │ 백그라운드   │ X ★★★      │
├────────────────┼──────────────┼──────────────┤
│ Broadcast      │ 이벤트 수신  │ X ★★       │
│ Receiver       │              │              │
├────────────────┼──────────────┼──────────────┤
│ Content        │ 데이터 공유  │ X           │
│ Provider       │              │              │
└────────────────┴──────────────┴──────────────┘

보안 고려사항:

1. AndroidManifest.xml 분석 ★★★
   - 권한 (Permission) 확인
   - Exported 컴포넌트 확인
     android:exported="true" → 외부 앱 접근 가능 (위험!)

2. 권한 악용
   - 과도한 권한 요청
   - BOOT_COMPLETED (자동 실행) ★★
   - SEND_SMS (SMS 발송)
   - READ_CONTACTS (연락처 탈취)

3. Intent 필터링
   - Intent: 컴포넌트 간 메시지
   - 검증 없이 Intent 처리 → 취약점

악성코드 분석:

도구:
- APKTool (디컴파일) ★★★
  apktool d app.apk

- dex2jar (DEX → JAR 변환)
- JD-GUI (자바 디컴파일러)
- Jadx (올인원 디컴파일러)

분석 순서:
1. AndroidManifest.xml 확인
   - 권한 목록
   - 4대 컴포넌트 선언
   - Exported 여부

2. 소스 코드 분석
   - 네트워크 통신 (C&C)
   - 민감 정보 수집
   - 백그라운드 Service

3. 동적 분석
   - 에뮬레이터 실행
   - Logcat 모니터링
   - 네트워크 트래픽 (Wireshark)
```

## 🔴 SCADA / Stuxnet ★★★

### 문제 (2024년 기출)
```
SCADA 시스템과 Stuxnet 웜의 특징은?
```

### ✅ 정답
```
SCADA (Supervisory Control And Data Acquisition)
= 감시 제어 데이터 수집 시스템

정의:
산업 제어 시스템 (ICS)의 한 유형
원격으로 시설을 감시하고 제어

사용 분야:
- 발전소 (원자력, 화력)
- 수처리 시설
- 석유/가스 파이프라인
- 제조업 (공장 자동화)
- 교통 시스템

구성 요소:

1. HMI (Human-Machine Interface)
   - 운영자 인터페이스
   - 모니터링 및 제어

2. PLC (Programmable Logic Controller) ★★★
   - 프로그래밍 가능한 제어기
   - 센서/액추에이터 제어

3. RTU (Remote Terminal Unit)
   - 원격 데이터 수집
   - 센서 데이터 전송

4. 통신 네트워크
   - SCADA 서버 ↔ RTU/PLC

5. SCADA 서버
   - 데이터 수집 및 저장
   - 명령 전송

프로토콜:
- Modbus ★★
- DNP3
- OPC (OLE for Process Control)

보안 취약점:

1. 레거시 시스템
   - 구형 OS (Windows XP 등)
   - 패치 어려움 ★★

2. 네트워크 격리 부족
   - 인터넷 연결
   - 내부 네트워크와 연결

3. 인증 부재
   - 기본 패스워드
   - 약한 인증

4. 암호화 부재
   - 평문 통신
   - 프로토콜 보안 취약

Stuxnet 웜 (2010년) ★★★

목적:
이란 나탄즈 우라늄 농축 시설 공격
원심분리기 파괴

특징:

1. 제로데이 취약점 4개 악용 ★★★
   - Windows 취약점
   - .Lnk 파일 취약점 (CVE-2010-2568) ★★
   - 프린터 스풀러 취약점

2. USB 전파 ★★★
   - .Lnk 파일 자동 실행
   - 격리 네트워크 침투

3. PLC 타겟팅 ★★★
   - Siemens Step7 (PLC 프로그래밍 소프트웨어)
   - 원심분리기 속도 조작
   - 정상처럼 위장 (HMI에는 정상 표시)

4. 디지털 서명 위조
   - Realtek, JMicron 인증서 도용
   - 정상 드라이버처럼 위장

5. 루트킷 기능
   - 자신을 숨김
   - 탐지 회피

공격 흐름:

1. USB 삽입
   ↓
2. .Lnk 취약점으로 실행
   ↓
3. Windows 제로데이로 권한 상승
   ↓
4. 네트워크 전파 (SMB, 프린터 스풀러)
   ↓
5. Siemens Step7 탐색
   ↓
6. PLC 코드 조작 ★★★
   (원심분리기 속도 변경)
   ↓
7. HMI에는 정상 표시
   (운영자는 모름)

영향:
- 이란 원심분리기 약 1,000대 파괴
- 핵 개발 지연
- 사이버 전쟁의 시작 ★★★

SCADA 보안 대책:

1. 네트워크 세그먼테이션 ★★★
   - OT(운영 기술)와 IT 네트워크 분리
   - Air Gap (물리적 격리)

2. 화이트리스팅
   - 승인된 프로그램만 실행

3. 패치 관리
   - 테스트 후 적용
   - 가상 패치 (IPS)

4. USB 제어 ★★
   - USB 비활성화
   - 승인된 USB만 허용

5. 모니터링
   - IDS/IPS
   - 이상 행위 탐지

6. 인증 강화
   - 2FA
   - 기본 패스워드 변경

7. 백업
   - PLC 코드 백업
   - 신속 복구
```

## 🔴 기타 시스템 개념 ★

### 추가 개념

```
1. SDR (Software Defined Radio)
   정의: 소프트웨어로 무선 통신 구현
   용도:
   - 무선 신호 분석
   - 해킹: 차량 키리스 엔트리 복제
   - 방어: 무선 침입 탐지

2. Secure Boot ★★
   정의: 부팅 시 디지털 서명 검증
   목적: 루트킷 방지
   구현:
   - UEFI Secure Boot
   - TPM 연동

3. /etc/shadow (Linux) ★★★
   역할: 암호화된 패스워드 저장
   권한: root만 읽기 가능 (000)
   형식:
   username:$6$salt$hash:lastchange:min:max:warn:inactive:expire

   $6$: SHA-512 해시 ★★

4. Windows Registry 주요 키
   HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Run
   → 시작 프로그램 ★★★

   HKLM\SYSTEM\CurrentControlSet\Services
   → 서비스 등록

   HKCU\Software
   → 사용자별 설정
```
