# Part 6. 암호화 - 서술형 실전 답안

> **시험 출제 비중**: ★★★ (매년 8-12문항)
> **문제 유형**: 비교, 개념 설명, 계산
> **평균 배점**: 6-8점

---

## 📝 유형 1: 비교/대조형 ★★★

### 문제 1-1: 대칭키 암호화와 비대칭키 암호화를 비교 설명하시오 (8점)

**✅ 모범 답안**:
```
[대칭키 암호화 (Symmetric Key Cryptography)]
정의: 암호화와 복호화에 동일한 키 사용

특징:
- 빠른 속도 (하드웨어 가속 가능)
- 키 길이 짧음 (128, 256비트)
- 키 교환 문제 (사전에 안전하게 공유 필요)
- 키 관리 부담 (n명 = n(n-1)/2 개 키)

알고리즘:
- 국정원 검증: ARIA, SEED, LEA, HIGHT
- 국제 표준: AES, DES, 3DES, RC4

용도:
- 대용량 데이터 암호화
- 파일 암호화
- 디스크 암호화
- VPN 터널 암호화

[비대칭키 암호화 (Asymmetric Key Cryptography)]
정의: 공개키로 암호화, 개인키로 복호화 (또는 반대)

특징:
- 느린 속도 (수학 연산 복잡)
- 키 길이 긺 (2048, 4096비트)
- 안전한 키 교환 (공개키는 공개 가능)
- 키 관리 용이 (n명 = n쌍)

알고리즘:
- RSA (Rivest-Shamir-Adleman)
- ECC (Elliptic Curve Cryptography)
- ElGamal
- DSA (Digital Signature Algorithm)

용도:
- 키 교환 (대칭키 전달)
- 전자서명
- 인증서
- SSL/TLS Handshake

[하이브리드 방식] ★★★
실무에서는 두 방식 조합:
1. 비대칭키로 대칭키 교환 (안전)
2. 대칭키로 데이터 암호화 (빠름)

예시: SSL/TLS, PGP, S/MIME
```

**채점 기준**:
- 대칭키 특징 (3점)
- 비대칭키 특징 (3점)
- 차이점 명확히 구분 (2점)

### 문제 1-2: 블록 암호 모드 중 ECB, CBC, CTR 모드를 비교하시오 (9점)

**✅ 모범 답안**:
```
[ECB (Electronic CodeBook) 모드]
방식:
- 평문을 블록 단위로 나눠 각각 독립적으로 암호화
- 같은 평문 블록 → 같은 암호문 블록

장점:
- 간단하고 빠름
- 병렬 처리 가능
- 오류 전파 없음

단점: ★★★
- 패턴 노출 (같은 블록 → 같은 암호문)
- 보안성 낮음
- 실무 사용 금지 (사용하면 감점!)

적용: 사용 금지

[CBC (Cipher Block Chaining) 모드] ★★★
방식:
- 이전 암호문 블록을 다음 평문 블록과 XOR
- 첫 블록은 IV(Initialization Vector)와 XOR
- C₁ = E(P₁ ⊕ IV)
- C₂ = E(P₂ ⊕ C₁)

장점:
- 패턴 은닉 (같은 평문 → 다른 암호문)
- 보안성 높음
- 가장 많이 사용

단점:
- 순차 처리 (병렬화 불가)
- 오류 전파 (1블록 오류 → 2블록 영향)

적용:
- 파일 암호화
- 디스크 암호화
- SSL/TLS

[CTR (Counter) 모드]
방식:
- Counter 값을 암호화하여 평문과 XOR
- Counter는 블록마다 증가 (Nonce + Counter)
- C₁ = P₁ ⊕ E(Counter₁)

장점:
- 병렬 처리 가능 (빠름)
- 오류 전파 없음 (1블록만 영향)
- 스트림 암호처럼 동작
- Random Access 가능

단점:
- Counter 재사용 금지 (같은 Counter → 보안 취약)
- Nonce 관리 필요

적용:
- 고속 통신
- IPSec
- WPA2

[비교표]
모드   패턴은닉   병렬화   오류전파   보안성
ECB     X         O       없음     낮음
CBC     O         X       2블록    높음
CTR     O         O       1블록    높음

[IV (Initialization Vector) 중요성] ★★★
- CBC, CTR 모두 IV/Nonce 필요
- 매번 다른 값 사용 (재사용 금지)
- 예측 불가능해야 함
- 암호문과 함께 전송 (평문 전송 가능)
```

**채점 기준**:
- ECB 설명 (2점)
- CBC 설명 (3점)
- CTR 설명 (2점)
- 비교 및 차이점 (2점)

---

### 문제 1-3: 해시(Hash)와 MAC(Message Authentication Code)의 차이를 설명하시오 (6점)

**✅ 모범 답안**:
```
[해시 (Hash)]
정의:
입력 데이터를 고정 길이 값으로 변환하는 단방향 함수

특징:
- 일방향성: 해시 → 원문 복원 불가능
- 고정 길이 출력 (SHA-256 → 256비트)
- 같은 입력 → 같은 출력 (결정론적)
- 키 불필요

알고리즘:
- SHA-256, SHA-512 (안전)
- MD5, SHA-1 (취약, 사용 금지)

용도:
- 파일 무결성 검증
- 패스워드 저장 (해시+솔트)
- 디지털 지문

문제점:
- 송신자 인증 불가
- 중간자가 데이터+해시 둘 다 변조 가능

[MAC (Message Authentication Code)]
정의:
메시지와 비밀키를 입력으로 하는 인증 코드

특징:
- 비밀키 사용 ★★★
- 송신자 인증 가능
- 무결성 + 인증 동시 제공

알고리즘:
- HMAC (Hash-based MAC) ★★★
  HMAC = Hash(Key ∥ Message)
- CMAC (Cipher-based MAC)

용도:
- 메시지 인증
- 네트워크 프로토콜 (IPSec, TLS)
- API 인증 (OAuth, JWT)

[차이점]
구분      해시          MAC
키 사용    X            O (비밀키)
인증      X            O
무결성     O            O
속도      빠름          느림
용도      저장          통신
```

**채점 기준**:
- 해시 설명 (2점)
- MAC 설명 (2점)
- 차이점 (2점)

## 📝 유형 2: 개념 설명형

### 문제 2-1: PKI(Public Key Infrastructure)의 구성요소 4가지를 쓰고 각각 설명하시오 (8점)

**✅ 모범 답안**:
```
[PKI 구성요소]

1. CA (Certificate Authority) - 인증기관 ★★★
역할:
- 디지털 인증서 발급
- 공개키와 소유자 신원 결합
- 인증서에 CA의 전자서명

주요 기능:
- 신원 확인
- 인증서 발급/갱신/폐기
- CRL 발행

예시:
- KISA 인증센터
- VeriSign, DigiCert

2. RA (Registration Authority) - 등록기관 ★★
역할:
- CA의 업무 대행
- 사용자 신원 확인
- 인증서 발급 요청 접수

주요 기능:
- 신분증 확인
- 서류 검증
- CA에게 발급 요청 전달

3. CRL (Certificate Revocation List) - 인증서 폐기 목록 ★★
내용:
- 폐기된 인증서 일련번호 목록
- 폐기 날짜
- 폐기 사유

폐기 사유:
- 개인키 유출
- 소유자 정보 변경
- CA 위반

문제점:
- 주기적 다운로드 필요
- 실시간성 부족

4. OCSP (Online Certificate Status Protocol) - 온라인 인증서 상태 프로토콜 ★★★
역할:
- 인증서 유효성 실시간 확인
- CRL의 대안

장점:
- 실시간 조회
- 트래픽 감소
- 빠른 응답

응답:
- Good: 유효
- Revoked: 폐기
- Unknown: 알 수 없음

[인증서 발급 절차]
1. 사용자 → RA: 신원 확인
2. RA → CA: 발급 요청
3. CA: 인증서 생성 및 서명
4. CA → 사용자: 인증서 전달

[인증서 검증]
1. CRL 확인 또는
2. OCSP 조회
→ 폐기 여부 확인
```

**채점 기준**:
- CA 설명 (2점)
- RA 설명 (2점)
- CRL 설명 (2점)
- OCSP 설명 (2점)

### 문제 2-2: 전자서명의 원리와 목적을 설명하시오 (7점)

**✅ 모범 답안**:
```
[전자서명 원리]

서명 생성 과정:
1. 송신자가 원문을 해시 함수로 해시값 생성
   Hash = SHA-256(원문)

2. 송신자의 개인키로 해시값 암호화
   전자서명 = Encrypt_Private(Hash)

3. 원문 + 전자서명을 함께 전송

검증 과정:
1. 수신자가 원문을 해시 함수로 해시값 생성
   Hash1 = SHA-256(수신 원문)

2. 송신자의 공개키로 서명 복호화
   Hash2 = Decrypt_Public(전자서명)

3. Hash1과 Hash2 비교
   일치 → 유효한 서명
   불일치 → 위변조 또는 잘못된 서명자

[목적]

1. 무결성 (Integrity) ★★★
   - 원문이 변조되지 않았음을 보장
   - 해시값으로 검증

2. 인증 (Authentication) ★★★
   - 송신자의 신원 확인
   - 개인키는 송신자만 보유

3. 부인방지 (Non-repudiation) ★★★
   - 송신 사실을 부인할 수 없음
   - 법적 증거 효력
   - 개인키는 본인만 소유

[전자서명 vs 암호화]
구분         전자서명              암호화
사용키       개인키(서명)          공개키(암호화)
           공개키(검증)         개인키(복호화)
목적         인증+무결성           기밀성
원문 노출     O                   X
```

**채점 기준**:
- 서명 생성 원리 (2점)
- 검증 원리 (2점)
- 목적 3가지 (3점)

## 📝 유형 3: 계산/실습형

### 문제 3-1: SHA-256 해시값 특징과 패스워드 저장 시 솔트(Salt)를 사용하는 이유를 설명하시오 (8점)

**✅ 모범 답안**:
```
[SHA-256 특징]
- SHA (Secure Hash Algorithm)
- 출력 길이: 256비트 (64자리 16진수)
- 입력: 임의 길이
- 출력: 고정 256비트
- 일방향성: 역산 불가능
- Avalanche 효과: 1비트 변경 → 전혀 다른 해시

예시:
SHA-256("password") = 
5e884898da28047151d0e56f8dc629...

SHA-256("Password") = 
e7cf3ef4f17c3999a94f2c6f612e8a...
(완전히 다름)

[패스워드 저장 시 솔트 사용 이유] ★★★

문제 1: 같은 패스워드 → 같은 해시
사용자A: password → 5e884898...
사용자B: password → 5e884898... (동일!)
→ 한 명 뚫리면 같은 패스워드 사용자 모두 위험

문제 2: 레인보우 테이블 공격
공격자가 흔한 패스워드 해시값 미리 계산
"password" → 5e884898...
"123456" → 8d969eef...
→ 해시값 일치하면 패스워드 알아냄

해결책: 솔트(Salt) 사용 ★★★

솔트란?
- 패스워드에 추가하는 랜덤 값
- 사용자마다 다른 솔트 사용

저장 방식:
Hash = SHA-256(password + salt)
DB 저장: salt + hash (둘 다 저장)

효과:
사용자A: password + salt1 → hash1
사용자B: password + salt2 → hash2 (다름!)

→ 같은 패스워드도 다른 해시값
→ 레인보우 테이블 무용지물
→ 각 사용자마다 별도 공격 필요

[구현 예시]
# 회원가입
salt = random_bytes(16)  # 16바이트 랜덤
hash = SHA-256(password + salt)
DB 저장: (salt, hash)

# 로그인
입력 패스워드 + DB의 salt → hash 생성
생성 hash == DB의 hash → 로그인 성공

[추가 보안]
- Key Stretching: 해시 여러 번 반복 (PBKDF2)
- 느린 해시 함수 사용 (bcrypt, scrypt, Argon2)
```

**채점 기준**:
- SHA-256 특징 (2점)
- 문제점 (레인보우 테이블) (2점)
- 솔트 개념 및 효과 (4점)
