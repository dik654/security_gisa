## 📝 유형 1: 파일 비교형 ★★★

### 문제 1-1: /etc/passwd와 /etc/shadow 파일의 차이점을 설명하고, 각 파일의 필드 구조를 쓰시오 (10점)

**✅ 모범 답안**:
```
[/etc/passwd]
권한: 644 (모든 사용자 읽기 가능)
목적: 사용자 계정 기본 정보 저장

필드 구조 (7개 필드, ':' 구분):
username:x:UID:GID:GECOS:home:shell

예시:
root:x:0:0:root:/root:/bin/bash
user1:x:1000:1000:User One:/home/user1:/bin/bash

각 필드 설명:
1. username: 사용자 이름
2. x: 패스워드 (x = /etc/shadow에 저장)
3. UID: 사용자 ID ★★★
   - 0: root (슈퍼유저)
   - 1-999: 시스템 계정
   - 1000 이상: 일반 사용자
4. GID: 그룹 ID
5. GECOS: 사용자 설명 (실명, 연락처 등)
6. home: 홈 디렉토리 경로
7. shell: 로그인 셸

[/etc/shadow]
권한: 400 또는 600 (root만 읽기 가능) ★★★
목적: 암호화된 패스워드 및 정책 저장

필드 구조 (9개 필드, ':' 구분):
username:password:lastchange:min:max:warn:inactive:expire:reserved

예시:
root:$6$rounds=5000$...:19000:0:99999:7:::
user1:$6$salt$hash...:19000:1:90:7:30:19365:

각 필드 설명:
1. username: 사용자 이름 (/etc/passwd와 동일)
2. password: 암호화된 패스워드 ★★★
   - $id$salt$hash 형식
   - $1$: MD5 (취약)
   - $5$: SHA-256
   - $6$: SHA-512 (권장)
   - *: 패스워드 잠금
   - !: 계정 비활성화
3. lastchange: 마지막 패스워드 변경일 (1970.1.1 기준 일수)
4. min: 최소 사용 기간 (일)
5. max: 최대 사용 기간 (일) ★★★
   - 99999: 만료 없음
   - 90: 90일마다 변경
6. warn: 만료 경고 기간 (일)
7. inactive: 비활성화 기간 (일)
8. expire: 계정 만료일 (1970.1.1 기준 일수)
9. reserved: 예약 (사용 안 함)

[보안 강화 목적] ★★★
과거:
- /etc/passwd에 패스워드 저장 (모두 읽기 가능)
- 암호화되어도 무차별 대입 공격 가능

현재:
- /etc/shadow로 분리 (root만 읽기)
- 일반 사용자는 패스워드 해시 볼 수 없음
- 공격자가 해시를 얻을 수 없어 안전

[보안 점검]
# root 외 UID 0 계정 찾기 (취약점)
awk -F: '$3==0 && $1!="root" {print $1}' /etc/passwd

# 패스워드 없는 계정 찾기 (취약점)
awk -F: '$2=="" {print $1}' /etc/shadow
```

**채점 기준**:
- /etc/passwd 구조 및 특징 (3점)
- /etc/shadow 구조 및 특징 (4점)
- 분리 이유 (보안 강화) (3점)

### 문제 1-2: /etc/shadow에서 5번째 필드(max)의 의미와 설정 방법을 설명하시오 (6점)

**✅ 모범 답안**:
```
[5번째 필드: max (최대 사용 기간)]
의미:
패스워드를 사용할 수 있는 최대 일수
이 기간이 지나면 패스워드 변경 필수

예시:
user1:$6$...:19000:1:90:7:::
                    ^^
                    90일마다 변경

설정값:
- 99999: 만료 없음 (기본값, 보안 취약)
- 90: 90일마다 변경 (일반 계정 권장) ★★★
- 60: 60일마다 변경 (특권 계정 권장) ★★★

[chage 명령어로 설정] ★★★
# 최대 사용 기간을 90일로 설정
chage -M 90 username

# 현재 정책 확인
chage -l username

# 출력 예시:
Last password change        : Jan 01, 2025
Password expires           : Apr 01, 2025
Password inactive          : never
Account expires            : never
Minimum number of days     : 1
Maximum number of days     : 90
Number of days of warning  : 7

[직접 편집] (비추천)
vi /etc/shadow
# 5번째 필드 값 변경

[보안 정책] ★★★
ISMS-P 권장:
- 일반 계정: 90일 이내
- 특권 계정 (root, admin): 60일 이내
- 최소 사용 기간(min): 1일 (즉시 재변경 방지)
- 경고 기간(warn): 7일

[관련 명령어]
chage -M 90 user1    # 최대 90일
chage -m 1 user1     # 최소 1일
chage -W 7 user1     # 경고 7일
chage -I 30 user1    # 비활성 30일
```

**채점 기준**:
- 5번째 필드 의미 (2점)
- chage 명령어 (2점)
- 권장 값 (2점)

## 📝 유형 2: 권한 계산형 ★★★

### 문제 2-1: chmod 755의 의미를 설명하고, 각 자리수를 2진수와 rwx로 표현하시오 (7점)

**✅ 모범 답안**:
```
[chmod 755의 의미]
파일 또는 디렉토리의 권한을 8진수로 설정

[각 자리수 분해]
7 (소유자, Owner):
- 8진수: 7
- 2진수: 111
- 권한: rwx (읽기 + 쓰기 + 실행)
- 계산: 4(r) + 2(w) + 1(x) = 7

5 (그룹, Group):
- 8진수: 5
- 2진수: 101
- 권한: r-x (읽기 + 실행)
- 계산: 4(r) + 0(-) + 1(x) = 5

5 (기타, Others):
- 8진수: 5
- 2진수: 101
- 권한: r-x (읽기 + 실행)
- 계산: 4(r) + 0(-) + 1(x) = 5

[ls -l 출력 형태]
-rwxr-xr-x 1 user group 1234 Jan 1 12:00 file.sh
 ^^^^^^^^^
 |||└─ 기타 (r-x)
 ||└── 그룹 (r-x)
 |└─── 소유자 (rwx)
 └──── 파일 유형 (- = 파일, d = 디렉토리)

[권한 값 대응표] ★★★
r (Read)    : 4
w (Write)   : 2
x (Execute) : 1

rwx = 4 + 2 + 1 = 7
rw- = 4 + 2 + 0 = 6
r-x = 4 + 0 + 1 = 5
r-- = 4 + 0 + 0 = 4
-wx = 0 + 2 + 1 = 3
-w- = 0 + 2 + 0 = 2
--x = 0 + 0 + 1 = 1
--- = 0 + 0 + 0 = 0

[chmod 755 사용 예]
# 실행 파일
-rwxr-xr-x  script.sh

# 디렉토리 (일반적)
drwxr-xr-x  /home/user/documents

[기타 일반적인 권한]
644 (rw-r--r--): 일반 파일 (소유자만 수정)
600 (rw-------): 민감한 파일 (소유자만 접근)
700 (rwx------): 개인 디렉토리
777 (rwxrwxrwx): 모두 접근 (보안 취약, 금지!)
```

**채점 기준**:
- 755의 의미 (2점)
- 각 자리수 계산 (3점)
- rwx 표현 (2점)

### 문제 2-2: 다음 조건의 권한을 8진수로 표현하시오 (6점)

**조건**:
- 소유자: 읽기, 쓰기
- 그룹: 읽기
- 기타: 없음

**✅ 모범 답안**:
```
[계산 과정]
소유자 (rw-):
r (4) + w (2) + - (0) = 6

그룹 (r--):
r (4) + - (0) + - (0) = 4

기타 (---):
- (0) + - (0) + - (0) = 0

[답]
640

[ls -l 출력]
-rw-r----- 1 user group 1234 Jan 1 12:00 file.txt

[명령어]
chmod 640 file.txt

[적용 예시]
- /etc/shadow: 640 또는 600
- 개인 문서: 640
- 설정 파일: 640
```

**채점 기준**:
- 소유자 권한 계산 (2점)
- 그룹 권한 계산 (2점)
- 기타 권한 계산 (2점)

## 📝 유형 3: 특수 권한형 ★★★

### 문제 3-1: setuid, setgid, sticky bit의 개념과 설정 방법, 그리고 각각을 찾는 명령어를 쓰시오 (12점)

**✅ 모범 답안**:
```
[1. setuid (Set User ID)] ★★★
개념:
파일 실행 시 소유자의 권한으로 실행
일반 사용자가 root 권한 필요한 명령어 실행 가능

설정:
chmod 4755 file  # 8진수
chmod u+s file   # 기호

표시:
-rwsr-xr-x  (s = setuid)
     ^

찾기: ★★★
find / -perm -4000 -type f 2>/dev/null
find / -perm /4000 -type f 2>/dev/null

예시:
/usr/bin/passwd  (일반 사용자도 패스워드 변경 가능)
/usr/bin/sudo
/bin/ping

위험성:
- 악용 시 권한 상승 공격
- 불필요한 setuid 파일은 제거
- 정기적으로 점검 필요

[2. setgid (Set Group ID)] ★★
개념:
- 파일: 실행 시 그룹의 권한으로 실행
- 디렉토리: 생성되는 파일이 디렉토리 그룹을 상속

설정:
chmod 2755 file  # 8진수
chmod g+s file   # 기호

표시:
-rwxr-sr-x  (s = setgid)
      ^

찾기:
find / -perm -2000 -type f 2>/dev/null

예시:
디렉토리에 설정 시:
drwxrwsr-x  /shared
그룹 협업 디렉토리로 활용

[3. sticky bit] ★★★
개념:
디렉토리에 설정 시, 파일을 생성한 소유자만 삭제 가능
다른 사용자는 읽기/쓰기는 가능하지만 삭제 불가

설정:
chmod 1777 dir   # 8진수
chmod +t dir     # 기호

표시:
drwxrwxrwt  (t = sticky bit)
        ^

찾기:
find / -perm -1000 -type d 2>/dev/null

예시: ★★★
/tmp  (임시 디렉토리)
drwxrwxrwt  /tmp
- 모두 파일 생성 가능
- 자기 파일만 삭제 가능
- 타인 파일 삭제 불가 (보안)

[특수 권한 조합]
4000: setuid
2000: setgid
1000: sticky bit
6000: setuid + setgid
7000: setuid + setgid + sticky bit

[명령어 정리] ★★★
# setuid 파일 찾기
find / -perm -4000 -type f 2>/dev/null

# setgid 파일 찾기
find / -perm -2000 -type f 2>/dev/null

# sticky bit 디렉토리 찾기
find / -perm -1000 -type d 2>/dev/null

# 특수 권한 모두 찾기
find / \( -perm -4000 -o -perm -2000 -o -perm -1000 \) 2>/dev/null

# 777 권한 파일 찾기 (보안 취약)
find / -perm -777 -type f 2>/dev/null
```

**채점 기준**:
- setuid 설명 및 찾기 (4점)
- setgid 설명 및 찾기 (3점)
- sticky bit 설명 및 찾기 (4점)
- /tmp 예시 (1점)

## 📝 유형 4: 명령어 작성형 ★★★

### 문제 4-1: umask의 개념을 설명하고, umask 0022일 때 생성되는 파일과 디렉토리의 권한을 계산하시오 (8점)

**✅ 모범 답안**:
```
[umask 개념]
파일이나 디렉토리 생성 시 기본 권한에서 제거할 권한을 지정
"빼기" 개념 (마스크)

[기본 권한]
파일: 666 (rw-rw-rw-)  # 실행 권한 없음
디렉토리: 777 (rwxrwxrwx)

[umask 0022 계산] ★★★

파일 권한:
666 (기본)
-022 (umask)
----
644 (rw-r--r--)  # 결과

설명:
- 소유자: 6 - 0 = 6 (rw-)
- 그룹: 6 - 2 = 4 (r--)
- 기타: 6 - 2 = 4 (r--)

디렉토리 권한:
777 (기본)
-022 (umask)
----
755 (rwxr-xr-x)  # 결과

설명:
- 소유자: 7 - 0 = 7 (rwx)
- 그룹: 7 - 2 = 5 (r-x)
- 기타: 7 - 2 = 5 (r-x)

[umask 설정 및 확인]
# 현재 umask 확인
umask
# 출력: 0022

# 8진수로 확인
umask -S
# 출력: u=rwx,g=rx,o=rx

# umask 변경
umask 0027  # 더 엄격
umask 0077  # 매우 엄격 (그룹/기타 모두 차단)

[일반적인 umask 값] ★★★
0022 (기본):
- 파일: 644 (rw-r--r--)
- 디렉토리: 755 (rwxr-xr-x)
- 일반적, 그룹/기타 읽기 가능

0027 (보안 강화):
- 파일: 640 (rw-r-----)
- 디렉토리: 750 (rwxr-x---)
- 기타 사용자 접근 차단

0077 (매우 엄격):
- 파일: 600 (rw-------)
- 디렉토리: 700 (rwx------)
- 소유자만 접근

[영구 설정]
# ~/.bashrc 또는 /etc/profile에 추가
umask 0027
```

**채점 기준**:
- umask 개념 (2점)
- 파일 권한 계산 (3점)
- 디렉토리 권한 계산 (3점)

[보안 로그 확인]
# Red Hat/CentOS

## 📝 유형 5: 프로세스/로그 관리형

### 문제 5-1: 좀비 프로세스를 찾는 방법과 lsof 명령어의 용도를 설명하시오 (7점)

**✅ 모범 답안**:
```
[좀비 프로세스 찾기] ★★

방법 1: ps 명령어
ps aux | grep 'Z'
ps aux | grep '<defunct>'

출력 예시:
user  1234  0.0  0.0    0    0 ?  Z  10:00  0:00 [process] <defunct>
                                   ^
                                   좀비 상태 (Z)

방법 2: top 명령어
top
# 상단에 "zombie" 개수 표시
Tasks: 100 total, 1 running, 98 sleeping, 0 stopped, 1 zombie

[좀비 프로세스란]
- 실행 완료했지만 프로세스 테이블에 남아있는 상태
- 부모 프로세스가 wait()를 호출하지 않음
- 리소스는 거의 사용 안 함
- PID는 점유 (많으면 PID 고갈)

[제거 방법]
# 부모 프로세스 종료 (권장)
kill -9 <부모PID>

# init(PID 1)이 자동으로 정리
# 시스템 재부팅 (최후 수단)

[lsof 명령어] ★★★
용도: List Open Files (열린 파일 목록)

기본 사용:
lsof  # 모든 열린 파일

주요 옵션:
# 특정 사용자
lsof -u username

# 특정 포트
lsof -i :80
lsof -i :22

# 특정 프로세스
lsof -p <PID>

# 특정 파일
lsof /var/log/syslog

# 네트워크 연결
lsof -i
lsof -i TCP
lsof -i UDP

# 특정 디렉토리
lsof +D /home/user

출력 예시:
COMMAND   PID  USER   FD   TYPE DEVICE SIZE/OFF NODE NAME
apache2  1234  www   3u  IPv4  12345      0t0  TCP *:80 (LISTEN)

활용:
1. 포트 사용 프로세스 찾기
   lsof -i :80  # 80번 포트 사용 중인 프로세스

2. 파일 삭제 안 될 때
   lsof /path/file  # 파일 사용 중인 프로세스 확인

3. 디스크 용량 문제
   삭제한 파일이 여전히 열려있는 경우 찾기

4. 보안 점검
   의심스러운 네트워크 연결 확인
```

**채점 기준**:
- 좀비 프로세스 찾기 (2점)
- 좀비 개념 (1점)
- lsof 용도 (2점)
- lsof 예시 (2점)

## 💡 Part 8 핵심 암기 체크리스트

### 필수 암기 파일 ★★★
```
□ /etc/passwd: 644, 7개 필드, 3번째=UID
□ /etc/shadow: 400/600, 9개 필드, 5번째=max
□ /var/log/btmp: lastb, 로그인 실패
□ /var/log/wtmp: last, 로그인 성공
□ /tmp: sticky bit (1777)
```

### 필수 암기 명령어 ★★★
```
□ find / -perm -4000 -type f 2>/dev/null  (setuid)
□ chmod 755 file  (rwxr-xr-x)
□ chage -M 90 user  (패스워드 최대 90일)
□ lastb  (로그인 실패)
□ lsof -i :80  (포트 80 사용 프로세스)
□ ps aux | grep 'Z'  (좀비 프로세스)
```

### 필수 암기 권한 계산 ★★★
```
□ rwx = 7 (4+2+1)
□ rw- = 6 (4+2)
□ r-x = 5 (4+1)
□ r-- = 4
□ 755 = rwxr-xr-x
□ 644 = rw-r--r--
□ umask 0022 → 파일 644, 디렉토리 755
```

### 필수 암기 특수 권한 ★★★
```
□ setuid: 4000, u+s, passwd 명령어
□ setgid: 2000, g+s, 그룹 상속
□ sticky bit: 1000, +t, /tmp
```
