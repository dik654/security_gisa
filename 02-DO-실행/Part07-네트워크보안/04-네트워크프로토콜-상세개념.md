# 네트워크 프로토콜 - 상세 개념

## 🔴 OSI 7계층 ★★★

### 문제 (2024년 기출)
```
OSI 7계층 각 계층의 역할과 프로토콜은?
```

### ✅ 정답
```
OSI 7계층 (Open Systems Interconnection)

┌──────┬────────────┬──────────────────┬────────────────┐
│ 계층 │   이름     │      역할        │   프로토콜     │
├──────┼────────────┼──────────────────┼────────────────┤
│  7   │ Application│ 응용 서비스      │ HTTP, FTP,     │
│      │ 응용 계층  │ 사용자 인터페이스│ SMTP, DNS,     │
│      │            │                  │ Telnet, SNMP   │
├──────┼────────────┼──────────────────┼────────────────┤
│  6   │Presentation│ 데이터 표현/변환 │ SSL/TLS,       │
│      │ 표현 계층  │ 암호화, 압축     │ JPEG, MPEG     │
├──────┼────────────┼──────────────────┼────────────────┤
│  5   │  Session   │ 세션 설정/유지   │ NetBIOS,       │
│      │ 세션 계층  │ 대화 제어        │ RPC, SQL       │
├──────┼────────────┼──────────────────┼────────────────┤
│  4   │ Transport  │ 종단간 전송 ★   │ TCP, UDP       │
│      │ 전송 계층  │ 흐름제어, 오류제어│ (포트 번호)   │
├──────┼────────────┼──────────────────┼────────────────┤
│  3   │  Network   │ 경로 설정 ★★    │ IP, ICMP,      │
│      │ 네트워크   │ 라우팅           │ IGMP, ARP      │
│      │   계층     │ (IP 주소)        │                │
├──────┼────────────┼──────────────────┼────────────────┤
│  2   │ Data Link  │ 프레임 전송      │ Ethernet,      │
│      │데이터링크  │ 오류 검출/수정   │ PPP, HDLC      │
│      │   계층     │ (MAC 주소)       │ (스위치)       │
├──────┼────────────┼──────────────────┼────────────────┤
│  1   │  Physical  │ 물리적 신호 전송 │ RS-232,        │
│      │ 물리 계층  │ 비트 전송        │ 케이블, 허브   │
└──────┴────────────┴──────────────────┴────────────────┘

암기법: "Please Do Not Throw Sausage Pizza Away"
(Physical - Data Link - Network - Transport - Session - Presentation - Application)
```

### 각 계층별 상세 설명
```
[계층 1] Physical (물리 계층)
- 비트를 전기 신호로 변환
- 케이블, 리피터, 허브
- 단위: Bit

[계층 2] Data Link (데이터링크 계층)
- 프레임 단위 전송
- MAC 주소 사용
- 오류 검출 (CRC)
- 장비: 스위치, 브리지
- 단위: Frame

[계층 3] Network (네트워크 계층)
- 패킷 라우팅
- IP 주소 사용
- 경로 설정 (라우팅)
- 장비: 라우터
- 단위: Packet
- 프로토콜: IP, ICMP, ARP, IGMP

[계층 4] Transport (전송 계층) ★★★
- 종단간(End-to-End) 전송
- 포트 번호 사용
- TCP: 연결 지향, 신뢰성 보장
- UDP: 비연결, 빠름
- 단위: Segment (TCP) / Datagram (UDP)

[계층 5] Session (세션 계층)
- 세션 설정/유지/종료
- 대화 제어
- 동기화 (체크포인트)

[계층 6] Presentation (표현 계층)
- 데이터 형식 변환
- 암호화/복호화
- 압축/압축 해제
- 문자 인코딩 (ASCII, EBCDIC)

[계층 7] Application (응용 계층)
- 사용자 애플리케이션 서비스
- HTTP, FTP, SMTP, DNS, Telnet
```

## 🔴 Ethernet (이더넷) ★★

### 문제 (2024년 기출)
```
Ethernet에서 사용하는 CSMA/CD와 CSMA/CA의 차이는?
```

### ✅ 정답
```
CSMA/CD vs CSMA/CA

1. CSMA/CD (Collision Detection) ★★★
   = 충돌 감지 방식

   동작 원리:
   1) 전송 전 캐리어 감지 (Carrier Sense)
   2) 매체가 비어있으면 전송
   3) 충돌 발생 시 감지 (Collision Detection)
   4) 충돌 시 잠시 대기 후 재전송 (랜덤 백오프)

   사용:
   - 유선 Ethernet (IEEE 802.3)
   - Half-Duplex 모드

   단점:
   - 충돌 후 재전송 → 지연 발생

2. CSMA/CA (Collision Avoidance) ★★★
   = 충돌 회피 방식

   동작 원리:
   1) 전송 전 캐리어 감지
   2) 매체가 비어있으면 DIFS 대기
   3) RTS (Request to Send) 전송
   4) CTS (Clear to Send) 수신
   5) 데이터 전송
   6) ACK 수신 확인

   사용:
   - 무선 LAN (IEEE 802.11 Wi-Fi)

   이유:
   - 무선은 충돌 감지 어려움 (Hidden Node Problem)
   - 충돌 방지가 더 효율적

비교:
┌────────────┬─────────────┬─────────────┐
│    구분    │  CSMA/CD    │  CSMA/CA    │
├────────────┼─────────────┼─────────────┤
│ 방식       │ 충돌 감지   │ 충돌 회피 ★│
│ 사용       │ 유선 LAN    │ 무선 LAN ★ │
│ 표준       │ 802.3       │ 802.11      │
│ 효율       │ 높음        │ 낮음        │
│ 지연       │ 낮음        │ 높음        │
└────────────┴─────────────┴─────────────┘
```

│      │ 브로드캐스트 메시지            │

- Windows 방화벽에서 135, 139, 445 차단
- SMBv1 비활성화
- 패치 적용 (MS17-010)

## 🔴 FTP 공격 (Bounce Attack) ★★

### 문제 (2024년 기출)
```
FTP Bounce Attack이란?
```

### ✅ 정답
```
FTP Bounce Attack

정의:
FTP 서버를 중계 서버로 악용하여
제3의 시스템을 공격하는 기법

동작 원리:
1. 공격자가 FTP 서버에 연결
2. PORT 명령어로 타겟 시스템 지정
3. FTP 서버가 타겟에 연결 시도
4. 공격자의 IP 대신 FTP 서버 IP가 노출됨

공격 시나리오:
┌─────────┐  1. FTP 접속        ┌─────────┐
│ 공격자  │ ───────────────→   │FTP 서버 │
│         │  2. PORT 공격대상   │         │
│         │     (타겟:포트)     │         │
└─────────┘                     └─────────┘
                                    │
                        3. 공격자 대신 연결
                                    ↓
                                ┌─────────┐
                                │ 타겟    │
                                │ 시스템  │
                                └─────────┘

악용 목적:
- 포트 스캔 (타겟 시스템)
- 방화벽 우회
- 공격자 IP 은닉

FTP 명령어:
PORT 192,168,1,100,0,80
→ 192.168.1.100:80 으로 연결 지시

방어:
1. FTP 서버 설정
   - PORT 명령어 제한
   - 외부 IP 연결 차단

2. 방화벽
   - FTP Active 모드 차단
   - Passive 모드만 허용

3. FTP 모드 비교:
   Active 모드: PORT 명령 (취약 ★)
   Passive 모드: PASV 명령 (안전)
```

## 🔴 HTTP 헤더/바디 구분자 ★★

### 문제 (2024년 기출)
```
HTTP에서 헤더와 바디를 구분하는 문자는?
```

### ✅ 정답
```
\r\n\r\n (CRLF CRLF) ★★★

상세 설명:
- \r\n: Carriage Return + Line Feed
- \r\n\r\n: 빈 줄 (Empty Line)

HTTP 요청/응답 형식:
┌───────────────────────────────┐
│ Request Line (요청 라인)      │
│ GET /index.html HTTP/1.1      │
├───────────────────────────────┤
│ Headers (헤더)                │
│ Host: www.example.com         │
│ User-Agent: Mozilla/5.0       │
│ Content-Length: 27            │
├───────────────────────────────┤ ← \r\n\r\n (빈 줄)
├───────────────────────────────┤
│ Body (바디)                   │
│ username=admin&password=1234  │
└───────────────────────────────┘

16진수 표현:
\r\n\r\n = 0x0D 0x0A 0x0D 0x0A

실제 예시:
GET /login HTTP/1.1\r\n
Host: example.com\r\n
Content-Length: 27\r\n
\r\n                    ← 헤더/바디 구분자 ★★★
username=admin&password=1234

보안 이슈:
1. HTTP Request Smuggling
   - \r\n\r\n 조작하여 요청 밀반입

2. Header Injection
   - CRLF 삽입으로 헤더 조작
   예: Location: http://evil.com\r\nSet-Cookie: admin=true

방어:
- 입력 검증 (\r, \n 필터링)
- Content-Length 검증
```

## 🔴 POST vs GET ★★

### 문제 (2024년 기출)
```
POST와 GET의 차이는?
```

### ✅ 정답
```
POST vs GET

┌─────────────┬──────────────────┬──────────────────┐
│    구분     │       GET        │       POST       │
├─────────────┼──────────────────┼──────────────────┤
│ 데이터 위치 │ URL (쿼리 문자열)│ HTTP Body ★     │
│             │ ?key=value       │                  │
├─────────────┼──────────────────┼──────────────────┤
│ 데이터 크기 │ 제한 있음        │ 제한 없음 ★     │
│             │ (브라우저마다    │                  │
│             │  2KB ~ 8KB)      │                  │
├─────────────┼──────────────────┼──────────────────┤
│ 보안        │ 낮음 (URL 노출)  │ 상대적으로 높음 │
│             │ ★★             │                  │
├─────────────┼──────────────────┼──────────────────┤
│ 캐싱        │ 가능             │ 불가능           │
├─────────────┼──────────────────┼──────────────────┤
│ 북마크      │ 가능             │ 불가능           │
├─────────────┼──────────────────┼──────────────────┤
│ 브라우저    │ 히스토리 남음    │ 히스토리 안남음  │
│ 히스토리    │                  │                  │
├─────────────┼──────────────────┼──────────────────┤
│ 용도        │ 데이터 조회      │ 데이터 생성/수정 │
│             │ (SELECT)         │ (INSERT/UPDATE)  │
├─────────────┼──────────────────┼──────────────────┤
│ 멱등성      │ O (여러번 호출   │ X (매번 다를 수  │
│ (Idempotent)│  동일 결과)      │  있음)           │
└─────────────┴──────────────────┴──────────────────┘

GET 예시:
GET /search?q=security&page=1 HTTP/1.1
Host: example.com

→ URL에 데이터 노출 ★
→ 로그에 기록됨 (보안 취약)

POST 예시:
POST /login HTTP/1.1
Host: example.com
Content-Type: application/x-www-form-urlencoded
Content-Length: 27

username=admin&password=1234
                ↑
              Body에 숨겨짐 ★

보안 고려사항:
1. 민감 정보 (비밀번호, 개인정보) → POST 사용 ★★★
2. GET은 로그/히스토리/캐시에 남음
3. POST도 HTTPS 사용 필수 (평문 전송 방지)
4. CSRF 공격: POST도 취약할 수 있음

RESTful API 사용:
- GET: 조회 (Read)
- POST: 생성 (Create)
- PUT: 수정 (Update)
- DELETE: 삭제 (Delete)
```

## 🎯 네트워크 프로토콜 핵심 암기 카드

### 카드 1: OSI 7계층
```
7. Application (HTTP, FTP, DNS)
6. Presentation (암호화, 압축)
5. Session (세션 관리)
4. Transport (TCP/UDP, 포트) ★
3. Network (IP, 라우팅) ★★
2. Data Link (MAC, 스위치)
1. Physical (비트, 케이블)
```

### 카드 2: Ethernet
```
CSMA/CD: 충돌 감지 (유선 LAN) ★
CSMA/CA: 충돌 회피 (무선 LAN) ★
```

### 카드 3: NetBIOS/SMB 포트
```
135: RPC
139: NetBIOS Session
445: SMB over TCP ★★★ (랜섬웨어 주 공격 경로)
```

### 카드 4: FTP Bounce Attack
```
FTP 서버를 중계로 악용
공격자 IP 은닉
PORT 명령어 제한으로 방어 ★
```

### 카드 5: HTTP
```
헤더/바디 구분: \r\n\r\n ★★★
GET: URL에 데이터 (보안 취약)
POST: Body에 데이터 (상대적 안전)
```

### 카드 6: DB 포트
```
MySQL: 3306
MSSQL: 1433 ★★★
Oracle: 1521
```

## 💡 실기 답안 작성 팁

### Tip 1: OSI 계층
```
✅ 4계층 전송계층 - TCP/UDP, 포트 번호, 종단간 전송
✅ 3계층 네트워크계층 - IP, 라우팅, 경로 설정

❌ 4계층 - TCP (너무 간략)
```

### Tip 2: CSMA
```
✅ CSMA/CD - 충돌 감지, 유선 LAN (802.3)
✅ CSMA/CA - 충돌 회피, 무선 LAN (802.11)

❌ CSMA/CD는 더 빠르다 (정답이지만 핵심 아님)
```

### Tip 3: NetBIOS 포트
```
✅ 135 (RPC), 139 (NetBIOS), 445 (SMB) ★★★

❌ 135, 137, 138, 139 (137/138은 UDP, 우선순위 낮음)
```

### Tip 4: HTTP 구분자
```
✅ \r\n\r\n (CRLF CRLF) ★★★
✅ 빈 줄 (Empty Line)

❌ \n\n (틀림! \r\n 필요)
```
