# 실기 기타 필수 개념 총정리

## 🔴 HTTP 응답 코드 ★★★

### 문제 (2024년 기출)
```
HTTP 응답코드 200, 300, 400, 500의 의미?
```

### ✅ 정답
```
┌──────┬─────────────────────────────────────┐
│ 코드 │          의미                       │
├──────┼─────────────────────────────────────┤
│ 200  │ OK - 성공 ★★★                     │
│      │ 요청 정상 처리                      │
├──────┼─────────────────────────────────────┤
│ 300  │ Redirection - 리다이렉션           │
│      │ 추가 조치 필요 (다른 URL로 이동)   │
│      │ 301: Moved Permanently (영구 이동) │
│      │ 302: Found (임시 이동)             │
├──────┼─────────────────────────────────────┤
│ 400  │ Client Error - 클라이언트 오류 ★  │
│      │ 잘못된 요청                         │
│      │ 401: Unauthorized (인증 필요)       │
│      │ 403: Forbidden (권한 없음)         │
│      │ 404: Not Found (페이지 없음)       │
├──────┼─────────────────────────────────────┤
│ 500  │ Server Error - 서버 오류 ★        │
│      │ 서버 내부 오류                      │
│      │ 502: Bad Gateway                    │
│      │ 503: Service Unavailable           │
└──────┴─────────────────────────────────────┘

요약:
2xx - 성공
3xx - 리다이렉션
4xx - 클라이언트 오류
5xx - 서버 오류
```

## 🔴 SEED 암호화 ★★

### 문제 (2024년 기출)
```
SEED 암호화의 특징은?
```

### ✅ 정답
```
SEED

1. 한국 표준 암호 알고리즘 ★
   - KISA (한국인터넷진흥원) 개발
   - 국내 표준 (KS X 1213)

2. 대칭키 블록 암호
   - 블록 크기: 128비트
   - 키 크기: 128비트
   - Feistel 구조 (16라운드)

3. 사용 분야
   - 전자상거래
   - 금융
   - 전자정부

4. 타 암호와 비교
   SEED (한국) vs AES (미국) vs ARIA (한국)
   ┌────────┬────────┬────────┬────────┐
   │  구분  │  SEED  │  AES   │  ARIA  │
   ├────────┼────────┼────────┼────────┤
   │ 블록   │ 128bit │ 128bit │ 128bit │
   │ 키     │ 128bit │128/192 │128/192 │
   │        │        │ /256   │ /256   │
   │ 구조   │Feistel │  SPN   │  SPN   │
   │ 국가   │ 한국   │ 미국   │ 한국   │
   └────────┴────────┴────────┴────────┘
```

## 🔴 디지털 포렌식 원칙 ★★

### 문제 (2024년 기출)
```
다음 중 디지털 포렌식의 원칙이 아닌 것은?
```

### ✅ 정답 (5대 원칙)
```
1. 정당성 (Legality)
   - 적법한 절차
   - 영장 또는 동의

2. 무결성 (Integrity) ★
   - 원본 훼손 금지
   - 해시값 검증 (MD5, SHA-256)

3. 재현성 (Reproducibility)
   - 동일 결과 재현 가능
   - 절차 문서화

4. 신속성 (Speed)
   - 휘발성 데이터 신속 수집
   - 타이밍 중요

5. 연속성 (Chain of Custody) ★★
   - 증거 관리 대장
   - 수집→보관→분석→법정 전 과정 추적

✗ 아닌 것 예시:
- 경제성 (비용 절감은 원칙 아님)
- 편의성 (절차 간소화는 원칙 위배)
```

## 🔴 컴파일 순서 ★★

### 문제 (2024년 기출)
```
컴파일 순서는?
(렉서, 파서, 중간코드 생성, 옵티마이저, 실행파일)
```

### ✅ 정답
```
[1] 렉서 (Lexer) - 어휘 분석
    소스 코드 → 토큰 분리
    예: int x = 10;
    → [int] [x] [=] [10] [;]

[2] 파서 (Parser) - 구문 분석
    토큰 → 구문 트리 (AST)
    문법 검사

[3] 중간 코드 생성 (Intermediate Code Generator)
    구문 트리 → 중간 표현 (IR)
    플랫폼 독립적

[4] 옵티마이저 (Optimizer) - 최적화
    중간 코드 최적화
    성능 향상, 코드 크기 감소

[5] 코드 생성기 (Code Generator)
    중간 코드 → 어셈블리/기계어

[6] 어셈블러 (Assembler)
    어셈블리 → 목적 코드 (.o, .obj)

[7] 링커 (Linker)
    목적 파일들 연결 → 실행 파일

요약 순서:
소스코드 → 렉서 → 파서 → 중간코드 → 옵티마이저 → 코드생성 → 어셈블 → 링크 → 실행파일
```

## 🔴 NTFS 파일 시스템 특징 ★★

### 문제 (2024년 기출)
```
NTFS 파일 시스템의 특징?
```

### ✅ 정답
```
NTFS (New Technology File System)

주요 특징:

1. 저널링 (Journaling) ★
   - 파일 시스템 작업 로그 기록
   - 시스템 장애 시 빠른 복구

2. 접근 제어 (ACL) ★★
   - 파일/폴더별 세밀한 권한 설정
   - FAT32는 불가능

3. 암호화 (EFS)
   - Encrypting File System
   - 파일 단위 암호화

4. 압축
   - 파일/폴더 투명 압축

5. 대용량 지원
   - 최대 파일 크기: 16EB (이론상)
   - 최대 볼륨 크기: 256TB (실용)

6. 쿼터 (Quota)
   - 사용자별 디스크 사용량 제한

7. 링크
   - 하드 링크, 심볼릭 링크 지원

FAT32 vs NTFS:
┌──────────┬──────────┬──────────┐
│   항목   │  FAT32   │   NTFS   │
├──────────┼──────────┼──────────┤
│ 권한관리 │    X     │    O ★  │
│ 암호화   │    X     │    O     │
│ 파일크기 │   4GB    │   16EB   │
│ 저널링   │    X     │    O ★  │
└──────────┴──────────┴──────────┘
```

## 🔴 데이터베이스 보안 구성요소 ★

### 문제 (2024년 기출)
```
데이터베이스 보안의 구성요소는?
```

### ✅ 정답
```
DB 보안 3대 요소:

1. 접근 통제 (Access Control) ★★
   - 계정 관리
   - 권한 부여 (GRANT)
   - 역할 기반 접근 통제 (RBAC)

2. 암호화 (Encryption)
   - TDE (Transparent Data Encryption)
   - 컬럼 단위 암호화
   - 백업 암호화

3. 감사 (Auditing) ★
   - 접속 로그
   - 쿼리 로그
   - 변경 이력 추적

추가 구성요소:

4. 인증 (Authentication)
   - DB 사용자 인증
   - 통합 인증 (LDAP, Kerberos)

5. 무결성 (Integrity)
   - 제약 조건 (PK, FK, CHECK)
   - 트랜잭션 (ACID)

6. 백업 및 복구
   - 정기 백업
   - 백업 암호화
```

## 🔴 Wireshark 패킷 바이트 ★

### 문제 (2024년 기출)
```
Wireshark 화면에서 분할된 패킷 바이트는?
```

### ✅ 정답
```
Wireshark 화면 구성:

┌─────────────────────────────────────┐
│ [1] Packet List (패킷 목록)         │
│ No. Time   Source  Destination...   │
└─────────────────────────────────────┘
┌─────────────────────────────────────┐
│ [2] Packet Details (패킷 상세)      │
│ ▶ Ethernet II                       │
│ ▶ Internet Protocol                 │
│ ▶ Transmission Control Protocol     │
└─────────────────────────────────────┘
┌─────────────────────────────────────┐
│ [3] Packet Bytes (패킷 바이트) ★   │
│ 0000  ff ff ff ff ff ff 00 50       │
│ 0010  ba 12 34 56 08 00 45 00       │
│ ...                                 │
└─────────────────────────────────────┘

분할된 패킷 바이트:
16진수(Hex) 형태로 표시
- 왼쪽: 오프셋 (0000, 0010, ...)
- 중간: 16진수 바이트
- 오른쪽: ASCII 문자 (출력 가능한 경우)

색상:
- 선택한 필드에 해당하는 바이트가 하이라이트됨
- 예: IP 헤더 선택 시 해당 바이트 강조
```

## 🔴 하드웨어 3요소 ★

### 문제 (2024년 기출)
```
하드웨어의 3요소?
```

### ✅ 정답
```
컴퓨터 하드웨어 3대 구성요소:

1. CPU (Central Processing Unit) ★★
   중앙 처리 장치
   - 연산 수행
   - 제어

2. 메모리 (Memory) ★★
   - RAM (주기억장치)
   - ROM
   - 캐시

3. 입출력 장치 (I/O Devices) ★
   - 입력: 키보드, 마우스
   - 출력: 모니터, 프린터
   - 보조기억장치: HDD, SSD (입출력 겸함)

5대 구성요소 (확장):
1. 입력장치
2. 출력장치
3. 연산장치 (CPU)
4. 제어장치 (CPU)
5. 기억장치 (메모리)

실기에서는 "CPU, 메모리, 입출력장치" 3가지가 정답
```

## 💡 실기 답안 작성 팁

### Tip 1: HTTP 코드는 백 단위
```
✅ 2xx 성공, 3xx 리다이렉션, 4xx 클라이언트 오류, 5xx 서버 오류

❌ 200, 201, 202... 모두 나열 (불필요)
```

### Tip 2: SEED는 한국 표준
```
✅ SEED - 한국 표준, 128bit 블록/키

❌ SEED - AES와 동일 (틀림!)
```

### Tip 3: 컴파일 순서는 순서대로
```
✅ 렉서 → 파서 → 중간코드 → 옵티마이저 → ...

❌ 옵티마이저 → 파서 (순서 틀림)
```
