# 정보보안기사 실기 - 서술형 답안 작성 가이드

> **목적**: 서술형 문제에서 만점을 받기 위한 체계적인 답안 작성 방법
> **적용**: 모든 Part의 서술형 문제 (개념 설명, 절차, 비교 등)

---

## 🎯 서술형 문제 유형 분석

### 1. 개념 설명형 ★★★

**문제 유형**:
```
"OOO의 정의를 설명하시오"
"OOO란 무엇인가?"
"OOO에 대해 서술하시오"
```

**답안 작성 템플릿**:
```
1) 핵심 정의 (1문장, 20자 내외)
2) 주요 특징 (2-3가지)
3) 구체적 예시 (필요시)
```

**예시 1**: SQL Injection이란?
```
❌ 나쁜 답안:
"SQL Injection은 나쁜 공격이다"

✅ 좋은 답안:
"웹 애플리케이션의 입력값 검증 부재를 이용하여
악의적인 SQL 쿼리를 삽입하는 공격 기법

특징:
1. OWASP Top 10 취약점
2. DB 정보 유출/변조 가능
3. Prepared Statement로 방어"
```

**예시 2**: ISMS-P란?
```
✅ 좋은 답안:
"정보보호 및 개인정보보호 관리체계 인증제도

구성:
1. 관리체계 수립 및 운영 (16개 항목)
2. 보호대책 요구사항 (64개 항목)
3. 개인정보 처리 단계별 요구사항 (22개 항목)

유효기간: 3년 (사후관리 연 1회)"
```

### 2. 절차 나열형 ★★★

**문제 유형**:
```
"OOO의 절차를 순서대로 쓰시오"
"OOO 단계를 나열하시오"
```

**답안 작성 템플릿**:
```
1. 첫 번째 단계
2. 두 번째 단계
3. 세 번째 단계
...

※ 반드시 번호 매기기
※ 화살표(→) 사용 가능
```

**예시 1**: ISMS-P 인증 절차
```
✅ 좋은 답안:
1. 인증 신청
2. 심사 계획 수립
3. 문서 심사
4. 현장 심사
5. 인증위원회 심의
6. 인증서 발급
7. 사후관리 (연 1회 이상)
```

**예시 2**: 침해사고 대응 절차
```
✅ 좋은 답안:
1. 사전 준비
2. 탐지 및 분석
3. 억제 및 격리
4. 제거
5. 복구
6. 사후 활동 (재발 방지)
```

### 3. 비교/대조형 ★★★

**문제 유형**:
```
"A와 B의 차이점을 설명하시오"
"A와 B를 비교하시오"
```

**답안 작성 템플릿**:
```
A:
- 특징 1
- 특징 2
- 사용 사례

B:
- 특징 1
- 특징 2
- 사용 사례
```

**예시 1**: 대칭키 vs 비대칭키
```
✅ 좋은 답안:
대칭키 암호화:
- 동일한 키로 암호화/복호화
- 빠른 속도
- 키 교환 문제
- 예: AES, ARIA, SEED

비대칭키 암호화:
- 공개키/개인키 쌍
- 느린 속도
- 안전한 키 교환
- 예: RSA, ECC
```

**예시 2**: IDS vs IPS
```
✅ 좋은 답안:
IDS (침입 탐지 시스템):
- 탐지 후 경고만 발생
- 패킷 복사본 분석
- 트래픽 영향 없음
- Out-of-Band 구성

IPS (침입 방지 시스템):
- 탐지 후 자동 차단
- 실시간 패킷 검사
- 지연 발생 가능
- In-Line 구성
```

### 4. 열거형 ★★★

**문제 유형**:
```
"OOO를 3가지 쓰시오"
"OOO의 종류를 나열하시오"
```

**답안 작성 템플릿**:
```
1. 첫 번째 항목 (간단한 설명)
2. 두 번째 항목 (간단한 설명)
3. 세 번째 항목 (간단한 설명)
```

**예시 1**: 위협의 종류 3가지
```
✅ 좋은 답안:
1. 자연적 위협 (지진, 화재, 홍수)
2. 인적 위협 (해킹, 내부자 공격, 사회공학)
3. 환경적 위협 (정전, 온습도 이상, 통신 장애)
```

**예시 2**: 위험대응 전략 4가지
```
✅ 좋은 답안:
1. 회피 (Risk Avoidance): 위험한 활동 중단
2. 전가 (Risk Transfer): 보험 가입, 아웃소싱
3. 감소 (Risk Mitigation): 보안대책 구현
4. 수용 (Risk Acceptance): 낮은 위험 수용
```

### 5. 원리/동작 설명형 ★★

**문제 유형**:
```
"OOO의 동작 원리를 설명하시오"
"OOO가 어떻게 작동하는지 서술하시오"
```

**답안 작성 템플릿**:
```
1. 시작/초기 상태
2. 중간 과정 (핵심 메커니즘)
3. 최종 결과
```

**예시 1**: SYN Flooding 공격 원리
```
✅ 좋은 답안:
1. 공격자가 위조된 출발지 IP로 SYN 패킷 대량 전송
2. 서버는 SYN-ACK 응답 후 ACK 대기 (Half-Open 상태)
3. 공격자는 ACK 전송하지 않음
4. 서버의 백로그 큐(Backlog Queue) 가득 참
5. 정상 사용자 연결 거부 (서비스 거부)

방어: SYN Cookie, SYN Proxy
```

**예시 2**: Kerberos 인증 과정
```
✅ 좋은 답안:
1. 클라이언트가 AS(인증 서버)에 TGT 요청
2. AS가 TGT(Ticket Granting Ticket) 발급
3. 클라이언트가 TGS(티켓 발급 서버)에 서비스 티켓 요청
4. TGS가 서비스 티켓 발급
5. 클라이언트가 서비스 티켓으로 서버 접근

특징: Single Sign-On, 타임스탬프 사용
```

### 6. 문제점/해결방안형 ★★★

**문제 유형**:
```
"OOO의 문제점과 해결방안을 쓰시오"
"OOO 취약점과 대응방법을 설명하시오"
```

**답안 작성 템플릿**:
```
문제점/취약점:
1. 문제 1
2. 문제 2

해결방안/대응방법:
1. 방안 1
2. 방안 2
```

**예시 1**: SQL Injection
```
✅ 좋은 답안:
취약점:
- 입력값 검증 부재
- 동적 쿼리 사용
- DB 정보 유출/변조 위험

대응방법:
1. Prepared Statement 사용 (필수) ★★★
2. 입력값 검증 (화이트리스트 방식)
3. 에러 메시지 최소화
4. DB 권한 최소화
5. WAF(웹 방화벽) 도입
```

**예시 2**: 패스워드 관리 문제
```
✅ 좋은 답안:
문제점:
- 단순 패스워드 사용
- 평문 저장
- 재사용

해결방안:
1. 복잡도 정책 (10자 이상, 특수문자 조합)
2. 해시+솔트 저장 (SHA-256 이상)
3. 변경 주기 설정 (90일)
4. 재사용 제한 (최근 5개)
5. 2단계 인증 (MFA) 도입
```

## 📝 답안 작성 핵심 원칙

### 1. 구조화 ★★★

```
✅ 좋은 답안:
명확한 구조
- 번호 매기기 (1, 2, 3)
- 단락 구분
- 들여쓰기

❌ 나쁜 답안:
"SQL Injection은 입력값을 통해 쿼리를 조작하는 공격이고
방어하려면 Prepared Statement를 쓰고 입력값을 검증하고..."
→ 가독성 낮음
```

### 2. 핵심 키워드 포함 ★★★

```
문제: "ISMS-P의 유효기간과 사후관리 주기를 쓰시오"

❌ 나쁜 답안:
"3년, 1년에 1번"

✅ 좋은 답안:
"유효기간: 3년
사후관리: 연 1회 이상"
→ 키워드 명시
```

### 3. 정확한 용어 사용 ★★★

```
❌ 피해야 할 표현:
"대충", "약", "비슷한", "거의"

✅ 사용해야 할 표현:
"정확히", "반드시", "필수", "의무"
```

### 4. 단위/숫자 명시 ★★★

```
❌ 나쁜 답안:
"90일마다 변경"

✅ 좋은 답안:
"일반 계정: 90일마다 변경
특권 계정: 60일마다 변경"
```

### 5. 영문 병기 (선택) ★★

```
✅ 좋은 답안:
"CIA Triad:
- C (Confidentiality, 기밀성)
- I (Integrity, 무결성)
- A (Availability, 가용성)"

→ 영문 약어 문제 대비
```

## 🔴 Part별 서술형 핵심 개념

### Part 1-5 (PLAN - 계획)

**Part 1: 보안 기본 원칙**
```
자주 나오는 개념:
- CIA Triad 설명
- 물리적 보안 구역 분류
- Clear Desk/Screen 정책
```

**Part 2: 접근통제 모델**
```
비교 문제 빈출:
- DAC vs MAC vs RBAC
- Bell-LaPadula vs Biba
- 강제적 vs 임의적 접근통제
```

**Part 3: ISMS-P**
```
절차/숫자 문제 빈출:
- ISMS-P 인증 절차 7단계
- 3개 영역 (16+64+22)
- CISO 의무 지정 (100만명/100억)
- 사후관리 (연 1회)
```

**Part 4: 위험관리**
```
공식/전략 문제 빈출:
- 위험도 = 자산가치 × 위협 × 취약점
- 위험대응 4전략 (회피/전가/감소/수용)
- 위험평가 방법론 비교
```

**Part 5: 보안정책 및 표준**
```
순서/비교 문제 빈출:
- 정책→표준→지침→절차
- ISO 27001 vs 27002
- PDCA 사이클
- CC 인증 EAL 등급
- NIST CSF 5대 기능
```

## ✍️ 실전 답안 작성 예시

### 예시 1: 복합 문제

**문제**: "SQL Injection의 정의, 공격 원리, 방어 방법을 서술하시오" (10점)

**✅ 만점 답안**:
```
1. 정의
웹 애플리케이션의 입력값 검증 부재를 이용하여
악의적인 SQL 쿼리를 삽입하는 공격 기법

2. 공격 원리
(1) 입력 폼에 SQL 명령어 삽입
    예: admin' OR '1'='1
(2) 동적 쿼리에 그대로 반영
(3) 의도하지 않은 쿼리 실행
(4) DB 정보 유출, 인증 우회, 데이터 변조

3. 방어 방법
(1) Prepared Statement 사용 (필수) ★★★
    - 쿼리와 데이터 분리
    - 파라미터 바인딩
(2) 입력값 검증 (화이트리스트 방식)
(3) 에러 메시지 최소화
(4) DB 계정 권한 최소화
(5) WAF(웹 방화벽) 도입
```

**배점 분석**:
- 정의 (2점)
- 공격 원리 (3점)
- 방어 방법 (5점)

### 예시 2: 계산 포함 서술형

**문제**: "chmod 755의 의미를 설명하고, 각 자리수가 나타내는 권한을 쓰시오" (6점)

**✅ 만점 답안**:
```
1. chmod 755의 의미
파일/디렉토리의 권한을 8진수로 설정하는 명령어

2. 각 자리수 권한
7 (소유자): rwx (읽기 + 쓰기 + 실행) = 4+2+1
5 (그룹): r-x (읽기 + 실행) = 4+0+1
5 (기타): r-x (읽기 + 실행) = 4+0+1

3. 권한 표시
-rwxr-xr-x

4. 일반적 사용
실행 파일, 디렉토리에 많이 사용
```

### 예시 3: 비교형

**문제**: "전체 백업, 증분 백업, 차등 백업을 비교 설명하시오" (9점)

**✅ 만점 답안**:
```
1. 전체 백업 (Full Backup)
- 모든 데이터 백업
- 복구 가장 빠름 (1개 파일만 필요)
- 시간/용량 가장 많이 소요
- 주기: 주 1회

2. 증분 백업 (Incremental Backup)
- 마지막 백업 이후 변경분만 백업
- 시간/용량 가장 적음
- 복구 느림 (전체 + 모든 증분 필요)
- 주기: 일 1회

3. 차등 백업 (Differential Backup)
- 마지막 전체 백업 이후 변경분 백업
- 시간/용량 중간
- 복구 중간 (전체 + 마지막 차등)
- 주기: 일 1회

비교표:
        속도   용량   복구속도
전체    느림   크다   빠름
증분    빠름   작다   느림
차등    중간   중간   중간
```
