```
3년 (사후관리 연 1회 이상 필수)
```

### 문제 1-3: Clear Desk 정책과 Clear Screen 정책을 각각 설명하시오 (6점)

**✅ 모범 답안**:
```
[Clear Desk 정책]
업무 종료 시 책상 위의 중요 문서, 저장매체, 출력물 등을
잠금장치가 있는 서랍이나 캐비닛에 보관하는 물리적 보안 정책

목적: 문서 분실, 도난, 무단 열람 방지

[Clear Screen 정책]
업무 이탈 시 컴퓨터 화면을 잠금(Screen Lock) 설정하여
화면에 표시된 정보가 타인에게 노출되지 않도록 하는 정책

방법:
- Windows: Win + L
- Linux: Ctrl + Alt + L
- 자동 화면 잠금: 5~10분 이내 설정 권장

목적: 정보 유출 방지, 무단 접근 차단
```

**채점 기준**:
- Clear Desk 정의 및 목적 (3점)
- Clear Screen 정의 및 방법 (3점)

### 문제 3-2: /etc/passwd와 /etc/shadow 파일의 차이를 설명하시오 (6점)

**✅ 모범 답안**:
```
[/etc/passwd]
- 권한: 644 (모든 사용자 읽기 가능)
- 내용: 사용자 계정 정보
- 필드: 7개
  username:x:UID:GID:설명:홈디렉토리:쉘
  예) root:x:0:0:root:/root:/bin/bash
- 패스워드: x 또는 * (실제 패스워드 없음)
- 보안: 낮음 (누구나 읽기 가능)

[/etc/shadow]
- 권한: 400 또는 600 (root만 읽기 가능)
- 내용: 암호화된 패스워드 및 정책
- 필드: 9개
  username:암호화패스워드:최종변경일:최소일:최대일:경고일:...
- 패스워드: 해시값 저장 (SHA-512 등)
- 보안: 높음 (root만 접근)

[보안 강화 목적]
과거 /etc/passwd에 패스워드가 저장되어 보안 취약
→ /etc/shadow로 분리하여 root만 접근 가능하도록 개선
```

**채점 기준**:
- /etc/passwd 특징 (2점)
- /etc/shadow 특징 (2점)
- 보안 강화 목적 (2점)

### 문제 5-2: 직무 분리(Separation of Duties) 원칙의 목적과 적용 예시를 설명하시오 (6점)

**✅ 모범 답안**:
```
[정의]
한 사람이 업무의 전 과정을 단독으로 처리하지 못하도록
업무를 분리하여 부정행위와 오류를 방지하는 내부 통제 원칙

[목적]
1. 내부 부정 방지
   - 한 사람의 단독 행위로 부정 불가능
   - 공모가 필요하여 부정 난이도 증가

2. 오류 감소
   - 상호 검증 통해 실수 발견
   - 이중 확인 체계

3. 견제와 균형 (Check and Balance)
   - 권한 집중 방지
   - 상호 감시

[적용 예시]
1. 시스템 개발 ≠ 시스템 운영
   - 개발자가 운영 권한 가지면 백도어 삽입 가능

2. 결제 승인자 ≠ 결제 실행자
   - 승인과 실행을 분리하여 횡령 방지

3. 감사 대상자 ≠ 감사자
   - 자기 감사 금지

4. 보안 정책 수립자 ≠ 보안 감사자
   - 독립성 확보

5. 데이터 입력 ≠ 데이터 승인
   - 데이터 무결성 보장
```

**채점 기준**:
- 정의 및 목적 (3점)
- 적용 예시 3가지 이상 (3점)

```
   - AD, 이메일, VPN, 업무 시스템 계정
   - 자동화 시스템 구축 (HR 연동)

2. 접근 권한 즉시 회수
   - 네트워크 접근 차단
   - 원격 접속(VPN, RDP) 즉시 차단
   - 빌딩 출입 카드 회수

3. 자산 반납 확인
   - 체크리스트 작성
   - 노트북, USB, 출입카드, 문서 등
   - 반납 확인서 징구

4. 보안 서약 연장
   - 퇴직 후에도 비밀유지 의무 지속
   - 영업비밀, 개인정보 유출 금지
   - 법적 책임 명시

5. 데이터 백업 및 이관
   - 업무 자료 백업
   - 후임자에게 인수인계
   - 개인 데이터는 삭제

6. 퇴직자 면담
   - 보안 준수 사항 재교육
   - 경쟁사 이직 시 주의사항
   - 접근 금지 정보 명시
```

**채점 기준**:
- 문제점 3가지 이상 (4점)
- 대응 방안 4가지 이상 (4점)

### 문제 6-2: 로그 관리의 보안 요구사항과 외부 백업이 필요한 이유를 설명하시오 (7점)

**✅ 모범 답안**:
```
[로그 관리 보안 요구사항]

1. 수집 대상
   - 인증/인가 로그 (로그인, 로그아웃, 권한 변경)
   - 중요 자산 접근 로그
   - 보안 장비 로그 (방화벽, IDS/IPS)
   - 시스템 로그 (오류, 이벤트)

2. 보관 기간
   - 일반 로그: 6개월 이상
   - 개인정보 처리 로그: 1년 이상
   - 전자금융거래 로그: 5년 이상

3. 위변조 방지
   - 로그 무결성 보장 (해시값 생성)
   - 로그 암호화
   - 수정 불가능 설정 (Append-Only)

4. 접근 통제
   - 최소 권한 원칙
   - 로그 관리자만 접근
   - 감사 증적 남기기

[외부 백업 필요성]

1. DBA/관리자 삭제 불가능
   문제: 내부 저장 시 DBA가 로그 삭제 가능
   해결: 외부 로그 서버로 실시간 전송
        → DBA도 삭제 불가능
        → 내부자 범죄 추적 가능

2. 시스템 장애 대비
   문제: DB 서버 장애 시 로그 손실
   해결: 별도 로그 서버에 백업
        → 원본 손실 시에도 복구 가능

3. 저장 공간 확보
   문제: DB 서버 디스크 부족
   해결: 외부 저장소 활용
        → 장기 보관 용이

4. 침해사고 분석
   문제: 공격자가 로그 삭제 시도
   해결: 외부 백업으로 증거 보존
        → 포렌식 분석 가능

[구현 방법]
- Syslog 서버 구축
- SIEM(Security Information and Event Management) 도입
- 클라우드 로그 저장소 활용
```

**채점 기준**:
- 로그 관리 요구사항 (3점)
- 외부 백업 필요성 (4점)
