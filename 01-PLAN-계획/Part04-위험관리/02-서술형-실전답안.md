## 📝 유형 1: 개념 설명형 + 계산

### 문제 1-1: 위험(Risk)의 정의와 위험도 계산 공식을 쓰고, 주어진 조건으로 위험도를 계산하시오 (8점)

**조건**:
- 자산가치: 5 (매우 중요)
- 위협 발생 가능성: 4 (높음)
- 취약점 심각도: 3 (보통)

**✅ 모범 답안**:
```
[위험의 정의]
위협(Threat)이 취약점(Vulnerability)을 이용하여
자산(Asset)에 손실을 입힐 가능성

[위험도 계산 공식]
위험도(Risk) = 자산가치 × 위협 × 취약점

[계산]
위험도 = 5 × 4 × 3
      = 60

[위험도 등급]
60점 → 상(High) 등급
- 상 (High): 60 이상 → 즉시 조치 필요
- 중 (Medium): 30~59 → 1개월 이내 조치
- 하 (Low): 29 이하 → 6개월 이내 검토

[조치 방안]
위험도 60(상등급)이므로 즉각적인 보안대책 필요:
- 취약점 제거 (패치 적용, 설정 강화)
- 위협 완화 (방화벽, IDS/IPS 도입)
- 자산 보호 강화 (암호화, 백업)
```

**채점 기준**:
- 위험 정의 (2점)
- 공식 (2점)
- 계산 과정 및 답 (2점)
- 등급 및 조치 (2점)

### 문제 1-2: 잔여위험(Residual Risk)의 개념과 관리 방법을 설명하시오 (6점)

**✅ 모범 답안**:
```
[잔여위험의 정의]
보안대책을 적용한 후에도 남아있는 위험

또는

위험 감소 조치를 수행한 후에도
완전히 제거되지 않고 수용하기로 결정한 위험

[발생 원인]
1. 비용 제약
   - 모든 위험을 100% 제거하는 것은 비용이 너무 큼
   - 비용 대비 효과 고려

2. 기술적 한계
   - 현재 기술로 완벽한 대응 불가능
   - 새로운 취약점 지속 발견

3. 업무 영향
   - 과도한 보안 통제는 업무 효율 저하
   - 사용자 편의성과 균형 필요

[계산 예시]
초기 위험도: 100
보안대책 효과: 70
잔여위험: 100 - 70 = 30

[관리 방법]
1. 경영진 승인
   - 잔여위험 수준을 경영진에게 보고
   - 수용 여부 승인 획득
   - 책임 소재 명확화

2. 문서화
   - 잔여위험 목록 작성
   - 수용 근거 문서화
   - 승인 증적 보관

3. 주기적 재평가
   - 최소 연 1회 재평가
   - 위협 환경 변화 반영
   - 필요 시 추가 대책 수립

4. 모니터링
   - 잔여위험 발현 여부 감시
   - 실제 피해 발생 시 즉시 대응
```

**채점 기준**:
- 정의 (2점)
- 발생 원인 (2점)
- 관리 방법 (2점)

## 📝 유형 2: 비교/대조형

### 문제 2-1: 4가지 위험대응 전략을 비교 설명하고, 각각의 적용 예시를 드시오 (10점)

**✅ 모범 답안**:
```
[1. 위험 회피 (Risk Avoidance)]
정의: 위험한 활동이나 프로세스 자체를 중단/포기

특징:
- 위험을 완전히 제거 (0%)
- 가장 확실한 방법
- 업무 제한/중단 발생

적용 예시:
- 보안이 취약한 온라인 서비스 중단
- 해킹 위험 높은 구형 시스템 폐기
- 위험 국가 진출 포기

[2. 위험 전가 (Risk Transfer)]
정의: 위험을 제3자에게 이전

특징:
- 손실 부담을 외부로 이전
- 비용 발생 (보험료, 외주비)
- 법적 책임은 여전히 존재

적용 예시:
- 사이버 보험 가입
- 클라우드로 서버 이전 (IDC 아웃소싱)
- 보안 관제 업무 외주
- 계약서에 면책 조항 명시

[3. 위험 감소/완화 (Risk Mitigation)]
정의: 보안대책을 구현하여 위험 수준 낮춤

특징:
- 가장 일반적이고 많이 사용
- 업무 지속 가능
- 비용 대비 효과 우수
- 잔여위험 존재

적용 예시:
- 방화벽 설치
- 백신 도입
- 암호화 적용
- IDS/IPS 구축
- Prepared Statement 사용 (SQL Injection 방어)
- 패치 적용
- 백업 수행

[4. 위험 수용 (Risk Acceptance)]
정의: 일정 수준 이하의 위험을 그대로 수용

특징:
- 비용 절감
- 위험 발생 시 전액 손실
- 경영진 승인 필요

적용 예시:
- 발생 가능성 낮은 위험
- 대응 비용 > 예상 손실
- 잔여위험 수용

[비교표]
전략     위험제거   비용    업무영향   사용빈도
회피     100%      낮음    높음      낮음
전가     부분      높음    낮음      중간
감소     부분      중간    중간      높음
수용     0%        없음    없음      낮음
```

**채점 기준**:
- 4가지 전략 정의 (4점)
- 각 전략 특징 (3점)
- 적용 예시 (3점)

### 문제 2-2: 위험평가 방법론 4가지를 비교하고, 가장 효과적인 방법과 그 이유를 설명하시오 (8점)

**✅ 모범 답안**:
```
[1. 베이스라인 접근법 (Baseline Approach)]
방법: 표준화된 보안대책 체크리스트 일괄 적용

장점:
- 빠르고 간편
- 비용 효율적
- 일관성 유지
- 초보자도 수행 가능

단점:
- 조직 특성 반영 어려움
- 불필요한 통제 적용 가능
- 새로운 위협 대응 미흡

예시:
- KISA 취약점 점검 가이드 전체 적용
- CIS Controls 20개 일괄 적용

[2. 비정형 접근법 (Informal Approach)]
방법: 전문가의 경험과 직관에 의존

장점:
- 유연성
- 신속한 대응
- 전문가 경험 활용

단점:
- 일관성 부족
- 주관적 판단
- 문서화 미흡
- 재현성 낮음

예시:
- 소규모 조직
- 긴급 상황
- 초기 검토 단계

[3. 상세 위험분석 (Detailed Risk Analysis)]
방법: 체계적이고 정량적인 위험분석 (자산→위협→취약점→위험도)

장점:
- 정확하고 신뢰성 높음
- 조직 특성 완벽 반영
- 경영진 의사결정 지원
- 문서화 체계적

단점:
- 시간 많이 소요
- 비용 높음
- 전문가 필요
- 유지관리 부담

예시:
- 중요 시스템 (금융, 의료)
- 대규모 조직

[4. 복합 접근법 (Combined Approach)] ★★★
방법: 위 3가지 방법 혼합 사용

장점:
- 효율성과 정확성 균형
- 비용 대비 효과 우수
- 유연한 적용
- 실무에서 가장 실용적

적용:
- 일반 자산: 베이스라인 (빠르게)
- 중요 자산: 상세 위험분석 (정확하게)
- 긴급 상황: 비정형 (신속하게)

[가장 효과적인 방법: 복합 접근법]
이유:
1. 자산 중요도에 따라 차별화
   - 핵심 자산에는 상세 분석 집중
   - 일반 자산에는 베이스라인 적용

2. 비용 효율성
   - 모든 자산에 상세 분석은 비용 과다
   - 선택과 집중

3. 실무 적합성
   - 시간/비용/정확성 균형
   - 대부분의 조직이 채택
```

**채점 기준**:
- 4가지 방법론 설명 (4점)
- 장단점 비교 (2점)
- 가장 효과적인 방법 및 이유 (2점)

### 문제 2-3: 위험(Risk), 위협(Threat), 취약점(Vulnerability)의 차이를 비교하고, 세 개념의 관계를 설명하시오 (9점) ★★★

**✅ 모범 답안**:
```
[위험 vs 위협 vs 취약점 비교]

| 구분 | 위험 (Risk) | 위협 (Threat) | 취약점 (Vulnerability) |
|------|------------|--------------|---------------------|
| **정의** | 위협이 취약점을 이용하여 자산에 손실을 입힐 **가능성** ★★★ | 자산에 해를 끼칠 수 있는 **잠재적 원인** ★★★ | 위협에 의해 악용될 수 있는 시스템의 **약점** ★★★ |
| **성격** | 결과 (Result) | 원인 (Cause) | 조건 (Condition) |
| **존재** | 위협 + 취약점이 있을 때 발생 | 항상 존재 가능 | 시스템에 내재 |
| **예시 1** | 고객정보 유출 위험 | 해커 | 패치되지 않은 웹서버 |
| **예시 2** | 랜섬웨어 감염 위험 | 랜섬웨어 | 약한 패스워드 |
| **예시 3** | 서비스 중단 위험 | 지진 | 단일 데이터센터 |
| **측정** | 정량적 (위험도 점수) | 정성적 (가능성) | 정량적 (CVSS 점수) |
| **통제 방법** | 위험 대응 전략 (회피/전가/감소/수용) | 위협 완화 | 취약점 제거/패치 |

[상세 설명]

1. 위협 (Threat) ★★★
   정의: 자산에 손실을 발생시킬 수 있는 잠재적 원인이나 사건

   특징:
   - 조직 외부에서 발생하는 경우가 많음
   - 완전히 제거 불가능
   - 지속적으로 변화

   분류:
   - 자연적 위협: 지진, 홍수, 화재
   - 인적 위협 (고의): 해킹, 악성코드, 내부자 공격
   - 인적 위협 (비고의): 실수, 오조작
   - 환경적 위협: 정전, 통신 장애

   예시:
   - 외부 해커 공격 시도
   - DDoS 공격
   - 랜섬웨어
   - SQL Injection 공격
   - 태풍, 낙뢰

2. 취약점 (Vulnerability) ★★★
   정의: 위협이 악용할 수 있는 시스템이나 프로세스의 약점

   특징:
   - 조직 내부에 존재
   - 제거 또는 완화 가능
   - 시간이 지나면서 새로 발견

   분류:
   - 기술적 취약점:
     - 소프트웨어 버그
     - 패치되지 않은 시스템
     - 설정 오류
     - 약한 암호화

   - 관리적 취약점:
     - 보안 정책 부재
     - 교육 미흡
     - 백업 미수행

   - 물리적 취약점:
     - 출입통제 미비
     - 단일 전원

   예시:
   - Windows SMB 취약점 (MS17-010)
   - SQL Injection 취약점
   - 기본 패스워드 사용 (admin/admin)
   - 디렉토리 리스팅 허용
   - 패치되지 않은 Apache 웹서버

3. 위험 (Risk) ★★★
   정의: 위협이 취약점을 악용하여 자산에 손실을 입힐 가능성

   특징:
   - 위협과 취약점이 모두 있을 때만 발생
   - 측정 및 정량화 가능
   - 관리 및 통제 대상

   공식:
   위험 (Risk) = 자산가치 × 위협 × 취약점

   예시:
   - 패치되지 않은 웹서버(취약점) + 해커(위협) = 웹사이트 해킹 위험
   - 약한 패스워드(취약점) + 랜섬웨어(위협) = 데이터 암호화 위험
   - 단일 전원(취약점) + 정전(위협) = 서비스 중단 위험

[세 개념의 관계] ★★★

관계식:
```
위협 (Threat) × 취약점 (Vulnerability) → 위험 (Risk)

위협이 존재하고 + 취약점이 존재하면 → 위험 발생
위협만 있고 취약점 없으면 → 위험 없음
취약점만 있고 위협 없으면 → 위험 낮음
```

실제 사례로 이해:

사례 1: WannaCry 랜섬웨어 (2017)
```
자산: 병원 환자 기록 DB
위협: WannaCry 랜섬웨어 (위협 발생 가능성: 높음)
취약점: Windows SMB 취약점 (MS17-010) 패치 안 됨
위험: 환자 기록 암호화로 병원 마비 위험

위험도 계산:
자산가치(5) × 위협(5) × 취약점(5) = 125 (매우 높음)

대응:
- 위협 완화: 방화벽으로 SMB 포트(445) 차단
- 취약점 제거: MS17-010 패치 적용
- 위험 감소: 네트워크 분리, 백업 강화
→ 위험도 낮아짐
```

사례 2: SQL Injection 공격
```
자산: 고객 개인정보 DB
위협: 외부 해커의 SQL Injection 공격 시도
취약점:
  - 입력 값 검증 미흡
  - Prepared Statement 미사용
  - 데이터베이스 권한 과다
위험: 고객 정보 대량 유출 위험

위험도: 높음 (자산가치 높음, 위협 존재, 취약점 多)

대응:
- 취약점 제거:
  - Prepared Statement 적용
  - 입력 값 검증 강화
  - DB 계정 권한 최소화
- 위협 완화:
  - WAF (Web Application Firewall) 도입
  - SQL Injection 패턴 차단
→ 위험 감소
```

[핵심 포인트]

위협만 있을 때:
```
위협: 해커가 SQL Injection 시도
취약점: 없음 (Prepared Statement 사용, 입력 검증 완벽)
→ 위험: 낮음 (공격해도 실패)
```

취약점만 있을 때:
```
위협: 없음 (인터넷에 노출 안 됨, 외부 접근 차단)
취약점: SQL Injection 취약점 존재
→ 위험: 낮음 (공격자가 접근 불가)
```

위협 + 취약점 모두 있을 때:
```
위협: 해커가 시도
취약점: SQL Injection 취약점
→ 위험: 높음 (공격 성공 가능성 높음)
```

[실전 적용]

위험 관리 프로세스:
```

### 문제 3-2: CIA Triad(정보보호의 3대 목표)를 설명하고, 각각을 보장하는 보안 기술을 3가지씩 쓰시오 (9점)

**✅ 모범 답안**:
```
[C - Confidentiality (기밀성)]
정의: 인가된 사용자만 정보에 접근할 수 있도록 보장

보안 기술:
1. 암호화
   - AES-256, RSA 등
   - 데이터 암호화, 통신 암호화

2. 접근 통제
   - 계정/패스워드 인증
   - 방화벽, ACL
   - Need-to-Know 원칙

3. 권한 관리
   - 최소 권한 원칙
   - RBAC (역할 기반 접근통제)
   - 특권 계정 관리

위협: 도청, 스니핑, 정보 유출

[I - Integrity (무결성)]
정의: 정보의 정확성과 완전성 보장 (무단 수정/변조 방지)

보안 기술:
1. 해시 함수
   - SHA-256, SHA-512
   - 파일 무결성 검증

2. 전자서명
   - RSA, ECDSA
   - 송신자 인증 + 무결성

3. MAC (Message Authentication Code)
   - HMAC
   - 메시지 인증

기타:
- 버전 관리
- 감사 로그
- Tripwire (파일 무결성 검사)

위협: 위변조, 중간자 공격

[A - Availability (가용성)]
정의: 필요할 때 정보와 시스템을 사용할 수 있도록 보장

보안 기술:
1. 백업
   - 전체/증분/차등 백업
   - 주기적 백업 (일/주)
   - 원격지 백업

2. 이중화 (Redundancy)
   - 서버 이중화 (Active-Active, Active-Standby)
   - 네트워크 이중화
   - 전원 이중화 (UPS, 발전기)

3. 재해복구 (DR)
   - Hot Site, Warm Site, Cold Site
   - 재해복구 계획 (DRP)
   - 업무연속성 계획 (BCP)

기타:
- DDoS 방어 (방화벽, IPS)
- 클러스터링
- 부하 분산 (Load Balancing)

위협: DDoS 공격, 장애, 재해

[추가 목표]
- Authenticity (진정성): 정보 출처 확인
- Non-repudiation (부인방지): 행위 부인 불가
- Accountability (책임추적성): 행위 추적 가능
```

**채점 기준**:
- C/I/A 정의 (3점)
- 각각의 보안 기술 3가지씩 (6점)
