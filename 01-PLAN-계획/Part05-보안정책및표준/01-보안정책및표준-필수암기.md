```

   - 권고사항 ★★

   - 모범 사례

4. 절차 (Procedure)
   - 상세 실행 방법

   - 가장 구체적

← 2024년 실기 필수!
```

## 🔴 보안 정책 체계 상세

### 1. 정책 (Policy) ★★★

**정의**:
```
조직의 보안 목표와 방향을 제시하는 최상위 문서
경영진이 승인하고 전 조직에 적용
```

**특징**:
```
✓ 추상적이고 원칙적
✓ 경영진 승인 필수 ★★★
✓ 변경 빈도 낮음 (연 1회 또는 필요 시)
✓ 전 직원 준수 의무
```

**작성 원칙**:
```
1. 명확성: 모호한 표현 지양
2. 일관성: 다른 정책과 모순 없음
3. 실현 가능성: 현실적으로 구현 가능
4. 포괄성: 조직 전체 적용
```

**예시**:
```
"정보보호 정책"

1. 목적
   본 정책은 조직의 정보자산을 보호하고
   정보보호 관리체계를 수립하기 위함

2. 적용 범위
   전 임직원 및 협력업체

3. 기본 원칙
   - 모든 정보자산은 기밀성, 무결성, 가용성을 보장한다
   - 정보 접근은 최소 권한 원칙을 따른다
   - 정보보호 사고 발생 시 즉시 보고한다

4. 책임
   - CISO: 정보보호 총괄
   - 부서장: 부서 내 정보보호 관리
   - 직원: 정책 준수
```

**실기 출제**: ★★★
- "최상위 보안 문서는?" → 정책
- "경영진이 승인하는 문서는?" → 정책

---

### 2. 표준 (Standard) ★★★

**정의**:
```
정책을 구현하기 위한 구체적인 기준
필수 준수 사항
```

**특징**:
```
✓ 구체적이고 측정 가능
✓ 필수 준수 (Mandatory) ★★★
✓ 기술적 요구사항 명시
✓ 정기적 검토/업데이트 (연 1회)
```

**예시**:
```
"패스워드 표준"

1. 길이
   - 최소 10자 이상 ★★★

2. 복잡도
   - 영문 대문자
   - 영문 소문자
   - 숫자
   - 특수문자
   → 4가지 중 3가지 이상 조합 ★★★

3. 변경 주기
   - 일반 계정: 90일마다 변경 ★★★
   - 특권 계정: 60일마다 변경 ★★★

4. 재사용 제한
   - 최근 5개 패스워드 재사용 금지 ★★

5. 초기 패스워드
   - 즉시 변경 ★★

6. 금지 사항
   - 사전 단어 사용 금지
   - 사용자 ID와 동일 금지
   - 연속/반복 문자 금지 (예: 1234, aaaa)
```

**실기 출제**: ★★★
- "정책을 구현하는 구체적 기준은?" → 표준
- "필수 준수 사항은?" → 표준
- 패스워드 표준 상세 내용 빈출

---

### 3. 지침 (Guideline) ★★

**정의**:
```
표준을 효과적으로 구현하기 위한 권고사항
준수 의무는 없음 (권장)
```

**특징**:
```
✓ 권고 사항 (Recommended)
✓ 모범 사례 제시
✓ 유연한 적용
✓ 준수 강제 안 함
```

**예시**:
```
"안전한 패스워드 생성 가이드라인"

1. 패스워드 생성 권장 방법
   - 문장의 첫 글자 조합
     예: "I love security in 2024!"
     → Ilsi2024!

   - 특수문자로 단어 연결
     예: Coffee@Morning#2024

   - 패스프레이즈 사용
     예: Blue$Sky#Flying@2024

2. 피해야 할 패스워드
   - 생일, 전화번호
   - 키보드 나열 (qwerty, asdf)
   - 흔한 단어 (password, admin)

3. 패스워드 관리자 사용 권장
   - 1Password, LastPass 등
   - 강력한 패스워드 자동 생성
   - 안전한 저장
```

**실기 출제**: ★★
- "권고사항을 제시하는 문서는?" → 지침

---

### 4. 절차 (Procedure) ★★

**정의**:
```
업무 수행을 위한 상세한 단계별 실행 방법
가장 구체적인 문서
```

**특징**:
```
✓ 단계별 작업 지침
✓ 스크린샷, 체크리스트 포함
✓ 누구나 따라할 수 있도록 상세
✓ 자주 업데이트
```

**예시**:
```
"Windows 패스워드 변경 절차"

1. Ctrl + Alt + Del 키 동시 누름

2. "암호 변경" 클릭

3. 기존 패스워드 입력

4. 새 패스워드 입력
   - 10자 이상
   - 영문대소문자+숫자+특수문자 조합

5. 새 패스워드 확인 입력

6. Enter 또는 "확인" 클릭

7. "암호가 변경되었습니다" 메시지 확인

8. 변경 일자 기록
```

**실기 출제**: ★
- "가장 구체적인 실행 방법은?" → 절차

## 🔴 주요 보안 표준

### 1. ISO/IEC 27001 ★★★

**개요**:
```
정보보호 관리체계(ISMS) 국제 표준
PDCA 사이클 기반 지속적 개선
```

**PDCA 사이클**: ★★★
```
Plan (계획):
- 정보보호 정책 수립
- 범위 설정
- 위험평가 수행 ★★★
- 보안 목표 설정
- 보안대책 선정

Do (실행):
- 보안대책 구현
- 보안 교육 실시
- 인식 제고 활동
- 정책/절차 배포

Check (점검):
- 보안 모니터링 ★★★
- 로그 분석
- 내부 심사 (연 1회 이상) ★★★
- 경영진 검토
- 측정 및 평가

Act (개선):
- 시정조치 (Corrective Action) ★★★
- 예방조치 (Preventive Action)
- 지속적 개선
- 정책/절차 업데이트
```

**인증 절차**:
```
1. 인증 신청
2. 1단계 심사 (문서 심사)
3. 2단계 심사 (현장 심사)
4. 시정조치
5. 인증 결정
6. 인증서 발급
7. 사후 심사 (연 1회)
```

**유효기간**: ★★
```
3년 (사후심사 연 1회 필수)
```

**실기 출제**: ★★★
- PDCA 사이클 각 단계 활동
- 내부 심사 주기 (연 1회)
- 유효기간 (3년)

### 2. ISO/IEC 27002 ★★

**개요**:
```
정보보호 통제 구현 지침
ISO 27001의 부속 표준
```

**구성**: ★★
```
14개 영역, 114개 통제 항목 (2022 개정판 기준)

14개 영역:
1. 조직적 통제 (Organizational Controls)
2. 인적 통제 (People Controls)
3. 물리적 통제 (Physical Controls)
4. 기술적 통제 (Technological Controls)
```

**ISO 27001 vs 27002**: ★★★
```
ISO 27001:
- "무엇을" (What)
- 요구사항 (Requirements)
- 인증 대상

ISO 27002:
- "어떻게" (How)
- 구현 가이드 (Guidelines)
- 참고 자료
```

**실기 출제**: ★★
- 114개 통제 항목
- ISO 27001과 27002의 차이

### 3. NIST Cybersecurity Framework ★★★

**개요**:
```
미국 NIST(국립표준기술연구소) 개발
사이버보안 리스크 관리 프레임워크
```

**5대 핵심 기능**: ★★★
```
1. Identify (식별) ★★★
   - 자산 관리
   - 비즈니스 환경 이해
   - 거버넌스
   - 위험평가
   - 리스크 관리 전략

2. Protect (보호) ★★★
   - 접근통제
   - 인식 및 교육
   - 데이터 보안
   - 보호 프로세스
   - 보호 기술

3. Detect (탐지) ★★★
   - 이상 및 이벤트
   - 보안 지속 모니터링
   - 탐지 프로세스

4. Respond (대응) ★★★
   - 대응 계획
   - 커뮤니케이션
   - 분석
   - 완화
   - 개선

5. Recover (복구) ★★★
   - 복구 계획
   - 개선
   - 커뮤니케이션
```

**암기법**: ★★★
```
"식보탐대복"

식 - Identify
보 - Protect
탐 - Detect
대 - Respond
복 - Recover
```

**실기 출제**: ★★★
- 5대 기능 나열
- 각 기능의 역할 설명

4. 보안 설정 구성
5. 계정 관리
6. 접근통제 관리

기초 통제 (IG2):
7. 지속적 취약점 관리
8. 감사 로그 관리
9. 이메일 및 웹브라우저 보호
10. 악성코드 방어
11. 데이터 복구
12. 네트워크 인프라 관리
13. 네트워크 모니터링 및 방어
14. 보안 인식 및 기술 교육
15. 서비스 제공자 관리
16. 애플리케이션 소프트웨어 보안

조직 통제 (IG3):
17. 사고 대응 관리
18. 침투 테스트
19. 비즈니스 연속성
20. 보안 프로그램
```

**실기 출제**: ★★
- 총 개수 (20개)
- 기본 통제 주요 항목

### 5. CC 인증 (Common Criteria) ★★★

**개요**:
```
ISO/IEC 15408 국제 표준
IT 제품의 보안 기능 평가 인증
```

**EAL 등급 (1~7)**: ★★★
```
EAL1 (Functionally Tested)
- 기능 테스트
- 가장 낮은 등급

EAL2 (Structurally Tested)
- 구조 테스트
- 개발 문서 검토

EAL3 (Methodically Tested and Checked)
- 체계적 테스트 및 검토

EAL4 (Methodically Designed, Tested and Reviewed)
- 체계적 설계, 테스트 및 검토
- 상용 제품 일반적 등급 ★★★

EAL5 (Semiformally Designed and Tested)
- 준형식적 설계 및 테스트

EAL6 (Semiformally Verified Design and Tested)
- 준형식적 검증 설계 및 테스트

EAL7 (Formally Verified Design and Tested)
- 형식적 검증 설계 및 테스트
- 가장 높은 등급 (군사용)
```

**보호프로파일 (PP)**: ★★
```
특정 유형 제품의 보안 요구사항
예: 방화벽 PP, IPS PP, 스마트카드 PP
```

**유효기간**: ★★★
```
5년
```

**실기 출제**: ★★★
- EAL 등급 범위 (1~7)
- 일반적 등급 (EAL4)
- 유효기간 (5년)

### 6. 국가정보보안기본지침 ★★★

**개요**:
```
국가사이버안전관리규정 제8조에 근거
국가 공공기관 대상 필수 준수 지침
```

**적용 대상**: ★★★
```
1. 국가기관
2. 지방자치단체
3. 공공기관
```

**주요 내용**: ★★★
```
1. 국가사이버안전관리 체계
   - 국가사이버안전센터
   - 분야별 보안관리 체계

2. 정보통신기반시설 보호 ★★★
   - 주요정보통신기반시설 지정
   - 취약점 분석/평가 (연 1회 이상)
   - 보호대책 수립/시행

3. 정보자산 분류 및 관리
   - I급 비밀: 누설 시 국가안전보장에 치명적
   - II급 비밀: 누설 시 국가안전보장에 상당한 위험
   - III급 비밀: 누설 시 국가안전보장에 해로움
   - 대외비: 공개 부적절

4. 암호장비 관리 ★★
   - 국가정보원장 승인 암호장비 사용
   - 암호키 관리 절차

5. 보안감사 ★★★
   - 정기 감사 (연 1회 이상)
   - 수시 감사 (필요 시)
```

**정보통신기반시설**: ★★★
```
정의:
전자적 제어·관리시스템 또는
정보통신망이 파괴·마비될 경우
국가안전보장, 경제·사회에 심각한 영향

예시:
- 전력, 통신, 금융
- 교통, 수도, 가스
- 의료, 방송
```

**주요정보통신기반시설 보호**: ★★★
```
취약점 분석/평가: 연 1회 이상 ★★★
보호계획 수립: 매년
보호조치 이행
침해사고 대응체계 구축
```

**실기 출제**: ★★★
- 적용 대상 (국가 공공기관)
- 정보통신기반시설 정의
- 취약점 분석/평가 주기 (연 1회)
- 정보자산 분류 (I/II/III급)

## 💡 실전 암기 팁

```
"정표지절" 로 암기!

정 - 정책 (Policy) - 경영진 승인
표 - 표준 (Standard) - 필수 준수
지 - 지침 (Guideline) - 권고사항
절 - 절차 (Procedure) - 상세 실행
```

### PDCA 암기 ★★★

```
Plan - 위험평가, 정책수립
Do - 보안대책 구현
Check - 모니터링, 내부심사 (연 1회)
Act - 시정조치, 개선
```

### NIST CSF 5대 기능 암기 ★★★

```
"식보탐대복"

식 - Identify (자산, 위험 식별)
보 - Protect (접근통제, 암호화)
탐 - Detect (모니터링, 탐지)
대 - Respond (사고 대응)
복 - Recover (복구, 백업)
```

### 유효기간 암기 ★★★

```
ISMS-P: 3년 (사후관리 연 1회)
ISO 27001: 3년 (사후심사 연 1회)
CC 인증: 5년

← "33333555" 로 암기!
```

```
EAL1: 기능 테스트 (낮음)
EAL4: 체계적 (일반적) ★★★
EAL7: 형식적 검증 (군사용, 높음)

## 🔥 2024년 출제 경향

### 최빈출 주제 ★★★

1. **보안 문서 체계**
   - 정책→표준→지침→절차 순서
   - 각 단계 특징 (경영진 승인, 필수 준수, 권고, 상세)

2. **PDCA 사이클**
   - Plan/Do/Check/Act 각 단계 활동
   - Check: 내부심사 연 1회 빈출

3. **CC 인증**
   - 유효기간 5년 ★★★
   - EAL 등급 (1~7, 일반적으로 EAL4)

4. **NIST CSF**
   - 5대 기능 나열
   - Identify, Protect, Detect, Respond, Recover

5. **국가정보보안기본지침**
   - 적용 대상 (국가 공공기관)
   - 정보통신기반시설 취약점 분석 (연 1회)

### 실기 답안 작성 팁

```
1. 순서 문제는 번호 매겨 나열
   예: 1. 정책 2. 표준 3. 지침 4. 절차

2. 유효기간은 단위 명시
   예: 5년 (O), 5 (X)

3. 주기는 정확하게
   예: 연 1회 이상 (O), 1년 (△)

4. PDCA는 한글/영문 병기
   예: P (Plan, 계획)

5. 약어는 풀어서 설명
   예: CC (Common Criteria, 공통평가기준)
      EAL (Evaluation Assurance Level, 평가보증등급)
```
