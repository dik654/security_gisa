## 1. 보안 문서 체계

### 문제 1. 보안 문서 체계 4단계와 특징 (20점) ★★★

**문제**:
조직의 정보보호를 위한 보안 문서는 추상적인 순서부터 구체적인 순서로 4단계 체계를 갖춘다. 각 단계의 명칭과 주요 특징을 작성하시오. (20점)

**✅ 모범 답안**:

#### 1. 정책 (Policy) - 5점
**정의**:
- 조직의 보안 목표와 방향을 제시하는 최상위 문서

**주요 특징**:
- 추상적이고 원칙적인 내용
- 경영진 승인 필수
- 조직 전체에 적용
- 변경 빈도 낮음 (연 1회 또는 필요 시)
- 준수 의무 있음

**예시**:
```
"모든 정보자산은 기밀성, 무결성, 가용성을 보장한다"
```

#### 2. 표준 (Standard) - 5점
**정의**:
- 정책을 구현하기 위한 구체적인 기준

**주요 특징**:
- 구체적이고 측정 가능한 내용
- 필수 준수 사항 (Mandatory)
- 기술적 요구사항 명시
- 정기적 검토/업데이트 (연 1회)

**예시**:
```
"패스워드는 10자 이상, 영문대소문자+숫자+특수문자 조합, 90일마다 변경"
```

#### 3. 지침 (Guideline) - 5점
**정의**:
- 표준을 효과적으로 구현하기 위한 권고사항

**주요 특징**:
- 권고 사항 (Recommended)
- 준수 의무 없음
- 모범 사례 제시
- 유연한 적용 가능

**예시**:
```
"패스워드 생성 시 문장의 첫 글자 조합 방식 권장"
```

#### 4. 절차 (Procedure) - 5점
**정의**:
- 업무 수행을 위한 상세한 단계별 실행 방법

**주요 특징**:
- 가장 구체적인 문서
- 단계별 작업 지침
- 스크린샷, 체크리스트 포함
- 누구나 따라할 수 있도록 상세하게 작성

**예시**:
```
"Windows 패스워드 변경 절차:
1. Ctrl+Alt+Del 키 동시 누름
2. '암호 변경' 클릭
3. 기존 패스워드 입력
..."
```

---

**채점 기준**:
- 4단계 명칭 정확히 기재 (각 1점, 총 4점)
- 각 단계별 주요 특징 2가지 이상 기술 (각 3점, 총 12점)
- 추상적→구체적 순서 정확 (2점)
- 예시 또는 실무 적용 언급 (2점)

**핵심 요약**:
```
정책 (Policy)     → 경영진 승인, 최상위, 추상적
표준 (Standard)   → 필수 준수, 구체적 기준
지침 (Guideline)  → 권고사항, 모범 사례
절차 (Procedure)  → 단계별 실행, 가장 구체적
```

**암기 팁**: "정표지절" (정책-표준-지침-절차)

### 문제 2. 정보보호 정책 작성 원칙 (15점) ★★★

**문제**:
조직의 정보보호 정책을 작성할 때 반드시 고려해야 할 4가지 원칙을 설명하시오. (15점)

**✅ 모범 답안**:

#### 1. 명확성 (Clarity) - 4점
**설명**:
- 모호한 표현을 지양하고 명확하게 작성
- 모든 직원이 이해할 수 있는 용어 사용
- 해석의 여지가 없도록 구체적으로 표현

**좋은 예**:
```
"중요 정보는 암호화하여 저장한다"
```

**나쁜 예**:
```
"정보를 적절히 보호한다" (모호함)
```

#### 2. 일관성 (Consistency) - 4점
**설명**:
- 다른 정책이나 규정과 모순되지 않아야 함
- 조직 내 모든 보안 문서 간 일관성 유지
- 상위 법령 및 규제 준수

**예시**:
```
접근통제 정책과 패스워드 정책이 서로 모순되지 않아야 함
```

#### 3. 실현 가능성 (Feasibility) - 4점
**설명**:
- 현실적으로 구현 가능한 내용
- 조직의 기술적, 재정적 역량 고려
- 과도한 요구사항 지양

**좋은 예**:
```
"중요 데이터는 일 1회 백업" (실현 가능)
```

**나쁜 예**:
```
"모든 데이터를 실시간으로 이중화" (과도한 요구)
```

#### 4. 포괄성 (Comprehensiveness) - 3점
**설명**:
- 조직 전체에 적용 가능
- 모든 정보자산과 구성원 포함
- 예외 사항 최소화

**예시**:
```
정책 적용 범위: "전 임직원, 협력업체, 파견직 포함"
```

---

**채점 기준**:
- 4가지 원칙 명칭 기재 (각 1점, 총 4점)
- 각 원칙별 설명 (각 2점, 총 8점)
- 예시 또는 적용 방법 언급 (3점)

**핵심 요약**:
```
1. 명확성: 모호한 표현 지양, 명확한 용어
2. 일관성: 다른 정책과 모순 없음
3. 실현 가능성: 현실적으로 구현 가능
4. 포괄성: 조직 전체 적용
```

## 2. 국제 표준 (ISO)

### 문제 3. ISO 27001 PDCA 사이클 (20점) ★★★

**문제**:
ISO/IEC 27001 정보보호 관리체계의 기반이 되는 PDCA 사이클의 각 단계별 주요 활동을 설명하시오. (20점)

**✅ 모범 답안**:

#### Plan (계획) - 5점
**주요 활동**:
1. **정보보호 정책 수립**
   - 경영진 승인
   - 조직 목표에 부합

2. **범위 설정**
   - 인증 범위 결정
   - 대상 자산 식별

3. **위험평가 수행** (가장 중요 ★★★)
   - 자산 식별
   - 위협 및 취약점 분석
   - 리스크 = 자산 × 위협 × 취약점
   - 리스크 평가 및 우선순위 결정

4. **보안 목표 설정**
   - 측정 가능한 목표 수립

5. **보안대책 선정**
   - ISO 27002 통제 항목 참고
   - 리스크 대응 방안 결정

#### Do (실행) - 5점
**주요 활동**:
1. **보안대책 구현**
   - 기술적 통제 구현 (방화벽, IDS/IPS, 암호화 등)
   - 관리적 통제 구현 (정책, 절차 수립)
   - 물리적 통제 구현 (출입통제, CCTV 등)

2. **보안 교육 실시**
   - 전 직원 대상 정기 교육
   - 역할별 맞춤 교육

3. **인식 제고 활동**
   - 캠페인, 이메일, 포스터 등

4. **정책/절차 배포**
   - 전사 공지 및 배포

#### Check (점검) - 5점
**주요 활동**:
1. **보안 모니터링** ★★★
   - 실시간 보안 이벤트 감시
   - 로그 수집 및 분석
   - 이상 행위 탐지

2. **내부 심사 (연 1회 이상)** ★★★
   - 독립적인 내부 심사원
   - 통제 항목 준수 여부 확인
   - 부적합 사항 식별

3. **경영진 검토**
   - 정기적 보고
   - 의사결정

4. **측정 및 평가**
   - KPI 측정
   - 목표 달성도 평가

#### Act (개선) - 5점
**주요 활동**:
1. **시정조치 (Corrective Action)** ★★★
   - 부적합 사항 원인 분석
   - 재발 방지 대책 수립
   - 시정조치 이행 및 확인

2. **예방조치 (Preventive Action)**
   - 잠재적 문제 식별
   - 사전 예방 대책

3. **지속적 개선**
   - PDCA 사이클 반복
   - 보안 수준 향상

4. **정책/절차 업데이트**
   - 변경 사항 반영
   - 최신화 유지

---

**채점 기준**:
- PDCA 4단계 명칭 정확히 기재 (각 1점, 총 4점)
- 각 단계별 주요 활동 3가지 이상 기술 (각 3점, 총 12점)
- 중요 활동 강조 (위험평가, 내부심사, 시정조치) (4점)

**핵심 요약**:
```
Plan (계획):   위험평가 ★★★, 정책 수립, 보안대책 선정
Do (실행):     보안대책 구현, 교육 실시
Check (점검):  모니터링, 내부심사 (연 1회) ★★★, 측정
Act (개선):    시정조치 ★★★, 지속적 개선
```

**암기 팁**:
- Plan: "위험평가가 핵심"
- Check: "내부심사 연 1회 이상" (빈출)

### 문제 4. ISO 27001 vs 27002 차이점 (12점) ★★

**문제**:
ISO/IEC 27001과 ISO/IEC 27002의 차이점을 비교하여 설명하시오. (12점)

**✅ 모범 답안**:

#### ISO/IEC 27001 - 6점

**성격**:
- 정보보호 관리체계(ISMS) 요구사항
- "무엇을 해야 하는가" (What)

**특징**:
1. **인증 대상** ★★★
   - 조직이 인증을 받을 수 있음
   - 제3자 인증 기관의 심사

2. **필수 요구사항**
   - 조직이 반드시 준수해야 할 사항
   - 의무적 (Mandatory)

3. **관리체계 프레임워크**
   - PDCA 사이클 기반
   - 정책, 조직, 절차 등 관리 체계

4. **유효기간**
   - 3년 (사후심사 연 1회)

**구성**:
```
10개 조항 + 부속서 A (93개 통제 항목)
```

#### ISO/IEC 27002 - 6점

**성격**:
- 정보보호 통제 구현 지침
- "어떻게 구현하는가" (How)

**특징**:
1. **참고 자료** ★★
   - 인증 대상이 아님
   - 가이드라인 성격

2. **권고사항**
   - 조직이 참고하여 적용
   - 선택적 (Optional)

3. **통제 구현 가이드**
   - 구체적인 구현 방법 제시
   - 모범 사례 제공

4. **ISO 27001의 부속 표준**
   - 27001의 부속서 A 통제 항목에 대한 상세 설명

**구성**:
```
4개 영역, 14개 통제 범주, 114개 통제 항목 (2022 개정판)

4개 영역:
1. 조직적 통제 (Organizational Controls)
2. 인적 통제 (People Controls)
3. 물리적 통제 (Physical Controls)
4. 기술적 통제 (Technological Controls)
```

#### 비교 요약표

| 구분 | ISO 27001 | ISO 27002 |
|-----|-----------|-----------|
| 성격 | 요구사항 (Requirements) | 구현 가이드 (Guidelines) |
| 목적 | What (무엇을) | How (어떻게) |
| 인증 | 인증 가능 ★★★ | 인증 불가 |
| 준수 | 필수 (Mandatory) | 권고 (Recommended) |
| 내용 | 관리체계 프레임워크 | 통제 구현 방법 |
| 통제 항목 | 93개 (부속서 A) | 114개 (상세 설명) |

---

**채점 기준**:
- ISO 27001 주요 특징 3가지 이상 (4점)
- ISO 27002 주요 특징 3가지 이상 (4점)
- 두 표준의 차이점 명확히 비교 (4점)

**핵심 요약**:
```
ISO 27001:
- 인증 대상 ★★★
- What (무엇을)
- 필수 요구사항
- 유효기간 3년

ISO 27002:
- 참고 자료
- How (어떻게)
- 권고사항
- 114개 통제 항목 상세 설명
```

### 문제 5. ISO 27001 인증 절차 (15점) ★★

**문제**:
ISO/IEC 27001 인증을 취득하기 위한 주요 절차를 순서대로 설명하시오. (15점)

**✅ 모범 답안**:

#### 1단계: 인증 신청 및 준비 - 3점
- 인증 기관 선정
- 인증 범위 결정
- 신청서 제출
- 인증 심사 일정 협의

#### 2단계: 1단계 심사 (Stage 1 Audit) - 3점
**목적**: 문서 심사 및 현장 심사 준비

**주요 활동**:
- 정보보호 정책, 절차 문서 검토
- 인증 범위 및 경계 확인
- 위험평가 방법론 검토
- 2단계 심사 준비 상태 평가
- 중대한 부적합 사항 확인 (있으면 2단계 진행 불가)

**결과**:
- 1단계 심사 보고서 발행
- 개선 권고사항 제시

#### 3단계: 2단계 심사 (Stage 2 Audit) - 4점
**목적**: 현장 실사를 통한 통제 구현 확인

**주요 활동**:
- 현장 방문 심사 ★★★
- 직원 인터뷰
- 시스템 및 통제 확인
- 증적(Evidence) 확인
- 부적합 사항 식별 및 지적
  - 중대한 부적합 (Major Nonconformity): 즉시 시정 필요
  - 경미한 부적합 (Minor Nonconformity): 일정 기간 내 시정

**심사 영역**:
- ISO 27001 요구사항 준수 여부
- 부속서 A 93개 통제 항목 적용 여부
- PDCA 사이클 운영 현황

#### 4단계: 시정조치 - 2점
- 부적합 사항에 대한 원인 분석
- 시정조치 계획 수립 및 이행
- 증적 제출
- 심사원 확인 및 승인

- 3년 후 갱신 심사 (Recertification)

### 문제 6. NIST CSF 5대 핵심 기능 (15점) ★★★

**문제**:
미국 NIST Cybersecurity Framework의 5대 핵심 기능(Core Functions)을 설명하시오. (15점)

**✅ 모범 답안**:

#### 1. Identify (식별) - 3점
**목적**: 조직의 사이버보안 리스크 이해

**주요 활동**:
- **자산 관리 (Asset Management)**
  - 하드웨어, 소프트웨어, 데이터, 인력 식별
  - 자산 목록 작성 및 관리

- **비즈니스 환경 이해**
  - 조직의 미션, 목표, 우선순위 파악
  - 공급망 이해

- **거버넌스**
  - 정책, 절차, 규정 수립
  - 역할 및 책임 정의

- **위험평가 (Risk Assessment)** ★★★
  - 자산, 위협, 취약점 식별
  - 리스크 평가 및 우선순위 결정

- **리스크 관리 전략**
  - 수용, 완화, 전가, 회피

#### 2. Protect (보호) - 3점
**목적**: 중요 서비스 제공을 보장하기 위한 보호 조치

**주요 활동**:
- **접근통제 (Access Control)** ★★★
  - 사용자 인증 및 인가
  - 최소 권한 원칙
  - 물리적 접근통제

- **인식 및 교육 (Awareness and Training)**
  - 보안 인식 교육
  - 역할별 보안 교육

- **데이터 보안 (Data Security)**
  - 암호화, 백업
  - 데이터 무결성 보호

- **보호 프로세스**
  - 보안 정책 및 절차 구현

- **보호 기술**
  - 방화벽, IDS/IPS, 백신

#### 3. Detect (탐지) - 3점
**목적**: 사이버보안 이벤트 발생을 적시에 탐지

**주요 활동**:
- **이상 및 이벤트 (Anomalies and Events)** ★★★
  - 비정상 활동 탐지
  - 보안 이벤트 분석

- **보안 지속 모니터링 (Continuous Monitoring)**
  - 네트워크 트래픽 모니터링
  - 로그 수집 및 분석
  - 실시간 감시

- **탐지 프로세스**
  - IDS/IPS, SIEM 운영
  - 이상 징후 탐지

**탐지 기술**:
```
- SIEM (Security Information and Event Management)
- IDS/IPS
- 로그 분석
- 행위 분석 (Behavior Analysis)
```

#### 4. Respond (대응) - 3점
**목적**: 탐지된 사이버보안 이벤트에 대한 적절한 조치

**주요 활동**:
- **대응 계획 (Response Planning)** ★★★
  - 사고 대응 계획 수립
  - 대응 절차 및 역할 정의

- **커뮤니케이션 (Communications)**
  - 내부/외부 이해관계자 통보
  - 법적 보고 의무 이행

- **분석 (Analysis)**
  - 사고 영향 범위 분석
  - 원인 분석

- **완화 (Mitigation)**
  - 사고 확산 차단
  - 피해 최소화

- **개선 (Improvements)**
  - 대응 프로세스 개선

#### 5. Recover (복구) - 3점
**목적**: 사이버보안 사고 후 정상 운영 복구

**주요 활동**:
- **복구 계획 (Recovery Planning)** ★★★
  - 복구 전략 수립
  - BCP/DRP (비즈니스 연속성 계획/재해 복구 계획)
  - RPO/RTO 정의

- **개선 (Improvements)**
  - 사고 대응 교훈 도출
  - 프로세스 개선

- **커뮤니케이션**
  - 복구 진행 상황 공유
  - 이해관계자 통보

**복구 활동**:
```
- 시스템 복원
- 데이터 복구
- 서비스 재개
- 사후 검토 (Post-Incident Review)
```

---

**채점 기준**:
- 5대 기능 명칭 정확히 기재 (각 1점, 총 5점)
- 각 기능별 주요 활동 설명 (각 2점, 총 10점)

**핵심 요약**:
```
1. Identify (식별):  자산 관리, 위험평가 ★★★
2. Protect (보호):   접근통제, 암호화, 교육 ★★★
3. Detect (탐지):    모니터링, SIEM, IDS/IPS ★★★
4. Respond (대응):   사고 대응, 분석, 완화 ★★★
5. Recover (복구):   BCP/DRP, 복원, 사후 검토 ★★★

## 4. CC 인증

### 문제 8. CC 인증 EAL 등급 (15점) ★★★

**문제**:
CC(Common Criteria) 인증의 EAL(Evaluation Assurance Level) 등급 체계를 설명하시오. (15점)

**✅ 모범 답안**:

#### CC 인증 개요 - 3점
**정의**:
- Common Criteria (공통평가기준)
- ISO/IEC 15408 국제 표준
- IT 제품의 보안 기능 평가 인증

**목적**:
- IT 제품 보안성 객관적 평가
- 국제적으로 상호 인정
- 구매자의 신뢰성 있는 선택 지원

#### EAL 등급 체계 (1~7) - 10점

**EAL1 (Functionally Tested) - 기능 테스트** - 1점
- 가장 낮은 등급
- 기본적인 기능 테스트만 수행
- 제품이 문서대로 동작하는지 확인
- 주로 상용 제품에 적용

**EAL2 (Structurally Tested) - 구조 테스트** - 1점
- 구조적 테스트 수행
- 개발 문서 검토
- 설계 문서 제공 필요

**EAL3 (Methodically Tested and Checked) - 체계적 테스트 및 검토** - 1점
- 체계적인 테스트 및 검토
- 개발 환경 통제 확인
- 중간 수준의 보증

**EAL4 (Methodically Designed, Tested and Reviewed) - 체계적 설계/테스트/검토** - 3점
- **상용 제품의 일반적 등급** ★★★
- 체계적 설계, 테스트, 검토
- 독립적 취약점 분석
- 개발 프로세스 문서화
- 비용 대비 효과적
- 대부분의 상용 보안 제품 목표 등급

**예시**:
```
- 방화벽
- VPN
- IPS
- 스마트카드
- 운영체제
```

**EAL5 (Semiformally Designed and Tested) - 준형식적 설계 및 테스트** - 1점
- 준형식적 설계 및 테스트
- 모듈화 설계 요구
- 높은 수준의 보증
- 전문 보안 제품

**EAL6 (Semiformally Verified Design and Tested) - 준형식적 검증 설계 및 테스트** - 1점
- 준형식적 검증
- 설계의 정확성 검증
- 매우 높은 보증 수준

**EAL7 (Formally Verified Design and Tested) - 형식적 검증 설계 및 테스트** - 2점
- 가장 높은 등급 ★★★
- 형식적 검증 기법 사용
- 수학적 증명
- 군사용, 국가 기밀 시스템
- 매우 높은 비용

**예시**:
```
- 군사 통신 시스템
- 국가 기밀 정보 시스템
- 핵심 기반시설 통제 시스템
```

#### 등급 선택 기준 - 2점
**고려사항**:
- 제품의 중요도
- 보안 요구사항
- 비용 (등급 상승 시 비용 기하급수적 증가)
- 개발 기간

**일반적 선택**:
```
상용 제품: EAL4 ★★★
전문 보안 제품: EAL5-6
군사/국가 기밀: EAL7
```

---

**채점 기준**:
- CC 인증 개요 및 ISO 표준 번호 (3점)
- EAL 등급 범위 (1~7) 명시 (2점)
- 각 등급 설명 (각 1점, EAL4와 EAL7은 2-3점)
- 일반적 등급 (EAL4) 강조 (3점)

**핵심 요약**:
```
CC 인증 (ISO/IEC 15408):
- EAL1 ~ EAL7 (7단계) ★★★
- EAL1: 기능 테스트 (가장 낮음)
- EAL4: 상용 제품 일반적 등급 ★★★
- EAL7: 형식적 검증 (군사용, 가장 높음) ★★★
```

**암기 팁**:
```
"1-4-7 만 기억!"
- EAL1: 기능 (낮음)
- EAL4: 상용 (일반)
- EAL7: 형식 (군사)
```

4. 보안 목적
5. 보안 기능 요구사항 (SFR)
6. 보안 보증 요구사항 (SAR)
```

**4. 평가 수행** - 1점

- 기능 시험
- 취약점 분석
- 문서 검토
- 소스코드 분석 (높은 EAL 등급)

**5. 인증서 발급** - 1점
- 평가 완료 후 인증기관이 인증서 발급
- IT보안인증사무국 (KECS) 발급
- 국제 상호인정 (CCRA - Common Criteria Recognition Arrangement)

- 인증 절차 4단계 이상 기술 (각 1-2점, 총 7점)

**핵심 요약**:

인증 절차:
1. 평가기관 선정

3. ST (보안목표명세서) 작성 ★★
4. 평가 수행
5. 인증서 발급

**문제**:
국가정보보안기본지침의 적용 대상과 주요 내용을 설명하시오. (18점)

**✅ 모범 답안**:

**3단계: 통보**

- 보호 의무 부여
